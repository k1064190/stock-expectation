Stage 25

A weekly scheduled job that scores gold entry timing and long-term macro bias into an ACCUMULATE / HOLD / PAUSE verdict.

Gold Weekly Trend

Why

Doctor Cho is dollar-cost-averaging into KRX 금현물 (physical gold, holds 2g) and wanted a recurring weekly checkpoint — like the existing stock crontab jobs — answering two questions: is now a reasonable spot to add this week's tranche, and is gold structurally biased to rise long-term. A backing deep-research pass (WGC / IMF / Fed / J.P. Morgan, 2026-07-03) established the macro facts that seed the scorecard: central-bank buying is structurally elevated (~1,000t/yr since 2022 vs ~500t/yr the prior decade), the worst historical gold bears required Volcker-style punitive real rates (~5–8%, currently absent), and the "dollar collapse" narrative is overstated (USD reserve share ~58%, flat since 2022).

What

  • deterministic technical score (weekly-entry timing): trend vs MA50/MA200, drawdown-from-52w-high, RSI band
  • deterministic macro scorecard (long-term bias): central-bank buying + real-rate regime + dollar structural drift + FX (KRW/USD), scored by Python rules from live data plus a quarterly-refreshed config file
  • one optional claude -p Korean summary paragraph (fail-open)
  • optional approximate personal 2g position P&L line (spot USD/oz × KRW/USD ÷ 31.1035, labelled approximate)
  • 12-week rolling state (state/gold_trend.json) for week-over-week deltas — never predictions.db
  • verdict: hard PAUSE flags (RSI > 75, real-rate punitive, or manual risk_off kill-switch) override; else ACCUMULATE when macro ≥ 55 and technical ≥ 50; else HOLD

How

Built over 8 TDD tasks (config → technical → macro → verdict → rendering → state → fail-open fetchers → orchestration) via subagent-driven development: a fresh implementer per task, a spec-and-quality review per task, then a whole-branch review. Fetchers are fail-open (any failure returns a sentinel; build_context converts each into a labelled degraded line; the report is written to disk before the best-effort Telegram send). Runs Sunday 21:00 KST. A calibration decision surfaced from the first live dry-run: real-rate restrictive_above_pct (2.0) originally did double duty as both the sub-score floor and the hard-PAUSE veto, so a live DFII10 ≈ 2.2% force-PAUSEd accumulation — contradicting the research. The two were decoupled: restrictive_above_pct (2.0) now only floors the sub-score, and a new punitive_above_pct (3.5) drives the hard PAUSE veto. After the change the dry-run returns ACCUMULATE at 2.2%.

Code locations

  • scheduler/gold_trend.py — the whole job (scoring functions, fail-open fetchers, build_context, main)
  • data/gold_macro_factors.yaml — slow structural inputs + weights/thresholds (punitive_above_pct: 3.5)
  • tests/test_gold_trend.py — 44 unit tests (2 network-marked)
  • scheduler/crontab.example — Sunday 21:00 KST line
  • CLAUDE.md — new "Weekly gold trend" scheduler subsection
  • .gitignore — reports/gold-trend-*.md
  • docs/superpowers/specs/2026-07-04-gold-weekly-trend-design.md
  • docs/superpowers/plans/2026-07-05-gold-weekly-trend.md

Retrospective

TDD plus per-task review caught tautological and boundary test gaps early; the most valuable catch was the whole-branch review flagging that the report wasn't gitignored (a personal-data leak risk) and that the day-one output was a PAUSE contradicting the tool's own thesis — surfaced only by running the live dry-run before declaring done. Open follow-ups: punitive_above_pct 3.5 is a seeded guess; the per-gram position figure is an approximation.

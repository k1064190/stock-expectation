11단계

예측 정확도 개선 이니셔티브: 백필 A/B 평가 게이트, 결정론적 재보정 및 사망 신호 제거, 강성 시장 레짐 게이트, 종목별 과확장 게이트, 구조화된 뉴스 특성, 필라별 컴포넌트 영속성, LLM_CONTEXT 엄격성 게이트, 그리고 LIVE 대 INTERACTIVE 누출 감사.

백필 하네스 (Backfill Harness)

왜

예측 승률이 73% (2026-05-11)에서 24% (2026-06-14)로 붕괴했습니다. 승인된 계획은 6가지 정확도 개선 사항(A–F)을 제시합니다. 모든 변경 사항은 라이브 /expect 흐름에 반영되기 전에 과거 데이터로 검증되어야 합니다. 그렇지 않으면 LIVE–INTERACTIVE 낙관 편향(F4)을 반복할 위험이 있습니다. 이 하네스가 바로 그 게이트입니다.

무엇을

scheduler/backfill_eval.py — 종료된(HIT/MISS) 예측에 대한 읽기 전용 A/B 도구이며, tests/test_backfill_eval.py(9개 테스트, 모두 통과)가 함께 제공됩니다. 보고 섹션:

  • [A] 등온 재보정 — 누출 방지: 이전 훈련 슬라이스에 재보정 맵을 피팅하고, 보류된 최근 테스트 슬라이스에서 원시 대 재보정 Brier를 채점합니다.
  • [B] 사망 신호 기여도 — 사망 신호 (valuation / cycle / mean_reversion)를 사용한 종료 행과 그렇지 않은 행을 구분합니다.
  • [D] 레짐 윈도우 억제 — 리스크-오프 윈도우 내에서 생성된 BULL 예측의 결과.

첫 실행 결과 (실제 DB, n=420 종료)

변경 지표 이전 이후
A (재보정, OOS) ALL Brier 0.340 0.204
A (재보정, OOS) LIVE Brier 0.331 0.160
B 사망신호 포함 승률 — 0.0% (n=15, Brier 0.424)
D BULL 6/1–6/7 승률 — 4.3% (n=140)

A와 D를 강하게 검증하며, B는 표본 수 부족으로 노이즈로 확인됩니다.

어떻게

별도 구현 없이 프로덕션 보정 수학(build_recalibration_map, apply_recalibration, get_calibration_report, mcp-prediction-store/metrics.py)을 재사용합니다. 훈련 슬라이스는 인메모리 DB에 로드되어 버킷팅이 라이브와 동일합니다. 시간 순서 분할은 get_signal_decay(outcome_date, created_at, id)를 따릅니다.

리뷰 루프
  • 수정 — DB가 읽기 전용이 아님 (codex, 높음): 하네스가 models.get_connection을 사용했는데, 이는 마이그레이션/인덱스/WAL/ 중복 자동수정 등 쓰기 작업을 수행합니다. _connect_readonly(file:...?mode=ro URI)로 교체했습니다.
  • 수정 — avg-return 100배 부풀림 (codex, 낮음): outcome_return은 백분율 포인트로 저장되는데, :+.2% 형식 지정자가 100을 곱했습니다. :+.2f%로 변경. "손상된 데이터"라는 이전 메모는 잘못된 것이었습니다.
  • 수정 — 잘못된 oos_fraction / 소규모-n (codex + gemini): 0 < oos_fraction < 1 유효성 검사 및 "데이터 부족" 가드를 추가했습니다.
  • 수정 — 지평선별 재보정 (gemini + code-reviewer): eval_recalibration/build_report에 선택적 timeframe 및 --timeframe CLI 플래그를 노출했습니다.
  • 수정 — 테스트 격차: 잘못된 분수, 빈 신호 목록, 커스텀 사망 세트, build_report 스모크 테스트 추가 (9개 → 15개).
  • 기각 — 인메모리 스키마 "Critical" (code-reviewer): 세 검토자 모두 get_calibration_report가 confidence/status/source/timeframe만 읽는다는 것을 확인했습니다.
  • 기각 — 엄격한 시점 분할 (gemini/codex): 분할이 outcome_date 기준이므로 테스트 결과가 피팅된 맵에 포함되지 않습니다. eval_recalibration에 문서화했습니다.
기존에 알려진 문제

scheduler/weekly_calibration.py:208,236이 avg_return에 :+.2%를 사용하여 동일한 100배 부풀림 버그가 있습니다. 별도 범위 한정 수정에 맡겼습니다.

코드 위치

  • tests/test_backfill_eval.py — 유닛 테스트 15개.
회고

인메모리 DB를 통해 프로덕션 재보정 빌더를 재사용한 것이 하네스의 정직성을 유지했습니다 (라이브에서 이탈할 수 있는 중복 보정 로직 없음). 세 검토자 루프의 효용이 증명됐습니다: codex가 읽기 전용 계약 위반과 데이터를 잘못 비난하게 만들었던 형식 버그를 잡아냈습니다. 앞으로의 교훈: 데이터를 탓하기 전에 표시 경로를 먼저 검증하세요.

재보정 및 사망 신호 (Recalibration And Dead Signals)

왜
  • F1/F7 (과신 + 미사용 재보정 맵): 0.60–0.70 신뢰도 구간이 실제보다 +0.28 높았으며, /expect가 운영자에게 수동으로 재보정 맵을 적용하도록 지시했음에도 백필 결과 기록된 신뢰도는 여전히 ~0.6에 가까운 상수였습니다. 수동 LLM 단계는 신뢰할 수 없으므로 재보정은 결정론적이어야 합니다.
  • F2/F5 (사망 신호): valuation, cycle, mean_reversion이 0%를 기록하며 신호별 보정만 오염시키고 있습니다.
무엇을
  • A — predict create의 --recalibrate 플래그 (stock_cli.py). 저장 전 원시 --confidence를 소스 범위 등온 곡선에 매핑합니다. JSON에 raw_confidence / recalibration_applied를 출력합니다. 해당 소스의 종료된 예측이 MIN_CLOSED_FOR_RECAL = 30 미만이면 안전하게 비활성화됩니다.
  • B — 사망 신호 제거: /expect 및 daily-briefing 스킬의 허용 --signals 목록에서 제거했습니다. 해당 읽기는 LLM_CONTEXT_SCORE를 통해 처리하도록 안내합니다.
  • 기존 버그 수정 (승인됨): weekly_calibration.py:208,236의 avg_return :+.2% 100배 부풀림. :+.2f%로 수정.
  • 테스트: tests/test_recalibration_cli.py (3개) — 최소 표본 게이트, 과신 하향 조정, 소스 범위 지정.
어떻게

재보정은 build_recalibration_map / apply_recalibration(mcp-prediction-store/metrics.py)을 재사용합니다. 백필 결과 지평선별 맵과 동등한 정확도(Brier 0.160 vs 0.169)를 보이고 현재 표본 크기에서 더 강건하여 글로벌(전체 지평선) 맵을 사용합니다. 소스 범위: LIVE 예측은 LIVE 이력에 대해서만 보정하며, 과피팅된 INTERACTIVE 행은 사용하지 않습니다(F4 격차). 로깅 임계값은 여전히 원시 신뢰도로 게이팅하며, 저장되는 값만 재보정되므로 "지평선별 ≥ 0.60 저장" 의미는 변경되지 않습니다.

검증

백필 OOS Brier: LIVE 0.331 → 0.160, ALL 0.340 → 0.204 (누출 방지 훈련/테스트 분할).

라이브 맵 검사에서 발견된 주의 사항: 프로덕션 LIVE 곡선은 원시 신뢰도가 거의 상수이므로 단일 앵커(0.612 → 0.248)를 가집니다. 재보정이 모든 신뢰도를 ~0.25 기저율로 붕괴시킵니다. 이것이 Brier 개선의 원천(기저율이 비정보적 0.6을 이기는) 이지만, 모델이 정보적 신뢰도 분포를 생성하기 전까지 기록된 신뢰도가 종목을 순위 매기기를 멈춘다는 의미입니다. 차별성 복원은 다운스트림 작업(변경 E / 메타-라벨링)입니다.

리뷰 루프
  • 치명적 (3개 모두, 수정) — 재보정이 자체 훈련 데이터를 오염시켰습니다. 재보정된 값을 confidence에 다시 저장하면 향후 맵이 오염됩니다: build_recalibration_map/get_calibration_report가 confidence를 원시 예측 변수로 읽기 때문입니다. 수정: nullable raw_confidence 열 추가(models.py 스키마 + _ensure_raw_confidence_column 마이그레이션). 보정은 COALESCE(raw_confidence, confidence)로 훈련합니다. 프로덕션 복사본에서 마이그레이션 검증(1169행 보존).
  • 수정 — 테스트 격차 (codex/code-reviewer): 게이트 이후 빈 맵 비활성화, 비오염 테스트, 종단간 cmd_predict_create --recalibrate 테스트 추가.
  • 인지됨 — 재생 이중 적용: 호출자가 저장된(이미 재보정된) 신뢰도를 --recalibrate와 함께 수동으로 재제출하면 다시 매핑됩니다. 일반 /expect 경로 외부이므로 문서화만 하고 게이팅하지 않습니다.
코드 위치
  • stock_cli.py — _recalibrated_confidence, MIN_CLOSED_FOR_RECAL, cmd_predict_create, --recalibrate 인수, raw_confidence 영속성.
  • mcp-prediction-store/models.py — raw_confidence 열, 스키마, _ensure_raw_confidence_column, 데이터클래스 필드, 삽입, _row_to_prediction.
  • mcp-prediction-store/metrics.py — COALESCE(raw_confidence, confidence)로 훈련.
  • scheduler/weekly_calibration.py:208,236 — avg_return 형식 수정.
  • .claude/skills/expect/SKILL.md — 재보정 단계 + 사망 신호 목록.
  • .claude/skills/daily-briefing/SKILL.md — 재보정 단계 + 사망 신호 규칙.
  • tests/test_recalibration_cli.py — 유닛 테스트 7개.
회고

재보정을 수동 LLM 지시에서 CLI 플래그로 이동한 것이 F7의 진정한 수정입니다 — 맵은 수주 전부터 존재했지만 신뢰성 있게 적용되지 않았습니다. 실제 라이브 맵 검사(백필 델타만이 아닌)를 통해 재보정이 현재 기저율로 퇴화하고 있음을 발견했습니다. 신뢰도가 차별성을 잃었다는 것을 나중에 발견하는 것보다 지금 솔직하게 기록하는 것이 낫습니다.

레짐 게이트 (Regime Gate)

왜

F3: 2026년 6월 하락장에서 /expect가 조정 내내 BULL을 계속 발행했습니다 (6/1–6/7 종료된 BULL 140개, 승률 4.3%). 결정론적 리스크-오프 게이트가 없었습니다 — 매크로 스킬은 LLM이 무시할 수 있는 자문 성격의 안내문이었습니다.

무엇을
  • stock-cli regime --market US|KR — 인덱스 프록시 가격 구조 (MA50/MA200 대비 추세, 52주 최고점 대비 낙폭, 1개월 수익률, 연율화 20일 실현 변동성)에서 결정론적 RISK_ON / NEUTRAL / RISK_OFF 판정. US는 SPY + QQQ 중 나쁜 쪽을 집계하며, KR은 KODEX 200 (069500)을 사용합니다.
  • 강성 게이트가 /expect(RULE R1) 및 daily-briefing (RULE R1)에 연결됨: RISK_OFF는 새 BULL을 억제(WATCH로 제한, 지평선을 NEUTRAL로); NEUTRAL은 BUY 바를 8.0에서 9.0으로 높이고 신뢰도를 제한 (cap 0.60); RISK_ON은 변경 없음.
  • tests/test_regime.py (16개 테스트).
어떻게

mcp-market-data/regime.py(compute_realized_vol, compute_regime, aggregate_regime)의 순수, 네트워크 무관 로직. CLI는 기존 프로바이더 + compute_horizon_metrics를 통해 인덱스 봉을 공급합니다. aggregate_regime은 dataclasses.replace로 입력 변경 없이 복사본을 반환하며, 모든 프록시의 점수를 proxy_scores에 기록합니다.

검증

각 예측의 발행 날짜 기준으로 레짐을 재구성하여 종료된 BULL 140개를 분류했습니다:

  • 발행 시 NEUTRAL: n=65, 승률 3.1% — 게이트가 이를 억제/강화합니다.
  • 발행 시 RISK_ON: n=75, 승률 5.3% — 발행 시 인덱스가 안정적으로 보였으므로 게이트가 잡을 수 없습니다.
  • 6/2 클러스터(72건)는 인덱스만으로는 게이팅 불가 — QQQ도 RISK_ON 상태였으며 낙폭은 이후에 발생했습니다. SPY는 전체 기간 동안 RISK_ON을 유지했습니다. QQQ는 6/7에 NEUTRAL로, KR은 포물선 변동성(1개월 +40%, 변동성 56%)으로 일찍 NEUTRAL을 신호했습니다.

결론 (과장 없음): 레짐 게이트는 부분적 완화책입니다 — 윈도우 패자의 ~46%(NEUTRAL 예측)를 제거하고 진행 중/포물선형 조정에서의 매수를 중단시키지만, 6/2 고점에서 광범위 인덱스는 안정적이었습니다. 보완적 레버(종목별 과확장)는 계획된 후속 단계이며, 재보정(A)은 이미 6/2 클러스터를 피해를 입혔던 과신을 붕괴시켰습니다.

리뷰 루프
  • 수정 (3개 모두) — aggregate_regime이 입력 판정을 변경했습니다. 이제 dataclasses.replace가 복사본을 반환하며, 테스트가 입력이 변경되지 않음을 확인합니다.
  • 수정 (codex 높음) — cmd_regime이 실패한 프록시를 조용히 삭제했습니다 (QQQ 누락 시 성장 주도 하락에 대한 US 게이트가 맹목적이 됨). 누락된 프록시가 이제 판정 메모에 표시됩니다.
  • 수정 (codex+gemini) — 불충분한 이력이 RISK_ON으로 기본 설정됐습니다. MA200이 없으면 추세를 알 수 없으므로 강성 게이트가 RISK_ON을 인증해서는 안 됩니다. 이제 메모와 함께 NEUTRAL로 하한을 설정합니다.
  • 수정 — 인수 파서 도움말이 US 기본값을 SPY로 표시했습니다. 이제 "worst-of SPY+QQQ"로 변경됐습니다.
  • 수정 — 테스트 격차: 정확한 실현 변동성 값, MA 우선순위, 불충분한 이력, 비변경, 동점→첫 번째, 단일 프록시.
  • 기각 — 임계값 진동/이력현상 (gemini): 임계값 근처의 일별 진동에는 영속적 상태가 필요합니다. 게이트는 브리핑당 한 번만 호출되므로 알려진 한계로 문서화했습니다.
코드 위치
  • mcp-market-data/regime.py — 판정 + 채점 + 집계.
  • stock_cli.py — cmd_regime, _regime_for_proxy, REGIME_INDEX, regime 파서.
  • .claude/skills/expect/SKILL.md (RULE R1, 1단계 가져오기), .claude/skills/daily-briefing/SKILL.md (RULE R1, 섹션 1 가져오기).
  • tests/test_regime.py.
회고

검증 결과 첫 번째 직관("레짐 게이트가 손실을 방지했을 것이다")을 반박했습니다. 데이터가 솔직하고 좁은 주장을 강제하고 실제 다음 레버(종목별 과확장)를 표면화했습니다. 연결 전 백필 작업이 효과를 발휘했습니다.

과확장 게이트 (Overextension Gate)

왜

D단계 검증에서 광범위 인덱스 레짐 게이트가 6/2 클러스터를 잡을 수 없음이 증명됐습니다: 해당 패자들(ORCL, NET, SMCI, DDOG, KR 반도체)은 인덱스가 안정적인 상태에서 반전한 포물선형 개별 종목이었습니다. 종목별 과확장 게이트가 누락된 레버입니다.

무엇을
  • HorizonMetrics에 새로운 overextension_level (NONE / ELEVATED / EXTREME)을 추가했습니다. RSI14 및 MA20 대비 가격 거리로 classify_overextension(rsi14, price, ma20)가 계산하며, horizon-metrics[-batch]에서 자동으로 노출됩니다.
  • /expect + daily-briefing의 RULE R2: EXTREME은 새 BULL을 억제(WATCH로 제한); ELEVATED는 BUY 바를 +1.0 높이고 신뢰도를 제한(cap 0.60).
  • R1+R2 스택 명시화: 어느 쪽에서든 WATCH 제한이 우선; BUY 바 상승은 가산적 (NEUTRAL 레짐 + ELEVATED 종목 → COMPOSITE ≥ 10.0).
  • mcp-market-data/tests/test_indicators.py에 테스트 추가; CLI 계약 테스트가 새 필드를 고정합니다.
어떻게

377개 종료된 BULL에 대해 각 예측의 진입 시점 지표를 재구성(각 티커 이력을 created_at으로 자름)하여 임계값을 보정했습니다: EXTREME = RSI14 > 75 또는 가격이 MA20 대비 > 15%; ELEVATED = RSI14 > 70 또는 > 8% 위. 순수, 네트워크 무관 분류기입니다.

검증
진입 시 overextension_level n 승률
NONE 99 53.5%
ELEVATED 79 41.8%
EXTREME 199 29.1%

EXTREME을 억제하면 유지된 BULL 승률이 48.3% (n=178) 대 전체 38.2% — +10pp로 단조 감소 기울기를 보입니다. RSI만 기준: RSI>75는 26.4% (n=125) 대 RSI<60의 47.5%. MA20 거리 기준: >15%는 29.6% (n=196) 대 3–8% 구간의 66%.

리뷰 루프
  • 세 검토자 모두 코드가 올바름을 확인했습니다 (중증도 순서, ma20≤0/None 가드, RSI-None 기본값, 점수 테이블과의 이중 계산 없음, 기본 데이터클래스 필드가 하위 호환됨).
  • 수정 (codex 중간) — R1+R2 스택 모호성: 바 상승을 가산적으로, WATCH 제한을 "어느 쪽이든 우선"으로 문서화했습니다.
  • 수정 (둘 다 낮음) — 오래된 스키마 목록 / 고정되지 않은 필드: overextension_level을 /expect 필드 목록과 CLI 계약 테스트의 expected_fields에 추가했습니다.
  • 수정 — 경계 테스트: 엄격한 RSI 경계 및 MA20 구간 테스트 추가 (하나의 테스트가 실패한 후 부동소수점 취약한 정확한 백분율 경계를 피했습니다).
  • 언급됨 (둘 다) — ELEVATED는 의도적으로 온화합니다: RSI 70–75는 여전히 +0.5 모멘텀과 고점 근처 사이클 +1.0을 얻어 R2의 +1.0 바를 부분적으로 상쇄합니다. ELEVATED가 41.8%(손익분기점 근처)를 기록하므로 소프트 게이트가 적합합니다; EXTREME(29%)은 강성 억제를 받습니다.
코드 위치
  • mcp-market-data/indicators.py — classify_overextension, OVEREXT_* 상수, HorizonMetrics.overextension_level, compute_horizon_metrics에 연결.
  • .claude/skills/expect/SKILL.md (RULE R2 + 필드 목록), .claude/skills/daily-briefing/SKILL.md (RULE R2).
  • mcp-market-data/tests/test_indicators.py, tests/test_cli_integration.py.
회고

이것은 D 검증이 예측한 보완책입니다: R1(시장) + R2(종목)이 함께 레짐-맹목 클러스터와 포물선형 개별 종목 모두를 해결합니다. 저장된 created_at에서 진입 시점 지표를 재구성하여 "패자들이 과확장됐다"는 직감을 보정된 단조 임계값으로 바꿨습니다.

뉴스 특성 (News Features)

왜

news 신호가 "사망"(~33% 승률)으로 평가됐습니다. 근본 원인: 채점이 원시 헤드라인 수와 평균 감성을 계산했는데, 리포스트가 수량을 부풀리고 오래된 미약한 신호가 강성 촉매와 동일한 가중치를 받았습니다. 최신 뉴스 필라에는 정보가 필요했지, 수량이 아니었습니다.

무엇을
  • mcp-market-data/news_features.py: NewsSignal을 생성하는 순수 특성 추출기 — 중복 제거된 unique_count, 최신성 가중 감성(3일 반감기 지수 감쇄), 촉매 event_tags (earnings/guidance/ma/analyst/regulatory_legal/product/leadership/capital), has_positive_catalyst / has_negative_catalyst 플래그.
  • news CLI 명령이 이제 items와 함께 signal 블록을 출력합니다.
  • 두 스킬 모두 signal에서 NEWS_SCORE를 채점하고 (최신성 가중 감성, 중복 제거 수량, 부정적 촉매 상한) event_tags를 LLM_CONTEXT 토론에 공급합니다.
  • tests/test_news_features.py에 16개 테스트.
어떻게
  • 최신성 가중치: w = 0.5 ** (age_days / 3) — 1주일 된 항목은 최신 항목의 ~20%로 계산됩니다. 미래 날짜는 age 0으로 제한; 파싱 불가능한 날짜는 단위 가중치로 폴백.
  • 중복 제거: 5단어 최소값이 있는 단어 접두사 포함으로, 통신사 리포스트는 축소되지만 짧은 일반 스텁이 별개 기사를 삼키지 않습니다.
  • 매칭: ASCII 키워드는 단어 경계(\bmiss\b — "mission"/"twins"/"heartbeat" 제외)로 매칭됩니다. 한국어 키워드는 서브스트링으로 매칭하므로 Alpha Vantage 감성 없는 KR Naver 헤드라인도 이벤트 태그와 촉매 플래그를 생성합니다.
검증

구조적/품질 개선 — 예측별 과거 헤드라인이 저장되지 않으므로 이것은 백필 승률 검증이 아닙니다(명확히 명시). 정당성은 정보 품질입니다: 중복 제거는 이중 계산을 제거하고, 최신성 가중치는 오래된 뉴스를 약화시키며, 촉매 태깅은 중요 이벤트를 노이즈에서 분리합니다. 뉴스 신호 승률이 개선되는지는 주간 보정을 통해 전방으로 측정됩니다. 라이브 확인: US AAPL이 채워진 감성 신호를 반환했습니다; KR 005930이 헤드라인 8개에서 7개로 중복 제거됐습니다.

리뷰 루프
  • 수정 (둘 다, 높음) — 서브스트링 촉매 오탐: "miss"/"halt"/"wins"/"beat"가 "mission"/"health"/"twins"/"heartbeat"에서 -2 상한을 발동할 수 있었습니다. 이제 ASCII 키워드가 단어 경계 정규식을 사용하며 명확한 구문 ("earnings miss", "trading halt")을 선호합니다. 테스트가 오탐 없음을 확인합니다.
  • 수정 (codex, 높음) — 스킬 드리프트: /expect에만 존재하던 미검증 "+1.0 hard catalyst" 행을 제거했습니다. NEWS_SCORE가 이제 두 스킬 전반에서 동일합니다.
  • 수정 (둘 다, 중간) — 중복 제거 과병합: 5단어 최소 접두사 가드를 추가했습니다. 테스트가 "Nvidia shares rise"가 더 긴 별개 헤드라인을 더 이상 삼키지 않음을 증명합니다.
  • 수정 (둘 다, 중간) — 한국어 맹점: 모든 이벤트 카테고리와 촉매 목록에 한국어 키워드를 추가했으며, 한글에는 서브스트링 매칭을 적용했습니다.
  • 수정 — 테스트 격차: 단어 경계, 한국어, 짧은 접두사, 미래 날짜 제한, 두 항목 잘못된 날짜, 오래된 헤드라인 감쇄.
  • 언급됨 — 최신성 반감기가 하드코딩됨 (3d): 향후 튜닝을 위해 모듈 상수로 노출됐습니다.
코드 위치
  • mcp-market-data/news_features.py — NewsSignal, classify_event, dedup_headlines, _contains, summarize_news, RECENCY_HALF_LIFE_DAYS, DEDUP_MIN_PREFIX_WORDS.
  • stock_cli.py — cmd_news signal 블록.
  • .claude/skills/expect/SKILL.md (6단계), .claude/skills/daily-briefing/SKILL.md (NEWS_SCORE).
  • tests/test_news_features.py.
회고

사망 뉴스 신호는 채점 문제만큼이나 데이터 문제였습니다: 중복 제거 + 최신성 + 촉매 구조는 이전 수량/평균 채점이 버렸던 정보입니다. 검증에 대해 솔직합니다: 이것은 백필할 수 없으므로 측정된 승리로 포장하지 않고 전방 확인을 위한 품질 개선으로 출시합니다.

컴포넌트 영속성 (Component Persistence)

왜

재보정(A)에서 기록된 신뢰도가 차별성이 없음을 드러냈습니다 — 시스템이 종목 점수를 왜 매겼는지 기록하지 않으므로 기저율로 붕괴됩니다. 세 가지 역량(알고리즘 / 뉴스 / LLM)을 조화시키고 언젠가 정보적 블렌딩 신뢰도를 출력하려면, 각 필라의 기여도를 예측별로 캡처해야 합니다. 기록하지 않은 데이터에서는 블렌드를 학습할 수 없습니다.

무엇을
  • predictions의 nullable components JSON 열 (가산적 마이그레이션, raw_confidence 미러링). 예: {"algo":7.0,"news":1.0,"llm_context":-1.5,"overextension":"NONE","regime":"RISK_ON"} 저장.
  • Prediction.components: Optional[dict]; 삽입 시 직렬화, 읽기 시 파싱.
  • predict create --components '<json>' (형식 오류/비객체/NaN 거부).
  • metrics.get_component_contribution + stock-cli component-contribution: 필라별 승률 분할 (수치 → 양/영/음; 범주형 → 값별). 컴포넌트 태그된 행이 누적될 때까지 비어 있습니다.
  • 두 스킬 모두 이제 기록하는 모든 예측에 --components를 출력합니다.
  • tests/test_components.py에 14개 테스트 + CLI 검증 테스트 3개.
어떻게

components는 여러 타입된 열 대신 하나의 확장 가능한 JSON 열입니다 — 마이그레이션이 저렴하고 새 필라에 개방적입니다. 기여도 읽기는 "긍정적 뉴스/llm 기여가 실제로 적중률을 높이는가?"라는 질문에 답합니다 — 신뢰도 차별성을 복원할 학습 블렌드(E2-미래)를 위한 측정 기반입니다.

검증

전방 지향 인프라: 프로덕션에는 현재 컴포넌트 태그된 종료 행이 0개이므로, /expect + daily-briefing이 새 예측을 기록하기 전까지 component-contribution은 비어 있습니다. 기여도 수학은 시드된 데이터로 유닛 테스트됩니다(긍정적 뉴스 0.8 승 대 부정적 0.2). 백필 주장 없습니다.

리뷰 루프
  • 수정 (모두, 높음) — 전체 교체 마이그레이션 데이터 손실. _migrate_schema_if_needed가 raw_confidence / components를 생략하는 하드코딩된 열 목록을 복사했습니다. 이를 가진 드리프트된 pre-v2 DB는 이를 잃게 됩니다. 이제 이전 열과 새 열의 교집합을 복사합니다. 회귀 테스트 추가.
  • 수정 (codex, 중간) — NaN/Infinity가 json.loads에 허용됐습니다. 이제 parse_constant로 거부합니다(비표준 JSON으로 직렬화되어 수치 분할을 왜곡할 수 있음).
  • 수정 (code-reviewer, 중간) — 영 대 음수 혼동. 수치 필라가 이제 양/영/음으로 분할됩니다.
  • 수정 (codex, 낮음) — n_with_components가 유효하지 않은 행을 계산했습니다. 이제 성공적으로 파싱된 딕트 행만 계산합니다.
  • 언급됨 — CHECK(json_valid(...)) 제안 거절: SQLite 버전 의존적이며 CLI가 이미 검증합니다.
코드 위치
  • mcp-prediction-store/models.py — components 열, _ensure_components_column, _migrate_schema_if_needed의 교집합 복사, 데이터클래스/삽입/읽기.
  • mcp-prediction-store/metrics.py — get_component_contribution.
  • stock_cli.py — --components 플래그 + 검증, cmd_component_contribution.
  • .claude/skills/expect/SKILL.md, .claude/skills/daily-briefing/SKILL.md.
  • tests/test_components.py, tests/test_recalibration_cli.py.
회고

리뷰에서 변경 사항이 직접 건드리지 않았지만 폭발 반경을 확장시킨 마이그레이션 경로의 잠재적 데이터 손실 버그를 발견했습니다 — 열을 추가할 때마다 전체 교체 복사를 감사해야 한다는 것을 상기시켜 줍니다. 이 단계는 설계상 승률 변경을 제공하지 않습니다; 다음 조화 단계(학습 블렌드)를 가능하고 정직하게 만드는 데이터 기반입니다.

LLM 컨텍스트 엄격성 (LLM Context Rigor)

왜

LLM_CONTEXT(매크로/섹터/내러티브 채널)가 약하게 평가됐습니다(~19% 승률). LLM이 판단하는 필라이므로 강화가 가장 어렵습니다. 코드로 판단을 개선할 수는 없지만, 부실한 판단을 신뢰하기를 거부할 수 있습니다: 인용 증거 없는 강한 점수, 일방적 토론, 또는 범위를 벗어난 값.

무엇을
  • mcp-market-data/llm_context.py: validate_llm_context(debate)가 엄격성 위반을 반환합니다; clamp_score; score_from_debate.
  • stock-cli lint-llm-context '<json>' (위반 시 exit 1)로 /expect가 점수를 신뢰하기 전 자체 게이팅할 수 있습니다.
  • 5b 단계는 이제 bull/bear 토론을 JSON으로 구조화하고 린트합니다; 린트 미통과 시 점수를 0 방향으로 감쇄합니다.
  • tests/test_llm_context.py에 14개 테스트.
어떻게 — 게이트가 강제하는 것
  • score가 [-5, +3] 범위 내, 유한 (NaN/Infinity 거부).
  • winner가 점수의 부호와 일치 (0 → neutral).
  • 진정한 bear 케이스: 실제(비공백 문자열) 주장이 있는 bear_point가 최소 1개.
  • |score| ≥ 2.0이면, 승리 측에 비공백 문자열 증거와 {macro, sector, event, flow, valuation, technical, narrative} 중 하나인 signal_type이 있는 포인트가 최소 1개 있어야 합니다.
솔직한 범위

이것은 토론의 형태와 규율을 강제하지, 진실을 강제하지 않습니다. LLM은 여전히 얕지만 잘 형성된 증거를 제출할 수 있습니다. 이것이 올바른 분업입니다: 린터가 구조적 부실을 결정론적으로 차단하고, 인간/2차 패스 검토가 내용을 판단합니다. 중요하게도, llm_context의 점수가 이제 H1의 --components를 통해 영속화되므로, component-contribution이 이 필라가 실제로 전방 알파를 추가하는지 측정합니다 — "LLM 채널이 노이즈인가?"를 추측이 아닌 측정된 질문으로 바꿉니다.

리뷰 루프

두 검토자 모두 첫 버전을 "의식일 뿐, 엄격하지 않다"고 평가하며 구체적인 우회로를 찾았습니다 — 모두 수정됐습니다:

  • 가짜 bear 케이스 (bear_points: [{}] / [""]) 통과됨 — 이제 실제 문자열 주장이 있는 bear 포인트가 필요합니다.
  • 비문자열 증거 (evidence: {})가 truthy로 문자열화되어 인용으로 계산됨 — 이제 비공백 문자열 증거만 유효합니다.
  • NaN 점수가 최대 강세 3.0으로 제한됨 — clamp_score가 비유한 값에 None을 반환하고 validate가 이를 표시합니다.
  • score==0 승리측 잠재 버그 — 명시적 None (0에서 증거 규칙 없음).
  • 모든 닫힌 우회로 + score==0 경계에 대한 테스트 추가.

회고

검토자들이 v1이 사소하게 충족 가능하다는 점에서 옳았습니다. bear 주장과 문자열 증거 확인을 강화하여 실제로 작동하는 게이트로 만들었습니다. LLM 필라의 진정한 승리는 측정 (H1) + 이 규율 게이트를 함께 사용하는 것입니다: 노이즈는 결정론적으로 감쇄되고, 살아남은 것은 이제 귀인 가능합니다.

누출 감사 (Leakage Audit)

왜

INTERACTIVE 예측이 66.7% 대 LIVE 24.8%를 기록했습니다 — 42pp 격차가 선행/누출로 인한 것이라면 INTERACTIVE 실적(및 이를 기반으로 한 모든 것)은 허상이 됩니다. 교차 소스 수치를 신뢰하기 전에 해결해야 했습니다.

무엇을 — 감사

날짜, 지평선, 보유 기간 및 월별 승률로 두 소스를 비교했습니다(읽기 전용 DB 쿼리):

INTERACTIVE LIVE
n (종료) 102 318
created_at 범위 2026-04-04 … 05-16 2026-04-04 … 06-11
월별 승률 4월 49/72, 5월 19/30 5월 55/141 (39%), 6월 22/175 (12.6%)
중간 보유 (일) 26 2
최소 보유 1 0
판정: 레짐 + 선택, 누출 아님
  1. 시간 생존 편향 (지배적). INTERACTIVE는 5/16에 중단됐습니다 — 6월 폭락을 경험하지 않았습니다. LIVE는 55%가 6월 예측이며 12.6% 승률을 기록했습니다. 폭락 윈도우를 제거하면 격차가 붕괴됩니다.
  2. 잔여 선택 (더 작음). 같은 달(5월): INTERACTIVE 63% 대 LIVE 39%. INTERACTIVE는 수동 심층 분석(더 높은 확신, 더 적은 종목)이고, LIVE는 일별 브리핑 폭입니다. 다른 선택이며, 선행이 아닙니다.
  3. 역날짜 없음. 모든 INTERACTIVE 예측이 전방으로 해소됩니다 (최소 보유 1일); 당일/소급 예측 없습니다.
  4. LIVE 2일 중간 보유가 진짜 단서입니다: 6월 LIVE 롱 포지션이 거의 즉시 손절됐습니다 — 데이터 아티팩트가 아닌 D와 E1로 이미 해결된 과확장/레짐 실패.
취한 조치
  • 오염 위험(INTERACTIVE의 부풀린 보정이 LIVE 신뢰도로 누출)이 이미 무력화됐음을 확인했습니다: 재보정 맵(A)이 소스 범위로 지정되어 LIVE 예측은 항상 LIVE 이력에 대해서만 보정됩니다.
  • 남은 위험은 스킬이 읽는 혼합 헤드라인 실적으로, 오해를 불러일으키는 ~35% 안에 분할이 숨겨져 있었습니다. track-record가 이제 소스가 혼합될 때마다 by_source 분석을 출력하므로, LIVE(실제 성과)와 INTERACTIVE(수동 표본)가 다시는 혼동되지 않습니다.
리뷰 루프

감사 + 소규모 가산적 CLI 변경(cmd_track_record의 by_source). 유닛 테스트가 혼합 시 분석이 나타나고 --source 필터 적용 시 없음을 확인합니다. 감사 추론 외 검토자 지적 사항 없음. 테스트 403개 통과.

코드 위치

  • tests/test_recalibration_cli.py — 분석 테스트.
  • 격차를 이미 격리하는 소스 범위 지정: stock_cli.py:_recalibrated_confidence (소스 범위 재보정 맵, A단계).
회고

가장 무서워 보였던 수치(42pp 격차)가 무해한 것으로 판명됐습니다 — 하지만 날짜별, 소스별 분석만이 이를 증명했습니다. 수정 방법은 솔직한 분해를 기본 보기로 만들어, 아무도 혼합 수치를 "시스템의 정확도"로 인용하지 않도록 하는 것입니다. 앞으로: LIVE가 재보정/게이트 이후 표본을 축적하면, 공통 윈도우에서 이 비교를 재실행하여 순수 선택 효과를 분리합니다.

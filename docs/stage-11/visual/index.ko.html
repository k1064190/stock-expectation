11단계

예측 정확도 이니셔티브: 백필 A/B 평가 게이트, 결정론적 등온 재보정, 사멸 신호 제거, 강력한 시장 레짐 게이트, 그리고 종목별 과열 게이트 — 2026년 5월~6월 사이에 관찰된 승률 73% → 24% 폭락에 대한 종합 대응입니다.

Backfill Harness

왜

예측 승률이 73%(2026-05-11)에서 24%(2026-06-14)로 폭락했습니다. 승인된 계획은 여섯 가지 정확도 개선 항목(A–F)을 규정합니다. 각 변경 사항은 라이브 /expect 흐름에 반영되기 전에 반드시 과거 데이터로 검증되어야 합니다 — 그렇지 않으면 LIVE-vs-INTERACTIVE 낙관 편향(F4)이 반복됩니다. 이 하네스가 바로 그 검증 게이트입니다.

무엇을

scheduler/backfill_eval.py — 종료(HIT/MISS) 예측에 대한 읽기 전용 A/B 도구, 그리고 tests/test_backfill_eval.py (9개 테스트, 전부 통과). 보고 항목:

  • [A] 등온 재보정 — 누출 방지: 이전 훈련 슬라이스에서 재보정 맵을 피팅하고, 보류된 최근 테스트 슬라이스에서 원시 대비 재보정된 Brier 점수를 측정합니다.
  • [B] 사멸 신호 기여도 — 종료된 행을 사멸 신호 (valuation/cycle/mean_reversion) 사용 여부로 분류합니다.
  • [D] 레짐 창 억제 — 리스크-오프 구간 내에서 생성된 BULL 예측의 결과(강력한 레짐 게이트가 억제했을 경우의 효과)를 산출합니다.

최초 실행 결과 (실제 DB, n=420 종료):

변경 항목 지표 이전 이후
A (재보정, OOS) ALL Brier 0.340 0.204
A (재보정, OOS) LIVE Brier 0.331 0.160
B 사멸 신호 포함 승률 — 0.0% (n=15, Brier 0.424)
D BULL 6/1–6/7 승률 — 4.3% (n=140)
어떻게

별도로 재구현하지 않고 프로덕션 보정 수학 (build_recalibration_map, apply_recalibration, get_calibration_report in mcp-prediction-store/metrics.py)을 재사용합니다. 훈련 슬라이스를 인메모리 DB에 로드하므로 버킷팅이 라이브와 동일합니다. 시간순 분할은 get_signal_decay (outcome_date, created_at, id)를 미러링합니다.

  • tests/test_backfill_eval.py — 15개 단위 테스트.

Recalibration And Dead Signals

왜
  • F1/F7 (과신 + 미사용 재보정 맵): 0.60–0.70 신뢰도 구간이 실제보다 +0.28 높게 나타났으며, /expect가 수동 적용을 지시했음에도 기록된 신뢰도는 여전히 ~0.6 상수에 머물렀습니다. 수동 LLM 단계는 신뢰할 수 없으며 재보정은 결정론적이어야 합니다.
  • F2/F5 (사멸 신호): valuation, cycle, mean_reversion은 0%에 도달했으며 신호별 보정만 오염시킵니다.
무엇을
  • A — predict create에 --recalibrate 플래그 (stock_cli.py). 저장 전 원시 --confidence를 소스 범위 등온 곡선으로 매핑합니다; JSON에 raw_confidence / recalibration_applied를 출력합니다. 해당 소스의 종료 예측이 MIN_CLOSED_FOR_RECAL = 30 미만이면 안전하게 무작동합니다.
  • B — 사멸 신호 제거: /expect와 daily-briefing 스킬의 허용 --signals 목록에서 제거했습니다. 운영자는 해당 읽기를 LLM_CONTEXT_SCORE를 통해 라우팅하도록 안내받습니다.
  • 기존 수정 (승인됨): weekly_calibration.py:208,236 avg-return 형식 :+.2% → :+.2f%.
  • 테스트: tests/test_recalibration_cli.py (3개) — 최소 표본 게이트, 과신 하향, 소스 범위 지정.
어떻게

재보정은 build_recalibration_map / apply_recalibration (mcp-prediction-store/metrics.py)을 재사용합니다. 전역 (전체 지평선) 맵을 사용합니다 — 백필에서 지평선별 맵만큼 정확하면서 (Brier 0.160 vs 0.169) 현재 표본 크기에서 더 강건합니다. 소스 범위 지정: LIVE 예측은 LIVE 이력에 대해서만 보정되며, 과적합된 INTERACTIVE 행(F4 격차)과는 무관합니다. 로깅 임계값은 여전히 원시 신뢰도 기준으로 게이팅되며, 저장되는 값만 재보정됩니다.

검증

백필 OOS Brier: LIVE 0.331 → 0.160, ALL 0.340 → 0.204 (누출 방지 훈련/테스트 분할).

라이브 맵 검사에서 드러난 주의 사항: 프로덕션 LIVE 곡선은 원시 신뢰도가 상수에 가깝기 때문에 단일 앵커 (0.612 → 0.248)만 가집니다. 따라서 재보정은 모든 신뢰도를 ~0.25 기본 비율로 수렴시킵니다. 이것이 Brier 개선의 원인이지만, 모델이 정보적인 신뢰도 분포를 출력하기 전까지 기록된 신뢰도가 종목을 순위 매기는 기능을 잃는다는 의미이기도 합니다. 식별력 복원은 후속 작업(변경 E / 메타 레이블링)입니다.

리뷰 루프
  • CRITICAL (전원, 수정) — 재보정이 자체 훈련 데이터를 오염시켰습니다. 재보정된 값을 다시 confidence에 저장하면 향후 맵이 오염됩니다: build_recalibration_map / get_calibration_report가 confidence를 원시 예측값으로 읽기 때문에, 재보정된 행(≈0.25)이 종료되면 원시인 것처럼 곡선에 재진입하여 도메인을 붕괴시키고(재귀 피드백) 재실행 시 조용히 이중 적용됩니다. 수정: nullable raw_confidence 열 추가(models.py 스키마 + 가산적 _ensure_raw_confidence_column 마이그레이션 + dataclass/insert/reader); 보정은 이제 COALESCE(raw_confidence, confidence)로 훈련됩니다. 새 테스트 test_map_trains_on_raw_not_recalibrated가 stored-0.30 / raw-0.65 행이 맵에 0.65로 기여함을 증명합니다. 마이그레이션이 프로덕션 복사본에서 검증되었습니다 (1169행 보존, 열 추가, 기존 맵 변경 없음).
  • 수정 — 테스트 공백 (codex/code-reviewer): empty-map-after-gate no-op, no-corruption 테스트, 그리고 엔드투엔드 cmd_predict_create --recalibrate 테스트를 추가했습니다.
  • 인정 — 재실행 이중 적용: 호출자가 이미 보정된 신뢰도를 --recalibrate로 재제출하면 재매핑됩니다. 정상적인 /expect 경로 외의 경우이며, 문서화만 하고 게이팅하지 않았습니다.

회고

재보정을 수동 LLM 지시에서 CLI 플래그로 전환한 것이 F7의 진정한 수정입니다 — 맵은 수 주 동안 존재했지만 신뢰할 수 있게 적용된 적이 없었습니다. 실제 라이브 맵을 검사(백필 델타만이 아닌)하여 재보정이 현재 기본 비율로 퇴화하고 있음을 발견한 것은 중요합니다: 나중에 신뢰도가 식별력을 잃었음을 발견하는 것보다 지금 솔직하게 기록하는 것이 낫습니다.

Regime Gate

왜

F3: 2026년 6월 하락 구간 동안 /expect는 조정 내내 BULL을 계속 발행했습니다(6/1–6/7 종료된 BULL 140건, 승률 4.3%). 결정론적 리스크-오프 게이트가 없었으며 매크로 스킬은 LLM이 무시할 수 있는 권고성 콜아웃에 불과했습니다.

무엇을
  • stock-cli regime --market US|KR → 지수 프록시 가격 구조(MA50/MA200 대비 추세, 52주 고점 대비 낙폭, 1개월 수익, 연환산 20일 실현 변동성)로부터 결정론적 RISK_ON / NEUTRAL / RISK_OFF 판정. 미국은 SPY + QQQ 중 더 나쁜 것을 집계하고, 한국은 KODEX 200 (069500)을 사용합니다.
  • /expect(RULE R1)와 daily-briefing(RULE R1)에 강력한 게이트를 연결: RISK_OFF → 새 BULL 억제 (WATCH로 제한, 지평선 → NEUTRAL); NEUTRAL → BUY 기준 8.0→9.0 상향 및 신뢰도 축소(0.60 상한); RISK_ON → 변경 없음.
  • tests/test_regime.py (16개 테스트).
어떻게

mcp-market-data/regime.py의 순수하고 네트워크 없는 로직 (compute_realized_vol, compute_regime, aggregate_regime); CLI는 기존 프로바이더 + compute_horizon_metrics를 통해 지수 바 데이터를 공급합니다. aggregate_regime은 dataclasses.replace를 통해 최악의 프록시를 반환하며(입력 변형 없음) 모든 프록시의 점수를 proxy_scores에 기록합니다.

검증

각 예측의 발행일 기준으로 레짐을 재구성하고 종료된 BULL 140건을 분류했습니다(6월 구간에 대한 네트워크 재구성 — 정직한 결과):

  • 발행 시 NEUTRAL: n=65, 승률 3.1% — 게이트가 억제/강화합니다.
  • 발행 시 RISK_ON: n=75, 승률 5.3% — 발행 당시 지수는 평온했습니다; 게이트로 잡을 수 없습니다.
  • 6/2 클러스터(72건)는 지수만으로는 게이팅 불가 — QQQ조차 RISK_ON이었고 낙폭은 이후에 발생했습니다. SPY는 전체 구간에서 RISK_ON을 유지했고, QQQ는 6/7이 되어서야 NEUTRAL로 전환되었습니다. KR은 포물선 변동성(1M +40%, vol 56%)을 통해 일찍 NEUTRAL을 표시했습니다.

결론 (과장 없음): 레짐 게이트는 부분적 완화 수단입니다 — 해당 구간의 패패(NEUTRAL) 약 46%를 제거하고 진행/포물선 조정장에서의 매수를 차단하지만, 6/2 고점에서 광역 지수는 평온했습니다. 보완 수단인 종목별 과열 게이트는 계획된 후속 단계이며, 재보정(A)은 이미 6/2 클러스터를 그토록 치명적으로 만든 과신을 해소합니다.

리뷰 루프
  • 수정 (전원) — aggregate_regime이 입력 판정을 변형시켰습니다. 이제 dataclasses.replace를 사용하며 테스트가 입력 불변을 검증합니다.
  • 수정 (codex High) — cmd_regime이 실패한 프록시를 조용히 제거했습니다 (QQQ 누락은 성장 주도 하락에 대한 미국 게이트를 맹목적으로 만듭니다). 누락된 프록시는 이제 판정 메모에 표시됩니다.
  • 수정 (codex+gemini) — 불충분한 이력이 RISK_ON으로 기본값 설정되었습니다. MA200 없이는 추세를 알 수 없으므로 강력한 게이트는 RISK_ON을 인증해서는 안 됩니다; 이제 메모와 함께 NEUTRAL로 하한이 설정됩니다.
  • 수정 — argparser 도움말이 미국 기본값으로 SPY를 명시했습니다; 이제 "worst-of SPY+QQQ"로 변경되었습니다.
  • 수정 — 테스트 공백: 정확한 실현 변동성 값, MA 우선순위, 불충분한 이력, 무변형, tie→first, 단일 프록시.
  • 기각 — 임계값 진동/히스테리시스 (gemini): 임계값 근처의 일별 진동은 영구 상태가 필요합니다; 게이트는 장중이 아닌 브리핑당 한 번 조회됩니다. 알려진 제한으로 문서화했습니다.

Overextension Gate

왜

D단계 검증은 광역 지수 레짐 게이트가 6/2 클러스터를 잡을 수 없음을 증명했습니다: 그 패자들(ORCL, NET, SMCI, DDOG, KR 반도체)은 지수가 평온한 동안 반전한 포물선 개별 종목들이었습니다. 종목별 과열 게이트가 누락된 레버입니다.

무엇을
  • HorizonMetrics에 새 overextension_level (NONE / ELEVATED / EXTREME) 추가. RSI14와 MA20 대비 가격 거리로 classify_overextension(rsi14, price, ma20)를 통해 계산됩니다. horizon-metrics[-batch]에서 자동으로 표시됩니다.
  • /expect + daily-briefing의 RULE R2: EXTREME → 새 BULL 억제(WATCH로 제한); ELEVATED → BUY 기준 +1.0 상향 및 신뢰도 축소 (0.60 상한).
  • R1+R2 중첩을 명시적으로 규정: 어느 쪽에서든 WATCH 상한이 우선; BUY 기준 상향은 가산적 (NEUTRAL 레짐 + ELEVATED 종목 → COMPOSITE ≥ 10.0).
  • mcp-market-data/tests/test_indicators.py에 테스트 추가; CLI 계약 테스트가 새 필드를 고정합니다.
어떻게

377개의 종료된 BULL에 대해 각 예측의 진입 시점 메트릭을 (created_at까지 각 종목 이력을 잘라내어) 재구성하여 임계값을 보정했습니다: EXTREME = RSI14 > 75 또는 MA20 대비 15% 초과; ELEVATED = RSI14 > 70 또는 8% 초과. 순수하고 네트워크 없는 분류기입니다.

검증

진입 시점 재구성, 377개 종료 BULL:

진입 시 overextension_level n 승률
NONE 99 53.5%
ELEVATED 79 41.8%
EXTREME 199 29.1%

EXTREME 억제 시 유지된 BULL 승률이 48.3%(n=178) vs 전체 38.2% — +10pp로 상승하며 깔끔한 단조 기울기를 보입니다. RSI14만으로: RSI14>75는 26.4%(n=125) vs RSI14<60에서 47.5%. MA20 거리로: >15%는 29.6%(n=196) vs 3–8% 구간에서 66%.

리뷰 루프
  • 세 명의 리뷰어 모두 코드가 올바르다고 검증했습니다(심각도 순서, ma20≤0/None 가드, RSI-None 기본값, 포인트 테이블과 이중 계산 없음, 기본값 dataclass 필드는 하위 호환).
  • 수정 (codex Medium) — R1+R2 중첩 모호성: 기준 상향이 가산적이고 WATCH 상한이 "어느 쪽이든 우선"임을 문서화했습니다.
  • 수정 (both Low) — 오래된 스키마 목록 / 미고정 필드: /expect 필드 목록과 CLI 계약 테스트의 expected_fields에 overextension_level을 추가했습니다.
  • 수정 — 경계 테스트: 엄격한 RSI 경계 및 MA20-band 테스트를 추가했습니다(부동소수점 불안정 정확-퍼센트 엣지는 한 번 플레이크 후 회피).
  • 주목 (both) — ELEVATED는 의도적으로 완화됩니다: RSI 70–75는 여전히 +0.5 모멘텀과 근고점 사이클 +1.0을 얻어 R2의 +1.0 기준 상향을 부분 상쇄합니다. 정당화: ELEVATED는 41.8% (손익분기점에 가까움)이므로 부드러운 게이트가 적절합니다; EXTREME(29%)은 강제 억제를 받습니다.

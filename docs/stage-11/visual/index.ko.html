11단계

예측 정확도 개선 이니셔티브: 모든 변경사항을 검증하는 읽기 전용 A/B 백필 하네스, 결정론적 재보정 및 불량 시그널 제거, 강제 시장 레짐 게이트, 종목별 과확장 게이트, 그리고 단순 거래량 점수를 대체하는 구조화된 뉴스 피처.

Backfill Harness

왜

예측 승률이 73%(2026-05-11)에서 24%(2026-06-14)로 붕괴됐다. 승인된 계획은 여섯 가지 정확도 변경사항(A–F)을 처방한다. 각 변경사항은 라이브 /expect 흐름에 적용되기 전에 반드시 과거 데이터로 검증해야 한다 — 그렇지 않으면 LIVE-vs-INTERACTIVE 낙관 편향(F4)을 반복할 위험이 있다. 이 하네스가 그 게이트다.

무엇을

scheduler/backfill_eval.py — 종료된(HIT/MISS) 예측에 대한 읽기 전용 A/B 도구, 그리고 tests/test_backfill_eval.py (테스트 9개, 전부 통과).

보고 섹션:

  • [A] Isotonic recalibration — 누출 방지: 이전 학습 슬라이스로 재보정 맵을 피팅하고, 보류된 최근 테스트 슬라이스에서 원시 대비 재보정 Brier를 채점한다.
  • [B] Dead-signal contribution — 종료 행을 불량 시그널 (valuation/cycle/mean_reversion) 사용 여부로 분류한다.
  • [D] Regime-window suppression — 리스크 오프 구간에서 생성된 BULL 예측 결과 (강제 레짐 게이트가 억제했을 경우의 가상 시나리오).

첫 실행 결과 (실제 DB, n=420 종료):

변경 지표 이전 이후
A (recal, OOS) ALL Brier 0.340 0.204
A (recal, OOS) LIVE Brier 0.331 0.160
B with-dead-signal 승률 — 0.0% (n=15, Brier 0.424)
D BULL 6/1–6/7 승률 — 4.3% (n=140)

A와 D의 효과를 강하게 검증했으며, B는 노이즈(저거래량)임을 확인했다.

어떻게

재구현 대신 프로덕션 보정 로직(build_recalibration_map, apply_recalibration, get_calibration_report in mcp-prediction-store/metrics.py)을 재사용했다. 학습 슬라이스는 인메모리 DB에 로드하여 버킷팅이 라이브와 동일하게 유지된다. 시간 순 분할은 get_signal_decay (outcome_date, created_at, id)를 미러링한다.

코드 위치
  • scheduler/backfill_eval.py — 하네스 (_connect_readonly, load_closed, _metrics, eval_recalibration, eval_dead_signals, eval_regime_window, build_report).
  • tests/test_backfill_eval.py — 유닛 테스트 15개.
리뷰 루프
  • 수정 — DB 읽기 전용 미적용 (codex, High): 하네스가 models.get_connection을 사용했는데, 이는 마이그레이션/인덱싱/WAL/중복 자가복구(쓰기)를 수행한다. _connect_readonly (file:...?mode=ro URI)로 교체하여 읽기 전용 계약을 준수한다.
  • 수정 — avg-return ×100 부풀림 (codex, Low): outcome_return은 퍼센트 포인트로 저장되어 있는데 :+.2% 포맷 지정자가 100을 곱해 −865%를 표시했다. 이제 :+.2f%로 수정했다. 이전의 "데이터 손상" 메모는 틀렸다 — 데이터는 정상이었고 표시 버그였다.
  • 수정 — 잘못된 oos_fraction / 소규모 n (codex + gemini): 0 < oos_fraction < 1 검증과 "데이터 부족" 가드를 보고서에 추가했다.
  • 수정 — 시간대별 재보정 (gemini + code-reviewer): eval_recalibration/build_report에 선택적 timeframe을 노출하고 --timeframe CLI 플래그를 추가하여 변경사항 A가 전체 대비 시간대별 맵을 비교할 수 있도록 했다.
  • 수정 — 테스트 누락: 잘못된 fraction, 빈 시그널 목록, 커스텀 불량 세트, build_report 스모크 테스트 추가 (9개 → 15개).
  • 기각 — 인메모리 스키마 "Critical" (code-reviewer): 세 리뷰어 모두 get_calibration_report가 confidence/status/source/timeframe만 읽는다고 확인했다. 4열 임시 테이블이 정확히 맞다.
  • 기각 — 엄격한 점-시간 분할 (gemini/codex): 분할이 outcome_date 기준이므로 테스트 결과가 피팅된 맵에 포함되지 않는다. 잔여 PIT 효과는 정상적 과신 편향에서 2차적이며 라이브 재보정을 미러링한다. 재구조화 대신 eval_recalibration에 문서화했다.
기존에 알려진 문제

scheduler/weekly_calibration.py:208,236이 동일한 ×100 부풀림 버그인 :+.2%로 avg_return을 포맷한다 — 프로덕션 주간 보고서가 평균 수익을 과대 표시한다. 별도의 범위 한정 수정을 위해 남겨뒀다.

회고

인메모리 DB를 통해 프로덕션 재보정 빌더를 재사용함으로써 하네스의 정직성을 유지했다 (라이브와 괴리될 수 있는 중복 보정 로직 없음). 세 리뷰어 루프는 충분히 효과를 발휘했다: codex가 읽기 전용 계약 위반과 데이터를 잘못 탓하게 한 포맷 버그를 잡아냈다. 앞으로 이어갈 교훈: 데이터를 탓하기 전에 표시 경로를 먼저 검증하라.

Recalibration And Dead Signals

왜

F1/F7 (과신 + 미사용 재보정 맵): 0.60–0.70 신뢰도 구간이 실제보다 +0.28 높게 나타났으며, /expect가 운영자에게 재보정 맵을 수동으로 적용하라고 지시했음에도 백필 결과 기록된 신뢰도는 여전히 ~0.6 상수 수준이었다. 수동 LLM 단계는 신뢰할 수 없다; 재보정은 결정론적이어야 한다.

F2/F5 (불량 시그널): valuation, cycle, mean_reversion이 0%를 기록하여 시그널별 보정을 오염시키기만 한다.

무엇을
  • A — predict create에 --recalibrate 플래그 (stock_cli.py). 저장 전 원시 --confidence를 소스 범위 isotonic 곡선을 통해 매핑한다; JSON에 raw_confidence / recalibration_applied를 출력한다. 해당 소스의 종료 예측이 MIN_CLOSED_FOR_RECAL = 30 미만이면 안전하게 no-op 처리된다.
  • B — 불량 시그널 제거: /expect와 daily-briefing 스킬의 허용 --signals 목록에서 제거됐다. 운영자는 해당 내용을 대신 LLM_CONTEXT_SCORE로 전달하도록 안내된다.
  • 기존 버그 수정 (승인됨): weekly_calibration.py:208,236이 avg_return을 :+.2%(×100 부풀림)로 포맷했다. 이제 :+.2f%로 수정됐다.
  • 테스트: tests/test_recalibration_cli.py (3개) — 최소 샘플 게이트, 과신 하향, 소스 범위 지정.
어떻게

재보정은 build_recalibration_map/apply_recalibration (mcp-prediction-store/metrics.py)을 재사용한다. 전체(all-horizon) 맵을 사용한다 — 백필 결과 시간대별 맵과 동등하게 정확(Brier 0.160 대 0.169)하면서 현재 샘플 크기에서 더 안정적이었다. 소스 범위: LIVE 예측은 LIVE 히스토리에 대해서만 보정하며, 과적합된 INTERACTIVE 행(F4 격차)은 포함하지 않는다. 기록 임계값은 여전히 원시 신뢰도 기준이며, 저장되는 값만 재보정되므로 "각 horizon ≥ 0.60 저장" 의미는 변경되지 않는다.

검증

백필 OOS Brier: LIVE 0.331 → 0.160, ALL 0.340 → 0.204 (누출 방지 학습/테스트 분할).

라이브 맵 점검에서 발견된 주의사항: 프로덕션 LIVE 곡선이 단일 앵커 (0.612 → 0.248)만 갖는다. 원시 신뢰도가 상수에 가깝기 때문에 재보정이 모든 신뢰도를 ~0.25 기준 비율로 무너뜨린다. 이것이 Brier 개선의 원인이지만(기준 비율이 비정보적인 0.6보다 낫다 — 순열 검정에서 원시 신뢰도가 시그널을 갖지 않음이 이미 밝혀졌다), 모델이 정보성 있는 신뢰도 분포를 출력하기 전까지는 기록된 신뢰도가 종목 순위를 매기지 못한다는 의미이기도 하다. 변별력 회복은 다운스트림 작업 (변경사항 E / 메타 레이블링)이며 재보정의 역할이 아니다.

리뷰 루프
  • 심각 (3명 모두, 수정) — 재보정이 자체 학습 데이터를 오염시켰다. 재보정된 값을 confidence에 저장하면 향후 맵이 오염된다. 수정: nullable raw_confidence 열 추가 (models.py 스키마 + additive _ensure_raw_confidence_column 마이그레이션 + 데이터클래스/삽입/리더); predict create는 이제 항상 원시 신뢰도를 거기에 저장하며, 보정은 COALESCE(raw_confidence, confidence)로 학습하여 재보정된 값을 절대 볼 수 없다. 새 테스트 test_map_trains_on_raw_not_recalibrated가 stored-0.30 / raw-0.65 행이 맵에 0.65를 기여함을 증명한다. 프로덕션 복사본으로 마이그레이션 검증 완료 (1169행 보존, 열 추가, 기존 맵 변경 없음).
  • 수정 — 테스트 누락 (codex/code-reviewer): 게이트 이후 빈 맵 no-op, 비오염 테스트, 그리고 raw가 보존되고 저장된 신뢰도가 보정됨을 확인하는 엔드투엔드 cmd_predict_create --recalibrate 테스트 추가.
  • 인지됨 — 재생 이중 적용: 호출자가 저장된(이미 보정된) 신뢰도를 --recalibrate와 함께 수동 재제출하면 다시 매핑될 것이다. 모델의 원시 신뢰도를 항상 전달하는 정상적인 /expect 경로 밖의 일이므로 문서화만 하고 게이팅하지 않았다.
코드 위치
  • stock_cli.py — _recalibrated_confidence, MIN_CLOSED_FOR_RECAL, cmd_predict_create, --recalibrate 인자, raw_confidence 저장.
  • mcp-prediction-store/models.py — raw_confidence 열, 스키마, _ensure_raw_confidence_column, 데이터클래스 필드, 삽입, _row_to_prediction.
  • mcp-prediction-store/metrics.py — get_calibration_report가 COALESCE(raw_confidence, confidence)로 학습.
  • scheduler/weekly_calibration.py:208,236 — avg_return 포맷 수정.
  • .claude/skills/expect/SKILL.md — 재보정 단계 + 불량 시그널 목록.
  • .claude/skills/daily-briefing/SKILL.md — 재보정 단계 + 불량 시그널 규칙.
  • tests/test_recalibration_cli.py — 유닛 테스트 7개.
회고

재보정을 수동 LLM 지시에서 CLI 플래그로 옮긴 것이 F7의 진짜 수정이다 — 맵은 몇 주 동안 존재했지만 한 번도 안정적으로 적용되지 않았다. 백필 델타만이 아니라 실제 라이브 맵을 점검한 결과 재보정이 현재 기준 비율로 퇴화하고 있음을 발견했다. 나중에 신뢰도가 변별력을 잃었다는 사실을 발견하는 것보다 지금 솔직하게 기록하는 편이 낫다.

Regime Gate

왜

F3: 2026년 6월 하락장에서 /expect가 조정 내내 BULL을 계속 발행했다 (6/1–6/7의 종료된 BULL 140건의 승률 4.3%). 결정론적 리스크 오프 게이트가 없었다 — 매크로 스킬은 LLM이 무시할 수 있는 권고 콜아웃이었다.

무엇을
  • stock-cli regime --market US|KR — 지수 프록시 가격 구조에서 결정론적 RISK_ON / NEUTRAL / RISK_OFF 판정 (MA50/MA200 대비 추세, 52주 고점 대비 하락, 1M 수익, 연환산 20일 실현 변동성). US는 SPY + QQQ 중 나쁜 쪽을 집계; KR은 KODEX 200(069500) 사용.
  • 강제 게이트를 /expect(RULE R1)와 daily-briefing (RULE R1)에 연결: RISK_OFF → 새 BULL 억제 (WATCH 상한, horizon → NEUTRAL); NEUTRAL → BUY 기준 8.0→9.0 상향 및 신뢰도 축소 (0.60 상한); RISK_ON → 변경 없음.
  • tests/test_regime.py (테스트 16개).
어떻게

mcp-market-data/regime.py의 순수한 네트워크 불필요 로직 (compute_realized_vol, compute_regime, aggregate_regime); CLI는 기존 프로바이더 + compute_horizon_metrics를 통해 지수 바를 공급한다. aggregate_regime은 dataclasses.replace로 (입력 변형 없이) 최악의 프록시를 반환하며 모든 프록시 점수를 proxy_scores에 기록한다.

검증

각 예측 발행일 기준으로 레짐을 재구성하여 종료된 BULL 140건을 분류했다:

  • 발행 시 NEUTRAL: n=65, 승률 3.1% — 게이트가 이것들을 억제/강화한다.
  • 발행 시 RISK_ON: n=75, 승률 5.3% — 발행 당시 지수가 평온해 보였다; 게이트가 이것들을 잡을 수 없다.
  • 6/2 클러스터(72건)는 지수 단독으로는 차단 불가능했다 — QQQ조차 RISK_ON이었고 하락은 이후에 왔다. SPY는 전체 기간 동안 RISK_ON을 벗어나지 않았다; QQQ는 6/7에 NEUTRAL로 전환됐다; KR은 포물선형 변동성(1M +40%, vol 56%)을 통해 일찍 NEUTRAL을 경보했다.

결론 (과장 없음): 레짐 게이트는 부분적인 완화책이다 — 해당 기간 패자의 ~46%(NEUTRAL 건)를 제거하고 진행/포물선형 조정에서 매수를 차단하지만, 6/2 고점에서는 광범위 지수가 평온했다. 보완 레버 — 종목별 과확장 — 은 계획된 후속 단계이며, 재보정(A)이 이미 6/2 클러스터를 그토록 손실적으로 만든 과신을 줄여준다.

리뷰 루프
  • 수정 (3명 모두) — aggregate_regime이 입력 판정을 변형했다. 이제 dataclasses.replace가 복사본을 반환하며 테스트가 입력이 변형되지 않았음을 단언한다.
  • 수정 (codex High) — cmd_regime이 실패한 프록시를 조용히 버렸다 (QQQ 손실 시 US 게이트가 성장주 주도 하락에 눈이 멀 수 있음). 이제 누락된 프록시가 판정 노트에 표시된다.
  • 수정 (codex+gemini) — 불충분한 히스토리가 RISK_ON으로 기본값을 사용했다. MA200 없이는 추세를 알 수 없으므로 강제 게이트가 RISK_ON을 확인해서는 안 된다; 이제 노트와 함께 NEUTRAL로 하한 설정.
  • 수정 — argparser 도움말이 US 기본값으로 SPY라고 했다; 이제 "worst-of SPY+QQQ".
  • 수정 — 테스트 누락: 정확한 실현 변동성 값, MA 우선순위, 불충분한 히스토리, 비변형, 타이→첫 번째, 단일 프록시.

Overextension Gate

왜

D단계 검증에서 광범위 지수 레짐 게이트가 6/2 클러스터를 잡을 수 없음이 밝혀졌다: 패자들(ORCL, NET, SMCI, DDOG, KR 반도체)은 지수가 평온한 동안 역전된 포물선형 개별 종목이었다. 종목별 과확장 게이트가 누락된 레버다.

무엇을
  • HorizonMetrics에 새 overextension_level (NONE / ELEVATED / EXTREME) 추가. RSI14와 MA20 대비 가격 거리로 classify_overextension(rsi14, price, ma20)가 계산한다. horizon-metrics[-batch]에서 자동으로 표시된다.
  • /expect + daily-briefing에 RULE R2: EXTREME → 새 BULL 억제 (WATCH 상한); ELEVATED → BUY 기준 +1.0 상향 및 신뢰도 축소 (0.60 상한).
  • R1+R2 중첩을 명시적으로 지정: WATCH 상한은 어느 쪽에서든 적용되며; BUY 기준 상향은 가산적임 (NEUTRAL 레짐 + ELEVATED 종목 → COMPOSITE ≥ 10.0).
  • mcp-market-data/tests/test_indicators.py에 테스트 추가; CLI 계약 테스트가 새 필드를 고정.
어떻게

각 예측의 진입 시점 지표를 재구성하여 종료된 BULL 377건으로 임계값을 보정했다 (각 티커 히스토리를 created_at으로 절단): EXTREME = RSI14 > 75 또는 가격 > MA20 15% 초과; ELEVATED = RSI14 > 70 또는 > 8% 초과. 순수하고 네트워크 불필요한 분류기.

검증
진입 시 overextension_level n 승률
NONE 99 53.5%
ELEVATED 79 41.8%
EXTREME 199 29.1%

EXTREME을 억제하면 유지된 BULL 승률이 48.3%(n=178) 대 전체 38.2% — +10pp로 깔끔한 단조 기울기를 보인다. RSI만으로: RSI>75가 26.4%(n=125) 대 RSI<60의 47.5%. MA20 거리 기준: >15%가 29.6%(n=196) 대 3–8% 구간의 66%.

리뷰 루프
  • 3명 모두 코드가 정확하다고 검증했다 (심각도 순서, ma20≤0/None 가드, RSI-None 기본값, 포인트 테이블과 이중 계산 없음, 기본값 데이터클래스 필드가 하위 호환).
  • 수정 (codex Medium) — R1+R2 중첩 모호성: 기준 상향은 가산적이고 WATCH 상한은 "어느 쪽이든 적용"으로 문서화했다.
  • 수정 (모두 Low) — 오래된 스키마 목록 / 고정되지 않은 필드: /expect 필드 목록과 CLI 계약 테스트의 expected_fields에 overextension_level을 추가했다.
  • 수정 — 경계 테스트: 엄격한 RSI 경계와 MA20 밴드 테스트 추가 (한 테스트가 실패한 후 부동소수점 불안정 정확 퍼센트 엣지 회피).
  • 주목 (모두) — ELEVATED는 의도적으로 완화: RSI14 70–75가 여전히 모멘텀 +0.5와 고점 근접 사이클 +1.0을 얻어 R2의 +1.0 기준을 부분적으로 상쇄한다. 정당화: ELEVATED가 41.8%(손익분기점 근접)를 기록했으므로 소프트 게이트가 적절하고; EXTREME(29%)이 강제 억제를 받는다.

News Features

왜

news 시그널이 "불량"으로 등급됐다(~33% 승률). 근본 원인: 원시 헤드라인 거래량과 평평한 감성 평균을 채점했다 — 재게시로 거래량이 부풀었고 오래된 약한 신호가 강한 촉매와 동일한 가중치를 받았다. 최신 뉴스 기둥에는 거래량이 아닌 정보가 필요했다.

무엇을
  • mcp-market-data/news_features.py: NewsSignal을 생성하는 순수 피처 추출기 — 중복 제거된 unique_count, recency-weighted sentiment (3일 반감기 지수 감쇠), 촉매 event_tags (earnings/guidance/ma/analyst/regulatory_legal/product/leadership/capital), 그리고 has_positive_catalyst / has_negative_catalyst 플래그.
  • news CLI 명령이 이제 items와 함께 signal 블록을 출력한다.
  • 두 스킬 모두 signal에서 NEWS_SCORE를 채점하고 (recency-weighted sentiment, 중복 제거된 거래량, 부정 촉매 하한) event_tags를 LLM_CONTEXT 토론에 공급한다.
  • tests/test_news_features.py에 테스트 16개.
어떻게
  • 최신성 가중치: w = 0.5 ** (age_days / 3) — 1주일 전 기사가 최신의 ~20%; 미래 날짜는 age 0으로 고정; 파싱 불가 날짜는 단위 가중치로 폴백.
  • 중복 제거: 최소 5단어 접두사 포함 관계 검사로 와이어 재게시 ("…, shares jump")는 축소되지만 짧은 일반 토막이 별개 기사를 삼키지 않는다.
  • 매칭: ASCII 키워드는 단어 경계에서 매칭 (\bmiss\b — "mission"/"twins"/"heartbeat" 불가); 한국어 키워드는 부분 문자열로 매칭하여 KR Naver 헤드라인 (Alpha Vantage 감성 없음)에서도 이벤트 태그와 촉매 플래그를 생성 (감자/유상증자/실적/소송 …).
검증

구조적/품질 개선 — 예측별 과거 헤드라인이 저장되지 않아 이것은 백필 승률로 검증되지 않는다 (명확히 명시). 정당화는 정보 품질이다: 중복 제거로 이중 계산을 없애고, 최신성 가중치로 오래된 뉴스를 약화시키며, 촉매 태깅으로 중요한 이벤트와 노이즈를 분리한다. 뉴스 시그널 승률을 높이는지는 주간 보정을 통해 향후 측정될 것이다. 실시간 확인: US AAPL이 채워진 감성 시그널을 반환했다; KR 005930이 헤드라인을 8개에서 7개로 중복 제거했다.

리뷰 루프
  • 수정 (모두, High) — 부분 문자열 촉매 오탐: "miss"/"halt"/"wins"/"beat"가 "mission"/"health"/"twins"/"heartbeat"에서 −2 하한을 발동할 수 있었다. 이제 ASCII 키워드가 단어 경계 정규식을 사용하고 목록이 모호하지 않은 구문("earnings miss", "trading halt")을 선호한다. 테스트가 오탐 없음을 단언.
  • 수정 (codex, High) — 스킬 드리프트: /expect에만 존재하던 미검증 "+1.0 hard catalyst" 행 제거; NEWS_SCORE가 이제 두 스킬 간 동일하다 (감성 + 거래량 + 부정 상한; 태그는 LLM만 공급).
  • 수정 (모두, Medium) — 중복 제거 과통합: 5단어 최소 접두사 가드 추가; 테스트가 "Nvidia shares rise"가 더 긴 별개 헤드라인을 더 이상 삼키지 않음을 증명.
  • 수정 (모두, Medium) — 한국어 맹점: 모든 이벤트 범주와 촉매 목록에 한국어 키워드를 추가하고 한글에 부분 문자열 매칭 적용.
  • 수정 — 테스트 누락: 단어 경계, 한국어, 짧은 접두사, 미래 날짜 고정, 두 항목 잘못된 날짜, 오래된 헤드라인 감쇠.
  • 주목 — 최신성 반감기가 하드코딩됨 (3일): 향후 조정을 위해 모듈 상수(RECENCY_HALF_LIFE_DAYS)로 노출됐다.

11단계

예측 정확도 개선 이니셔티브: 읽기 전용 백필 A/B 평가 하네스가 모든 정확도 변경 사항을 라이브 흐름에 적용하기 전에 과거 데이터로 검증하고, 결정론적 재보정과 사장된 시그널 제거가 체계적 과신을 수정하며, 시장 레짐 게이트와 종목별 과확장 게이트가 고위험 진입을 억제하고, 구조화된 뉴스 기능이 단순 볼륨 점수를 대체하며, 필라별 컴포넌트 영속성이 학습 기반 신뢰도 블렌딩의 토대를 마련하고, LLM_CONTEXT 엄밀성 게이트가 해당 필라 점수를 신뢰하기 전에 토론 규율을 강제합니다.

Backfill Harness

왜

예측 승률이 73%(2026-05-11)에서 24%(2026-06-14)로 붕괴되었습니다. 승인된 계획은 여섯 가지 정확도 변경 사항(A–F)을 규정합니다. 각 변경 사항은 라이브 /expect 흐름에 적용되기 전에 반드시 과거 데이터로 검증되어야 합니다 — 그렇지 않으면 LIVE-vs-INTERACTIVE 낙관주의 편향(F4)을 반복할 위험이 있습니다. 이 하네스가 바로 그 게이트입니다.

무엇을

scheduler/backfill_eval.py — 종료된(HIT/MISS) 예측에 대한 읽기 전용 A/B 도구이며, tests/test_backfill_eval.py(15개 테스트, 전부 통과)를 포함합니다. 보고 섹션:

  • [A] 등조 재보정 — 누수 방지: 초기 훈련 슬라이스에 재보정 맵을 피팅하고, 최근 보류 테스트 슬라이스에서 원본 대비 재보정 Brier를 채점합니다.
  • [B] 사장 시그널 기여도 — 사장된 시그널 (valuation/cycle/mean_reversion) 사용 여부로 종료 행을 분리합니다.
  • [D] 레짐 윈도우 억제 — 리스크오프 윈도우 내에서 생성된 BULL 예측 결과(하드 레짐 게이트가 억제했을 내용)입니다.
첫 실행 결과 (실제 DB, n=420 종료)
변경 사항 지표 이전 이후
A (recal, OOS) ALL Brier 0.340 0.204
A (recal, OOS) LIVE Brier 0.331 0.160
B with-dead-signal 승률 — 0.0% (n=15, Brier 0.424)
D BULL 6/1–6/7 승률 — 4.3% (n=140)

A와 D를 강력히 검증하고, B는 노이즈(낮은 볼륨)로 확인합니다.

어떻게

재구현 없이 프로덕션 보정 수학(build_recalibration_map, apply_recalibration, get_calibration_report, mcp-prediction-store/metrics.py)을 재사용합니다. 훈련 슬라이스는 인메모리 DB에 로드되어 버킷팅이 라이브와 동일합니다. 시간순 분할은 get_signal_decay(outcome_date, created_at, id)를 따릅니다.

리뷰 루프
  • 수정 — DB 읽기 전용 아님 (codex, 높음): models.get_connection을 _connect_readonly (file:...?mode=ro URI)로 교체. 읽기 전용 계약 준수.
  • 수정 — avg-return 100배 부풀림 (codex, 낮음): outcome_return은 퍼센트 포인트로 저장됨; :+.2% 형식이 100을 곱했음. :+.2f%로 변경. 기존의 "데이터 손상" 메모는 오류 — 표시 버그였음.
  • 수정 — 잘못된 oos_fraction / 소규모 n (codex + gemini): 유효성 검사 및 "데이터 부족" 가드 추가.
  • 수정 — 호라이즌별 재보정 (gemini + code-reviewer): eval_recalibration에 선택적 timeframe 및 --timeframe CLI 플래그 노출.
  • 수정 — 테스트 누락: 잘못된 분수, 빈 시그널 목록, 커스텀 사장 세트, build_report 스모크 테스트 추가 (9 → 15).
  • 기각 — 인메모리 스키마 "Critical" (code-reviewer): 세 리뷰어 모두 4컬럼 임시 테이블이 정확하다고 확인.
  • 기각 — 엄격한 시점 분할 (gemini/codex): 분할은 outcome_date 기준이므로 테스트 결과가 피팅 맵에 유입되지 않음. eval_recalibration에 문서화.
기존에 알려진 문제 (범위 외, 미수정)

scheduler/weekly_calibration.py:208,236이 avg_return을 :+.2%로 형식화 — 동일한 100배 부풀림 버그. 별도의 범위 한정 수정을 위해 유보.

회고
인메모리 DB를 통해 프로덕션 재보정 빌더를 재사용한 것은 하네스를 정직하게 유지했습니다 (라이브와 괴리될 수 있는 중복 보정 로직 없음). 세 리뷰어 루프는 충분한 가치를 발휘했습니다: codex가 읽기 전용 계약 위반과 데이터를 잘못 탓하게 만든 형식 버그를 잡아냈습니다. 앞으로 기억할 교훈: 데이터를 탓하기 전에 표시 경로를 먼저 검증하라.

재보정 및 사장 시그널 제거

왜
  • F1/F7 (과신 + 미사용 재보정 맵): 0.60–0.70 신뢰도 대역이 실제보다 +0.28 높았고, /expect가 운영자에게 재보정 맵을 수동으로 적용하도록 지시했음에도 기록된 신뢰도는 여전히 ~0.6으로 거의 고정이었습니다. 수동 LLM 단계는 신뢰할 수 없으며, 재보정은 결정론적이어야 합니다.
  • F2/F5 (사장 시그널): valuation, cycle, mean_reversion은 승률 0%를 기록하며 시그널별 보정만 오염시킵니다.
무엇을
  • A — predict create의 --recalibrate 플래그 (stock_cli.py). 저장 전 소스 범위 등조 곡선을 통해 원본 --confidence를 매핑하고, JSON에 raw_confidence / recalibration_applied를 출력. 해당 소스의 종료 예측이 MIN_CLOSED_FOR_RECAL = 30 미만이면 안전하게 무연산.
  • B — 사장 시그널 제거: /expect와 daily-briefing 스킬의 허용 --signals 목록에서 제거. 운영자는 해당 판독값을 LLM_CONTEXT_SCORE로 라우팅하도록 안내.
  • 기존 수정 (승인됨): weekly_calibration.py:208,236에서 avg_return을 :+.2%(×100 부풀림)로 형식화하던 버그. :+.2f%로 수정.
  • 테스트: tests/test_recalibration_cli.py(7개) — 최소 샘플 게이트, 과신 하향 조정, 소스 범위 지정.
어떻게

재보정은 build_recalibration_map / apply_recalibration(mcp-prediction-store/metrics.py)을 재사용합니다. 전체(모든 호라이즌) 맵이 사용됩니다 — 백필 결과 호라이즌별 맵만큼 정확하면서(Brier 0.160 vs 0.169) 현재 샘플 규모에서 더 강건합니다. 소스 범위: LIVE 예측은 LIVE 이력만 참조하고, 과적합된 INTERACTIVE 행은 참조하지 않습니다(F4 격차). 로깅 임계값은 여전히 원본 신뢰도로 게이팅하며, 저장되는 값만 재보정됩니다.

검증

백필 OOS Brier: LIVE 0.331 → 0.160, ALL 0.340 → 0.204(누수 방지 훈련/테스트 분할).

주의: 프로덕션 LIVE 곡선은 단일 앵커(0.612 → 0.248)를 가집니다. 원본 신뢰도가 거의 고정이기 때문에 재보정은 모든 신뢰도를 ~0.25 기본 비율로 수렴시킵니다. 이것이 Brier 개선의 원천이지만(기본 비율이 비정보적 0.6을 이김), 모델이 정보적인 신뢰도 스프레드를 내보낼 때까지 기록된 신뢰도가 선택을 순위 매기지 못하게 됩니다. 판별력 회복은 후속 작업(변경 E / 메타 레이블링)이며, 재보정의 역할이 아닙니다.

리뷰 루프
  • CRITICAL (3개 모두, 수정) — 재보정이 자체 훈련 데이터를 오염시킴. 재보정 값을 confidence에 다시 저장하면 미래 맵이 오염됩니다. 수정: nullable raw_confidence 컬럼 추가; 보정은 COALESCE(raw_confidence, confidence)로 훈련하여 재보정 값을 절대 참조하지 않음. 새 테스트 test_map_trains_on_raw_not_recalibrated가 저장-0.30 / 원본-0.65 행이 맵에 0.65를 기여함을 증명. 프로덕션 복사본(1169행 보존, 컬럼 추가, 레거시 맵 변경 없음)에서 마이그레이션 검증.
  • 수정 — 테스트 누락 (codex/code-reviewer): 게이트 후 빈 맵 무연산, 비오염 테스트, 엔드투엔드 cmd_predict_create --recalibrate 테스트 추가.
  • 인지됨 — 재실행 이중 적용: 호출자가 저장된 신뢰도를 --recalibrate로 수동 재제출하면 다시 맵이 적용됨. 정상 /expect 경로 외의 케이스이므로 문서화하고 게이팅하지 않음.

  • mcp-prediction-store/metrics.py — COALESCE(raw_confidence, confidence)로 훈련.
  • scheduler/weekly_calibration.py:208,236 — avg_return 형식 수정.

회고
재보정을 수동 LLM 지시에서 CLI 플래그로 전환한 것이 F7의 실질적 수정입니다 — 맵은 몇 주 동안 존재했지만 안정적으로 적용된 적이 없었습니다. 실제 라이브 맵을 검사한 것(단순히 백필 델타만이 아니라)이 재보정이 현재 기본 비율로 퇴화하고 있음을 발견했습니다. 나중에 신뢰도가 판별을 멈췄다는 것을 발견하는 것보다 지금 정직하게 기록하는 것이 낫습니다.

레짐 게이트

왜

F3: 2026년 6월 하락 구간 동안 /expect는 조정 국면에서도 BULL을 계속 발행했습니다(6/1–6/7 동안 140개 종료 BULL의 승률 4.3%). 결정론적 리스크오프 게이트가 없었고, 매크로 스킬은 LLM이 무시할 수 있는 권고적 호출에 불과했습니다.

무엇을
  • stock-cli regime --market US|KR — 인덱스 프록시 가격 구조 (MA50/MA200 대비 추세, 52주 고점 대비 하락, 1M 수익률, 20일 연환산 실현 변동성)에서 결정론적 RISK_ON / NEUTRAL / RISK_OFF 판정. 미국은 SPY+QQQ 중 더 나쁜 값을 집계하고, 한국은 KODEX 200(069500)을 사용합니다.
  • /expect(RULE R1) 및 daily-briefing(RULE R1)에 하드 게이트 연결: RISK_OFF → 새 BULL 억제(WATCH 상한, 호라이즌 → NEUTRAL); NEUTRAL → BUY 기준선 8.0→9.0 상향, 신뢰도 축소(0.60 상한); RISK_ON → 변경 없음.
  • tests/test_regime.py — 16개 테스트.
어떻게

mcp-market-data/regime.py의 순수 네트워크 없는 로직 (compute_realized_vol, compute_regime, aggregate_regime); CLI는 기존 프로바이더 + compute_horizon_metrics를 통해 인덱스 바를 공급합니다. aggregate_regime은 dataclasses.replace로 복사본을 반환하며 (입력 변이 없음), 각 프록시의 점수를 proxy_scores에 기록합니다.

검증 (6월 윈도우 네트워크 재구성 — 정직한 결과)

각 예측 발행일 기준으로 레짐을 재구성하고 140개 종료 BULL을 분류:

발행 시 레짐 n 승률
발행 시 NEUTRAL 65 3.1%
발행 시 RISK_ON 75 5.3%

6/2 클러스터(72개 콜)는 인덱스만으로는 차단 불가 — QQQ조차 RISK_ON이었고, 하락은 이후에 발생했습니다. SPY는 해당 윈도우 내내 RISK_ON을 벗어나지 않았고, QQQ는 6/7에서야 NEUTRAL로 전환. 한국은 포물선형 변동성(1M +40%, vol 56%)으로 일찍 NEUTRAL을 표시.

결론 (과장 없음): 레짐 게이트는 윈도우 패자의 ~46%(NEUTRAL)를 제거하고 진행 중인 조정에서 추가 매수를 막습니다. 그러나 6/2 고점에서 광범위 인덱스는 안정적이었습니다. 보완 레버 — 종목별 과확장 — 는 계획된 후속 단계이며, 재보정(A)이 이미 6/2 클러스터를 그토록 큰 피해로 만든 과신을 해소합니다.

리뷰 루프
  • 수정 (3개 모두) — aggregate_regime이 입력 판정을 변이시킴. 이제 dataclasses.replace가 복사본을 반환; 테스트가 입력 불변을 확인.
  • 수정 (codex 높음) — cmd_regime이 실패한 프록시를 조용히 삭제함(QQQ를 잃으면 성장주 주도 하락에 미국 게이트가 맹목적이 됨). 누락된 프록시는 이제 판정 노트에 표시.
  • 수정 (codex+gemini) — 불충분한 이력이 RISK_ON으로 기본값 설정됨. 이제 NEUTRAL로 하한 적용 + 노트.
  • 수정 — argparser 도움말: 이제 "worst-of SPY+QQQ"로 표시.
  • 수정 — 테스트 누락: 정확한 실현 변동성 값, MA 우선순위, 불충분한 이력, 비변이, 동점→첫 번째, 단일 프록시.
  • 기각 — 임계값 진동/이력 현상 (gemini): 임계값 근방의 일일 진동에는 영속 상태가 필요하나 게이트는 브리핑당 한 번만 조회됨. 알려진 한계로 문서화.
코드 위치
  • mcp-market-data/regime.py — 판정, 점수, 집계.
  • stock_cli.py — cmd_regime, _regime_for_proxy, REGIME_INDEX, regime 파서.
  • .claude/skills/expect/SKILL.md(RULE R1, Step 1 fetch); .claude/skills/daily-briefing/SKILL.md(RULE R1, Section 1 fetch).
  • tests/test_regime.py.
회고
검증이 첫 직감("레짐 게이트가 손실을 막을 수 있었을 것")을 반박했습니다. 데이터가 정직하고 더 좁은 주장을 강제하고 실질적인 다음 레버(종목별 과확장)를 표면화했습니다. 연결 전에 백필한 것이 결실을 맺었습니다.

과확장 게이트

왜

D단계 검증은 광범위 인덱스 레짐 게이트가 6/2 클러스터를 잡을 수 없음을 증명했습니다: 해당 패자들(ORCL, NET, SMCI, DDOG, 한국 반도체)은 인덱스가 안정적인 동안 반전한 포물선 개별 종목이었습니다. 종목별 과확장 게이트가 빠진 레버입니다.

무엇을
  • RSI14와 MA20 대비 가격 거리로 classify_overextension(rsi14, price, ma20)가 계산하는 새 overextension_level(NONE / ELEVATED / EXTREME)을 HorizonMetrics에 추가. horizon-metrics[-batch]에서 자동 표시.
  • /expect + daily-briefing의 RULE R2: EXTREME → 새 BULL 억제(WATCH 상한); ELEVATED → BUY 기준선 +1.0 상향, 신뢰도 축소(0.60 상한).
  • R1+R2 스태킹 명시화: 어느 쪽에서든 WATCH 상한이 우선; BUY 기준선 상향은 누적 (NEUTRAL 레짐 + ELEVATED 종목 → COMPOSITE >= 10.0).
  • mcp-market-data/tests/test_indicators.py에 테스트 추가; CLI 계약 테스트가 새 필드를 고정.
어떻게

각 예측의 진입 시점 지표를 재구성하여(각 티커의 이력을 created_at까지 잘라내어) 377개 종료 BULL로 임계값을 보정: EXTREME = RSI14 > 75 또는 가격이 MA20 대비 >15%; ELEVATED = RSI14 > 70 또는 >8%. 순수 네트워크 없는 분류기.

검증 (진입 시점 재구성, 377개 종료 BULL)
진입 시 overextension_level n 승률
NONE 99 53.5%
ELEVATED 79 41.8%
EXTREME 199 29.1%

EXTREME 억제 시 유지된 BULL 승률 48.3%(n=178) vs 전체 38.2% — +10pp로 상승하며, 명확한 단조 기울기. RSI만으로: RSI>75는 26.4%(n=125), RSI<60은 47.5%. MA20 거리로: >15%는 29.6%(n=196), 3–8% 구간은 66%.

리뷰 루프
  • 세 리뷰어 모두 코드 정확성 확인 (심각도 순서, ma20<=0/None 가드, RSI-None 기본값, 포인트 테이블과 중복 없음, 기본값 설정된 데이터클래스 필드 하위 호환성).
  • 수정 (codex 중간) — R1+R2 스태킹 모호성: 기준선 상향을 누적으로, WATCH 상한을 "어느 쪽이든 우선"으로 문서화.
  • 수정 (양쪽 낮음) — 오래된 스키마 목록 / 미고정 필드: /expect 필드 목록과 CLI 계약 테스트의 expected_fields에 overextension_level 추가.
  • 수정 — 경계 테스트: 엄격한 RSI 경계 및 MA20 밴드 테스트 추가 (부동소수점 불안정 정확 퍼센트 엣지 이후 하나의 테스트가 불안정하여 회피).
  • 주목 — ELEVATED는 의도적으로 완만: RSI 70–75는 여전히 +0.5 모멘텀과 고점 근접 사이클 +1.0을 획득하여 R2의 +1.0 기준선을 부분 상쇄. 정당화: ELEVATED 41.8%(손익분기점 근접)이므로 소프트 게이트가 적절하고, EXTREME(29%)이 하드 억제.
코드 위치
  • mcp-market-data/indicators.py — classify_overextension, OVEREXT_* 상수, HorizonMetrics.overextension_level, compute_horizon_metrics에서의 연결.
  • .claude/skills/expect/SKILL.md(RULE R2 + 필드 목록); .claude/skills/daily-briefing/SKILL.md(RULE R2).
  • mcp-market-data/tests/test_indicators.py, tests/test_cli_integration.py.
회고
이것이 D 검증이 예측한 보완 레버입니다: R1(시장) + R2(종목)가 함께 레짐-맹목 클러스터와 포물선 개별 종목 모두를 처리합니다. 저장된 created_at에서 진입 시점 지표를 재구성한 것이 "패자들이 과확장되었다"는 직감을 보정된 단조 임계값으로 전환했습니다.

뉴스 기능

왜

news 시그널이 "사장"(~33% 승률)으로 평가되었습니다. 근본 원인: 점수가 원시 헤드라인 볼륨과 평균 감성에 집중 — 재게시물이 볼륨을 부풀리고 오래된 소프트 언급이 강한 촉매제와 동일하게 가중되었습니다. 최신 뉴스 필라에는 볼륨이 아닌 정보가 필요했습니다.

무엇을
  • mcp-market-data/news_features.py — 순수 기능 추출기로 NewsSignal 생성: 중복 제거된 unique_count, 최신성 가중 감성(3일 반감기 지수 감쇠), 촉매 event_tags (earnings/guidance/ma/analyst/regulatory_legal/product/leadership/capital), has_positive_catalyst / has_negative_catalyst 플래그.
  • news CLI 명령이 이제 items 외에 signal 블록을 출력합니다.
  • 두 스킬 모두 signal에서 NEWS_SCORE를 채점하고 (최신성 가중 감성, 중복 제거 볼륨, 부정 촉매 하드 상한) event_tags를 LLM_CONTEXT 토론에 공급합니다.
  • tests/test_news_features.py — 16개 테스트.
어떻게
  • 최신성 가중: w = 0.5 ** (age_days / 3) — 일주일 된 항목은 최신 항목의 ~20%로 계산; 미래 날짜는 age 0으로 클램프; 파싱 불가 날짜는 단위 가중치로 폴백.
  • 중복 제거: 최소 5단어 접두사 포함 방식으로 와이어 재게시물 ("…, shares jump")은 합쳐지지만 짧은 일반 스텁은 별개 기사를 삼키지 않음.
  • 매칭: ASCII 키워드는 단어 경계로 매칭 (\bmiss\b — "mission"/"twins"/"heartbeat" 방지); 한국어 키워드는 부분 문자열로 매칭하여 KR 네이버 헤드라인에서도 이벤트 태그와 촉매 플래그가 도출됨 (감자/유상증자/실적/소송 …).
검증

구조적/품질 개선 — 예측별 역사적 헤드라인이 저장되지 않으므로 백필 승률 검증은 불가능(명확히 명시). 정당화는 정보 품질: 중복 제거로 이중 집계 제거, 최신성 가중으로 오래된 뉴스 약화, 촉매 태깅으로 물질적 이벤트와 노이즈 분리. 라이브 확인: 미국 AAPL은 채워진 감성 시그널을 반환했고, 한국 005930은 8→7 헤드라인으로 중복 제거.

리뷰 루프
  • 수정 (양쪽, 높음) — 부분 문자열 촉매 거짓 양성: "miss"/"halt"/"wins"/"beat"가 "mission"/"health"/"twins"/"heartbeat"에서 -2 하드 상한을 발동할 수 있었음. 이제 ASCII 키워드는 단어 경계 정규식 사용; 테스트가 거짓 발동 없음을 확인.
  • 수정 (codex, 높음) — 스킬 간 편차: /expect에만 존재하던 미검증 "+1.0 hard catalyst" 행 제거; NEWS_SCORE가 이제 두 스킬에서 동일.
  • 수정 (양쪽, 중간) — 중복 제거 과합병: 최소 5단어 접두사 가드 추가; 테스트가 "Nvidia shares rise"가 더 긴 별개 헤드라인을 삼키지 않음을 확인.
  • 수정 (양쪽, 중간) — 한국어 공백: 모든 이벤트 카테고리와 촉매 목록에 한국어 키워드 추가, Hangul에 부분 문자열 매칭.
  • 수정 — 테스트 누락: 단어 경계, 한국어, 짧은 접두사, 미래 날짜 클램프, 두 항목 잘못된 날짜, 오래된 헤드라인 감쇠.
  • 주목 — 최신성 반감기 하드코딩(3일): 향후 튜닝을 위해 모듈 상수 RECENCY_HALF_LIFE_DAYS로 노출.
코드 위치

  • stock_cli.py — cmd_news signal 블록.
  • .claude/skills/expect/SKILL.md(Step 6); .claude/skills/daily-briefing/SKILL.md(NEWS_SCORE).
  • tests/test_news_features.py.
회고
사장된 뉴스 시그널은 데이터 문제만큼이나 점수화 문제였습니다: 중복 제거 + 최신성 + 촉매 구조가 기존 볼륨/평균 점수화가 버린 정보입니다. 검증에 대한 솔직함: 백필이 불가능하므로 향후 확인할 품질 개선으로 출시 — 측정된 승리인 척하지 않음.

컴포넌트 영속성

왜

재보정(A)이 기록된 신뢰도가 판별력이 없음을 드러냈습니다 — 시스템이 선택을 점수화한 이유를 기록하지 않기 때문에 기본 비율로 수렴합니다. 세 가지 역량(알고리즘/뉴스/LLM)을 조화시키고 언젠가 정보적인 블렌딩 신뢰도를 발행하려면, 각 필라의 기여도가 예측별로 캡처되어야 합니다. 기록하지 않은 데이터에서 블렌딩을 학습할 수는 없습니다.

무엇을
  • predictions에 nullable components JSON 컬럼 추가 (누적 마이그레이션, raw_confidence와 동일한 패턴). 예: {"algo":7.0,"news":1.0,"llm_context":-1.5,"overextension":"NONE","regime":"RISK_ON"}.
  • Prediction.components: Optional[dict]; 삽입 시 직렬화, 읽기 시 파싱.
  • predict create --components '<json>' (malformed/non-object/NaN 거부).
  • metrics.get_component_contribution + stock-cli component-contribution: 필라별 승률 분할 (숫자 → 양수/영/음수; 범주형 → 값별). 컴포넌트 태그된 행이 누적될 때까지 비어 있음.
  • 두 스킬 모두 이제 모든 기록된 예측에 --components를 출력.
  • tests/test_components.py — 14개 테스트 + 3개 CLI 유효성 검사 테스트.
어떻게

components는 여러 타입 컬럼 대신 하나의 확장 가능한 JSON 컬럼 — 마이그레이션이 저렴하고 새 필라에 열려 있습니다. 기여도 읽기는 "양수 뉴스/llm 기여도가 실제로 히트율을 높이는가?"에 답합니다 — 신뢰도 판별력을 복원할 수 있는 학습 기반 블렌딩 (E2-미래)의 측정 기반.

검증

선행 인프라: 현재 프로덕션에는 컴포넌트 태그된 종료 행이 0개이므로 /expect + daily-briefing이 새 예측을 기록할 때까지 component-contribution이 비어 있습니다. 기여도 수학은 시드된 데이터로 단위 테스트됨(양수 뉴스 0.8 승 vs 음수 0.2). 백필 주장 없음.

리뷰 루프
  • 수정 (모두, 높음) — 풀스왑 마이그레이션 데이터 손실: _migrate_schema_if_needed가 raw_confidence/ components를 누락한 하드코딩 컬럼 목록을 복사했음. 이제 기존 컬럼과 신규 컬럼의 교집합을 복사. 회귀 테스트 추가(두 컬럼 포함 + analysis_group_id 없는 레거시 DB → 값 보존).
  • 수정 (codex, 중간) — NaN/Infinity이 json.loads에서 허용됨; 이제 parse_constant로 거부.
  • 수정 (code-reviewer, 중간) — 영 vs 음수 혼동; 숫자 필라가 이제 양수/영/음수로 분할.
  • 수정 (codex, 낮음) — n_with_components가 잘못된 행을 집계했음; 이제 성공적으로 파싱된 dict 행만 집계.
  • 수정 — cmd_component_contribution의 오류 처리; malformed/non-object/NaN 컴포넌트에 대한 CLI 유효성 검사 테스트.
  • 주목 — CHECK(json_valid(...)) 제안 거부: SQLite 버전 의존적이고 CLI가 이미 검증하므로 불필요한 취약성 추가.
코드 위치
  • mcp-prediction-store/models.py — components 컬럼, _ensure_components_column, _migrate_schema_if_needed의 교집합 복사, 데이터클래스/삽입/읽기.
  • mcp-prediction-store/metrics.py — get_component_contribution.
  • stock_cli.py — --components 플래그 + 유효성 검사, cmd_component_contribution.
  • .claude/skills/expect/SKILL.md, .claude/skills/daily-briefing/SKILL.md.
  • tests/test_components.py, tests/test_recalibration_cli.py.
회고
리뷰가 변경 사항이 직접 수정하지는 않았지만 폭발 반경을 확대시킨 마이그레이션 경로의 잠재적 데이터 손실 버그를 잡아냈습니다 — 컬럼이 추가될 때마다 풀스왑 복사를 감사해야 한다는 교훈. 이 단계는 의도적으로 승률 변화를 제공하지 않습니다; 다음 조화 단계(학습 기반 블렌딩)를 가능하고 정직하게 만드는 데이터 토대입니다.

LLM Context Rigor

왜

LLM_CONTEXT(매크로/섹터/내러티브 채널)는 약한 성적(~19% 승률)을 보이며, LLM이 판단하기 때문에 강화하기 가장 어려운 필라입니다. 코드에서 판단을 더 좋게 만들 수는 없지만, 엉성한 판단 — 인용 근거 없는 강한 점수, 일방적인 토론, 범위를 벗어난 값 — 은 신뢰하기를 거부할 수 있습니다.

무엇을
  • mcp-market-data/llm_context.py — validate_llm_context(debate)가 엄밀성 위반을 반환; clamp_score; score_from_debate.
  • stock-cli lint-llm-context '<json>'(위반 시 exit 1)으로 /expect가 점수를 신뢰하기 전 자체 게이팅 가능.
  • Step 5b는 이제 bull/bear 토론을 JSON으로 구조화하고 린트; 비클린 린트는 점수를 0 방향으로 약화시킴을 의미.
  • tests/test_llm_context.py — 14개 테스트.
어떻게 — 게이트가 강제하는 것
  • score ∈ [-5, +3], 유한값(NaN/Infinity 거부).
  • winner가 점수의 부호와 일치(0 ⇒ neutral).
  • 진정한 bear 케이스: 실제(비공백 문자열) 주장이 있는 bear_point 최소 1개.
  • |score| >= 2.0일 때, 우세한 쪽이 비공백 문자열 근거와 signal_type ∈ {macro, sector, event, flow, valuation, technical, narrative}를 가진 포인트 최소 1개.
정직한 범위

이것은 토론의 형식과 규율을 강제하며, 사실을 강제하지 않습니다. LLM은 여전히 피상적이지만 형식에 맞는 근거를 제출할 수 있습니다. 이것이 올바른 역할 분담입니다: 린터가 구조적 엉성함을 결정론적으로 차단하고, 인간/2차 검토가 내용을 판단합니다. 중요하게도, llm_context의 점수가 이제 H1의 --components를 통해 저장되므로 component-contribution이 이 필라가 실제로 알파를 추가하는지 향후 측정합니다 — "LLM 채널이 노이즈인가?"를 추측 대신 측정된 질문으로 전환.

리뷰 루프

두 리뷰어 모두 첫 번째 버전을 "의식, 엄밀성 아님"으로 평가하고 구체적인 우회 경로를 발견했습니다 — 모두 수정:

  • 가짜 bear 케이스(bear_points: [{}] / [""])가 통과 → 이제 실제 문자열 주장이 있는 bear 포인트 필요.
  • 비문자열 근거(evidence: {})가 truthy로 문자열화되어 인용으로 집계 → 이제 비공백 문자열 근거만 자격.
  • NaN 점수가 최대 강세 3.0으로 클램프 → clamp_score가 비유한값에 대해 None을 반환하고 validate가 플래그.
  • score==0 우세 쪽 잠재 버그 → 명시적 None (0에서 근거 규칙 없음).
  • 모든 닫힌 우회 경로 + score==0 경계에 대한 테스트 추가.

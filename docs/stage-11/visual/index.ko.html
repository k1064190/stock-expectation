11단계

예측 정확도 개선 이니셔티브: 백필 A/B 평가 게이트, 결정론적 등위회귀 재보정, 무효 신호 제거, 강제 시장 레짐 게이트, 종목별 과확장 게이트, 구조화된 뉴스 피처, 그리고 예측 기둥(pillar)별 컴포넌트 영속성 저장.

백필 하네스 (Backfill Harness)

왜

예측 적중률이 73% (2026-05-11)에서 24% (2026-06-14)로 붕괴되었습니다. 승인된 계획은 여섯 가지 정확도 개선 사항(A–F)을 제시합니다. 각 변경은 라이브 /expect 플로우에 적용되기 전에 반드시 과거 데이터로 검증되어야 합니다 — 그렇지 않으면 LIVE-vs-INTERACTIVE 낙관 편향(F4)을 반복할 위험이 있습니다. 이 하네스가 그 게이트입니다.

무엇을

scheduler/backfill_eval.py — 종료(HIT/MISS) 예측에 대한 읽기 전용 A/B 도구 및 tests/test_backfill_eval.py (9개 테스트, 전부 통과).

보고하는 섹션:

  • [A] 등위회귀 재보정 — 누출 방지: 이전 학습 슬라이스에 재보정 맵을 적합하고, 보류된 최근 테스트 슬라이스에서 원시 대비 재보정 Brier 점수를 산출합니다.
  • [B] 무효 신호 기여도 — 무효 신호 (valuation/cycle/mean_reversion) 사용 여부에 따라 종료된 행을 분리합니다.
  • [D] 레짐 구간 억제 — 리스크 오프(risk-off) 구간 내에서 생성된 BULL 예측의 결과 (강제 레짐 게이트가 억제했을 항목).
첫 실행 결과 (실제 DB, n=420 종료)
변경 지표 이전 이후
A (recal, OOS) ALL Brier 0.340 0.204
A (recal, OOS) LIVE Brier 0.331 0.160
B 무효 신호 포함 적중률 — 0.0% (n=15, Brier 0.424)
D BULL 6/1–6/7 적중률 — 4.3% (n=140)

A와 D를 강하게 검증하며, B는 표본 수 부족(소음)으로 확인됩니다.

어떻게

mcp-prediction-store/metrics.py의 프로덕션 보정 수학 (build_recalibration_map, apply_recalibration, get_calibration_report)을 재구현 없이 재사용합니다. 학습 슬라이스를 인메모리 DB에 로드하여 버킷팅이 라이브와 동일하게 유지됩니다. 시간 순서 분할은 get_signal_decay (outcome_date, created_at, id)를 반영합니다.

코드 위치
  • scheduler/backfill_eval.py — 하네스 (_connect_readonly, load_closed, _metrics, eval_recalibration, eval_dead_signals, eval_regime_window, build_report).
  • tests/test_backfill_eval.py — 유닛 테스트 15개.
리뷰 루프
수정 DB가 읽기 전용이 아님 (codex, High): 하네스가 마이그레이션/인덱싱/WAL/ 자가복구(쓰기)를 수행하는 models.get_connection을 사용했습니다. _connect_readonly (file:...?mode=ro URI)로 교체하여 읽기 전용 계약을 준수합니다.
수정 avg-return 100배 부풀림 (codex, Low): :+.2% 포맷 지정자가 100을 곱했습니다(-865% 표시). 이제 :+.2f%로 수정. 이전 "데이터 손상" 메모는 틀렸습니다 — 데이터는 정상이었고 표시 버그였습니다.
수정 잘못된 oos_fraction / 작은 n (codex + gemini): 0 < oos_fraction < 1 유효성 검사와 "데이터 부족" 가드를 추가했습니다.
수정 수평별 재보정 (gemini + code-reviewer): eval_recalibration/ build_report에 선택적 timeframe과 --timeframe CLI 플래그를 노출했습니다 (1W 전역 Brier 0.331→0.169 vs 전체 수평 0.331→0.160).
수정 테스트 공백: 잘못된 분수, 빈 신호 목록, 커스텀 무효 집합, build_report 스모크 테스트 추가 (9→15개).
기각 인메모리 스키마 "Critical" (code-reviewer): 세 리뷰어 모두 get_calibration_report가 4개 컬럼만 읽음을 확인; 4-컬럼 임시 테이블이 정확합니다.
기각 엄격한 시점(point-in-time) 분할 (gemini/codex): 분할이 outcome_date 기준이라 테스트 결과가 적합 맵에 들어가지 않습니다. 재구조화 대신 eval_recalibration에 문서화했습니다.
기존에 알려진 이슈 (수정 범위 외)

scheduler/weekly_calibration.py:208,236이 avg_return을 :+.2% (동일한 100배 부풀림 버그)으로 포맷합니다 — 프로덕션 주간 보고서의 평균 수익률이 과장됩니다. 별도의 범위 한정 수정으로 남겨 두었습니다.

회고

인메모리 DB를 통해 프로덕션 재보정 빌더를 재사용한 것이 하네스를 신뢰할 수 있게 만들었습니다(라이브에서 벗어날 수 있는 중복 보정 로직 없음). 세 리뷰어 루프가 충분히 역할을 했습니다: codex가 읽기 전용 계약 위반과 데이터를 잘못 비난하게 만든 포맷 버그를 발견했습니다. 앞으로 가져갈 교훈: 데이터를 비난하기 전에 표시 경로를 검증할 것.

재보정 및 무효 신호 제거

왜
  • F1/F7 (과신 + 미사용 재보정 맵): 0.60–0.70 신뢰도 구간이 실제보다 +0.28 높았고, /expect가 운영자에게 재보정 맵을 수동 적용하도록 안내했음에도 기록된 신뢰도는 여전히 ~0.6에 고정되어 있었습니다. 수동 LLM 단계는 신뢰할 수 없으며, 재보정은 결정론적이어야 합니다.
  • F2/F5 (무효 신호): valuation, cycle, mean_reversion이 0% 적중률을 기록하며 신호별 보정을 오염시킵니다.
무엇을
  • A — predict create의 --recalibrate 플래그: 저장 전에 원시 --confidence를 소스 범위 등위회귀 곡선으로 매핑합니다; JSON에 raw_confidence / recalibration_applied를 반환합니다. 해당 소스의 종료 예측이 MIN_CLOSED_FOR_RECAL = 30 미만이면 안전하게 무시됩니다.
  • B — 무효 신호 제거: /expect와 daily-briefing 스킬 모두에서 허용 --signals 목록에서 제거; 해당 판단은 LLM_CONTEXT_SCORE를 통해 처리하도록 안내합니다.
  • 기존 버그 수정 (승인됨): weekly_calibration.py:208,236의 :+.2% (100배 부풀림)을 :+.2f%로 수정.
  • 테스트: tests/test_recalibration_cli.py (3개) — 최소 표본 게이트, 과신 인하, 소스 범위 지정.
어떻게

재보정은 build_recalibration_map/apply_recalibration (mcp-prediction-store/metrics.py)을 재사용합니다. 전역 (전체 수평) 맵을 사용합니다 — 백필에서 수평별 맵과 동일한 정확도 (Brier 0.160 vs 0.169)를 보이면서 현재 표본 수에서 더 견고했습니다. 소스 범위 지정: LIVE 예측은 LIVE 이력에 대해서만 보정되며, 과적합된 INTERACTIVE 행을 사용하지 않습니다(F4 격차). 로깅 임계값은 여전히 원시 신뢰도에 대해 게이트하며, 저장되는 값만 재보정됩니다.

검증

백필 OOS Brier: LIVE 0.331 → 0.160, ALL 0.340 → 0.204 (누출 방지 학습/테스트 분할).

라이브 맵 점검에서 드러난 주의 사항: 프로덕션 LIVE 곡선은 원시 신뢰도가 거의 일정하기 때문에 단일 앵커(0.612 → 0.248)만 갖습니다. 재보정이 현재 모든 신뢰도를 ~0.25 기저 비율로 수렴시킵니다. 이것이 Brier 개선의 원천(비정보적 0.6보다 기저 비율이 우수)이지만, 모델이 정보성 있는 신뢰도 분포를 생성하기 전까지 기록된 신뢰도가 종목 순위 결정을 멈춥니다. 판별력 회복은 하위 작업(변경 E / meta-labeling)이며 재보정의 역할이 아닙니다.

리뷰 루프
수정 — Critical (전원) 재보정이 자체 학습 데이터를 오염시켰습니다. 재보정 값을 confidence에 다시 저장하면 build_recalibration_map/ get_calibration_report가 confidence를 원시 예측변수로 읽기 때문에 미래 맵이 오염됩니다(재귀적 피드백). 수정: nullable raw_confidence 컬럼 추가 (additive _ensure_raw_confidence_column 마이그레이션 + dataclass/insert/reader); 보정은 COALESCE(raw_confidence, confidence)로 학습합니다. 새 테스트 test_map_trains_on_raw_not_recalibrated가 raw 기여를 증명합니다. 프로덕션 복사본 검증 완료 (1169행 보존, 컬럼 추가, 기존 맵 유지).
수정 테스트 공백 (codex/code-reviewer): 빈 맵 후 게이트 무조작 테스트, 무오염 테스트, 엔드-투-엔드 cmd_predict_create --recalibrate 테스트 추가.
인정 재생 이중 적용: 호출자가 저장된(이미 보정된) 신뢰도를 --recalibrate와 함께 다시 제출하면 다시 매핑될 수 있습니다. 정상 /expect 경로 밖의 케이스이므로 문서화하고 게이트하지 않았습니다.

회고

재보정을 수동 LLM 지시에서 CLI 플래그로 옮긴 것이 F7의 실질적 수정입니다 — 맵은 수 주 동안 존재했지만 안정적으로 적용된 적이 없었습니다. 실제 라이브 맵을 점검한 것(백필 델타만이 아닌)이 재보정이 현재 기저 비율로 퇴화한다는 사실을 파악하게 했습니다. 신뢰도가 판별력을 잃었다는 것을 나중에 발견하는 것보다 지금 솔직하게 기록하는 것이 낫습니다.

레짐 게이트 (Regime Gate)

왜

F3: 2026년 6월 하락 국면에서 /expect가 조정을 관통하며 계속 BULL을 발행했습니다 (6/1–6/7 종료된 BULL 140개의 적중률 4.3%). 결정론적 리스크 오프 게이트가 없었으며, 매크로 스킬은 LLM이 무시할 수 있는 권고 사항이었습니다.

무엇을
  • stock-cli regime --market US|KR — 인덱스 프록시 가격 구조 (MA50/MA200 대비 추세, 52주 최고가 대비 하락률, 1개월 수익률, 연율화된 20일 실현 변동성)에서 결정론적 RISK_ON / NEUTRAL / RISK_OFF 판정을 내립니다. 미국은 SPY + QQQ 중 나쁜 쪽을 집계하고, 한국은 KODEX 200 (069500)을 사용합니다.
  • /expect (RULE R1)와 daily-briefing (RULE R1)에 강제 게이트 적용: RISK_OFF는 새 BULL을 억제하고(WATCH 상한, 수평 → NEUTRAL); NEUTRAL은 BUY 기준을 8.0→9.0으로 올리고 신뢰도를 제한(0.60 상한); RISK_ON은 변경 없음.
  • tests/test_regime.py (16개 테스트).
어떻게

mcp-market-data/regime.py의 순수 네트워크-무관 로직 (compute_realized_vol, compute_regime, aggregate_regime); CLI는 기존 프로바이더 + compute_horizon_metrics를 통해 인덱스 바를 제공합니다. aggregate_regime은 dataclasses.replace로 입력 변환 없이 복사본을 반환하며, proxy_scores에 모든 프록시 점수를 기록합니다.

검증

각 예측의 발행 날짜 기준으로 레짐을 재구성하고 140개 종료 BULL을 버킷팅:

  • 발행 시 NEUTRAL: n=65, 적중률 3.1% — 게이트가 이를 억제/강화합니다.
  • 발행 시 RISK_ON: n=75, 적중률 5.3% — 발행 시 인덱스가 안정적이었음; 게이트가 이를 포착할 수 없습니다.
  • 6/2 클러스터(72개 콜)는 인덱스만으로는 게이트할 수 없었습니다 — 심지어 QQQ도 RISK_ON이었고 하락은 이후에 왔습니다. SPY는 전체 구간 동안 RISK_ON을 유지했으며; QQQ는 6/7에 NEUTRAL로 전환됐고; 한국은 포물선 변동성(1개월 +40%, 변동성 56%)을 통해 일찍 NEUTRAL을 표시했습니다.

결론 (과장 없음): 레짐 게이트는 부분적 완화책입니다 — 구간 패배자의 ~46% (NEUTRAL 항목)를 제거하고 진행 중인 조정에서 매수를 멈추지만, 6/2 고점에서 광역 인덱스는 안정적이었습니다.

리뷰 루프
수정 (전원) aggregate_regime이 입력 판정을 변환했습니다. 이제 dataclasses.replace가 복사본을 반환하며, 테스트가 입력 불변을 검증합니다.
수정 (codex High) cmd_regime이 실패한 프록시를 자동으로 삭제했습니다 (QQQ를 잃으면 미국 게이트가 성장 주도 하락을 포착하지 못함). 누락된 프록시는 이제 판정 메모에 표시됩니다.
수정 (codex + gemini) 이력 부족 시 RISK_ON이 기본값이었습니다. MA200 없이는 추세를 알 수 없으므로 강제 게이트가 RISK_ON을 인증해서는 안 됩니다; 이제 메모와 함께 NEUTRAL로 하한 처리됩니다.
수정 argparser 도움말이 US 기본값을 SPY라고 했습니다; 이제 "SPY+QQQ 중 나쁜 쪽"으로 수정.
수정 테스트 공백: 정확한 실현 변동성 값, MA 우선순위, 이력 부족, 무변환, 동점-첫 번째, 단일 프록시.
기각 임계값 진동/히스테리시스 (gemini): 임계값 근처의 일별 진동은 영속 상태가 필요합니다; 게이트는 장중이 아닌 브리핑당 한 번 조회됩니다. 알려진 제한 사항으로 문서화됨.
코드 위치
  • mcp-market-data/regime.py — 판정, 점수, 집계.
  • stock_cli.py — cmd_regime, _regime_for_proxy, REGIME_INDEX, regime 파서.
  • .claude/skills/expect/SKILL.md (RULE R1, Step 1 fetch), .claude/skills/daily-briefing/SKILL.md (RULE R1, Section 1 fetch).
  • tests/test_regime.py.
회고

검증은 첫 번째 직관("레짐 게이트가 손실을 막았을 것이다")을 반박했습니다. 데이터가 솔직하고 좁은 주장을 강제하며 다음 실질적 레버(종목별 과확장)를 표면화시켰습니다. 연결 전에 백필부터 진행한 것이 효과를 발휘했습니다.

과확장 게이트 (Overextension Gate)

왜

D 단계 검증에서 광역 인덱스 레짐 게이트가 6/2 클러스터를 포착할 수 없음을 증명했습니다: 해당 패배 종목들(ORCL, NET, SMCI, DDOG, KR 반도체)은 인덱스가 안정적인 동안 반전한 포물선 개별 종목이었습니다. 종목별 과확장 게이트가 빠진 레버입니다.

무엇을
  • HorizonMetrics에 새로운 overextension_level (NONE / ELEVATED / EXTREME) 추가. RSI14와 MA20 대비 가격 거리로 classify_overextension(rsi14, price, ma20)에 의해 계산됩니다. horizon-metrics[-batch]에서 자동으로 표시됩니다.
  • /expect + daily-briefing의 RULE R2: EXTREME은 새 BULL을 억제하고(WATCH 상한); ELEVATED는 BUY 기준을 +1.0 올리고 신뢰도를 제한(0.60 상한).
  • R1+R2 스태킹을 명시화: 둘 중 하나의 WATCH 상한이 우선됩니다; BUY 기준 인상은 누적됩니다 (NEUTRAL 레짐 + ELEVATED 종목 = COMPOSITE ≥ 10.0).
  • mcp-market-data/tests/test_indicators.py에 테스트 추가; CLI 계약 테스트가 새 필드를 고정합니다.
어떻게

377개 종료 BULL에 대해 각 예측의 진입 시점 메트릭을 재구성하여(티커 이력을 created_at까지 잘라냄) 임계값을 보정했습니다: EXTREME = RSI14 > 75 또는 가격이 MA20보다 15% 초과; ELEVATED = RSI14 > 70 또는 8% 초과. 순수 네트워크-무관 분류기입니다.

검증 (진입 시점 재구성, 377개 종료 BULL)
진입 시 overextension_level n 적중률
NONE 99 53.5%
ELEVATED 79 41.8%
EXTREME 199 29.1%

EXTREME 억제 시 유지된 BULL 적중률이 48.3% (n=178) vs 전체 38.2% — +10pp로 향상되며, 깔끔한 단조 그래디언트를 보입니다. RSI만으로: RSI>75는 26.4% (n=125) 적중 vs RSI<60에서 47.5%. MA20 거리: >15%는 29.6% (n=196) 적중 vs 3–8% 구간에서 66%.

리뷰 루프
검증 완료 (전원) 코드 정확성 확인: 심각도 순서, ma20 ≤ 0/None 가드, RSI-None 기본값, 점수 테이블과의 이중 계산 없음, 역방향 호환 dataclass 필드.
수정 (codex Medium) R1+R2 스태킹 모호성: 기준 인상이 누적됨을 문서화하고 WATCH 상한을 "둘 중 하나가 이기면 됨"으로 명시했습니다.
수정 (둘 다 Low) 오래된 스키마 목록 / 고정되지 않은 필드: overextension_level을 /expect 필드 목록과 CLI 계약 테스트의 expected_fields에 추가했습니다.
수정 경계 테스트: 엄격한 RSI 경계 테스트와 MA20 구간 테스트 추가 (부동소수점 취약 정밀 백분율 엣지는 한 번 오류 후 회피했습니다).
참고 (둘 다) ELEVATED는 의도적으로 완만합니다: RSI 70–75는 여전히 +0.5 모멘텀과 근-최고가 사이클 +1.0을 얻어 R2의 +1.0 기준 인상을 부분 상쇄합니다. 정당성: ELEVATED는 41.8% (손익 분기점 근처)를 기록했으므로 소프트 게이트가 적절하며; EXTREME (29%)은 강제 억제를 받습니다.
코드 위치
  • mcp-market-data/indicators.py — classify_overextension, OVEREXT_* 상수, HorizonMetrics.overextension_level, compute_horizon_metrics 연결.
  • .claude/skills/expect/SKILL.md (RULE R2 + 필드 목록), .claude/skills/daily-briefing/SKILL.md (RULE R2).
  • mcp-market-data/tests/test_indicators.py, tests/test_cli_integration.py.
회고

이것은 D 검증이 예측한 보완책입니다: R1 (시장) + R2 (종목)이 함께 레짐 맹점 클러스터와 포물선 개별 종목 모두를 다룹니다. 저장된 created_at에서 진입 시점 메트릭을 재구성한 것이 직관("패배자들이 과확장되어 있었다")을 보정된 단조 임계값으로 바꿔 주었습니다.

뉴스 피처 (News Features)

왜

news 신호가 "무효"로 평가받았습니다(~33% 적중). 근본 원인: 채점이 헤드라인 총량과 평탄 감성 평균을 집계했습니다 — 재게시가 볼륨을 부풀리고 오래된 약한 신호가 강한 촉매와 동일한 가중치를 받았습니다. 최신 뉴스 기둥에는 볼륨이 아닌 정보가 필요했습니다.

무엇을
  • mcp-market-data/news_features.py: 순수 피처 추출기로 NewsSignal을 생성합니다 — 중복 제거된 unique_count, 최근성 가중 감성 (3일 반감기 지수 감쇠), 촉매 event_tags (earnings/guidance/ma/analyst/regulatory_legal/product/leadership/capital), 그리고 has_positive_catalyst / has_negative_catalyst 플래그.
  • news CLI 명령이 이제 items 옆에 signal 블록을 제공합니다.
  • 두 스킬 모두 signal에서 NEWS_SCORE를 채점하고(최근성 가중 감성, 중복 제거 볼륨, 부정 촉매 강제 상한) event_tags를 LLM_CONTEXT 토론에 제공합니다.
  • tests/test_news_features.py에 16개 테스트.
어떻게
  • 최근성 가중치: w = 0.5 ** (age_days / 3) — 1주일 된 항목은 최신 항목의 ~20% 반영; 미래 날짜는 나이 0으로 고정; 파싱 불가 날짜는 단위 가중치로 대체됩니다.
  • 중복 제거: 최소 5단어 접두사 포함 관계를 사용하여 와이어 재게시("…, shares jump")는 합쳐지지만 짧은 일반 스텁이 별개 기사를 흡수하지 않습니다.
  • 매칭: ASCII 키워드는 단어 경계에서 매칭합니다 (\bmiss\b — "mission"/"twins"/"heartbeat"가 아닌 경우); 한국어 키워드는 부분 문자열로 매칭하여 네이버 헤드라인(Alpha Vantage 감성 없음)에서도 이벤트 태그와 촉매 플래그를 생성합니다 (감자/유상증자/실적/소송 …).
검증

구조적/품질 개선 — 과거 예측별 헤드라인이 저장되어 있지 않아 백필 적중률 검증이 불가합니다(솔직히 명시). 정당성은 정보 품질입니다: 중복 제거가 이중 계산을 제거하고, 최근성 가중치가 오래된 뉴스를 경감시키며, 촉매 태깅이 중요 이벤트를 소음에서 분리합니다. 뉴스 신호의 적중률 향상 여부는 주간 보정을 통해 앞으로 측정됩니다. 라이브 확인: US AAPL이 채워진 감성 신호를 반환했습니다; KR 005930이 헤드라인을 8→7개로 중복 제거했습니다.

리뷰 루프
수정 (둘 다, High) 부분 문자열 촉매 오탐: "miss"/"halt"/"wins"/"beat"가 "mission"/"health"/ "twins"/"heartbeat"에서 -2 강제 상한을 발동할 수 있었습니다. 이제 ASCII 키워드는 단어 경계 정규식을 사용하며 목록은 명확한 구문을 선호합니다 ("earnings miss", "trading halt"). 테스트가 오탐 없음을 검증합니다.
수정 (codex, High) 스킬 드리프트: /expect에만 존재했던 검증되지 않은 "+1.0 hard catalyst" 행을 제거했습니다; NEWS_SCORE가 이제 두 스킬에서 동일합니다 (감성 + 볼륨 + 부정 상한; 태그는 LLM에만 공급).
수정 (둘 다, Medium) 중복 제거 과합산: 5단어 최소 접두사 가드 추가; 테스트가 "Nvidia shares rise"가 더 긴 별개 헤드라인을 흡수하지 않음을 증명합니다.
수정 (둘 다, Medium) 한국어 맹점: 모든 이벤트 카테고리와 촉매 목록에 한국어 키워드를 추가하고, 한글에 부분 문자열 매칭을 적용했습니다.
수정 테스트 공백: 단어 경계, 한국어, 짧은 접두사, 미래 날짜 고정, 2항목 잘못된 날짜, 오래된 헤드라인 감쇠.
참고 최근성 반감기가 하드코딩(3d)됨: RECENCY_HALF_LIFE_DAYS 모듈 상수로 노출하여 향후 튜닝 가능하게 했습니다.
코드 위치
  • mcp-market-data/news_features.py — NewsSignal, classify_event, dedup_headlines, _contains, summarize_news, RECENCY_HALF_LIFE_DAYS, DEDUP_MIN_PREFIX_WORDS.
  • stock_cli.py — cmd_news signal 블록.
  • .claude/skills/expect/SKILL.md (Step 6), .claude/skills/daily-briefing/SKILL.md (NEWS_SCORE).
  • tests/test_news_features.py.
회고

무효 뉴스 신호는 데이터 문제만큼이나 채점 문제였습니다: 중복 제거 + 최근성 + 촉매 구조가 기존 볼륨/평균 채점이 버렸던 정보입니다. 검증에 솔직합니다: 이 항목은 백필할 수 없으므로 측정된 승리인 척하지 않고 향후 확인될 품질 개선으로 출시합니다.

컴포넌트 영속성 (Component Persistence)

왜

재보정(A)에서 기록된 신뢰도가 판별력을 갖지 않음이 드러났습니다 — 시스템이 종목을 왜 그렇게 채점했는지 기록하지 않기 때문에 기저 비율로 수렴됩니다. 세 가지 능력(알고리즘 / 뉴스 / LLM)을 조화시키고 언젠가 정보성 있는 블렌드 신뢰도를 생성하려면, 각 기둥의 기여도를 예측별로 포착해야 합니다. 저장하지 않은 데이터로는 블렌드를 학습할 수 없습니다.

무엇을
  • predictions에 nullable components JSON 컬럼 추가 (가산적 마이그레이션, raw_confidence를 반영). 예시: {"algo":7.0,"news":1.0,"llm_context":-1.5,"overextension":"NONE","regime":"RISK_ON"}.
  • Prediction.components: Optional[dict]; insert 시 직렬화, read 시 파싱.
  • predict create --components '<json>' (잘못된 형식/ 비객체/NaN 거부).
  • metrics.get_component_contribution + stock-cli component-contribution: 기둥별 적중률 분할 (수치형: 양수/영/음수; 범주형: 값별). 태그된 행이 쌓일 때까지 비어 있습니다.
  • 두 스킬 모두 이제 모든 기록된 예측에서 --components를 사용합니다.
  • tests/test_components.py에 14개 테스트 + CLI 검증 테스트 3개.
어떻게

components는 여러 타입 컬럼 대신 단일 확장 가능 JSON 컬럼입니다 — 마이그레이션 비용이 낮고 새로운 기둥에 개방되어 있습니다. 기여도 읽기는 "긍정적 news/llm 기여가 실제로 적중률을 높이는가?"라는 질문에 답합니다 — 신뢰도 판별력을 회복할 수 있는 학습된 블렌드(E2-미래)의 측정 기반입니다.

검증

미래 지향 인프라: 프로덕션에는 오늘 현재 컴포넌트 태그된 종료 행이 0개이므로, component-contribution은 /expect + daily-briefing이 새 예측을 기록할 때까지 비어 있습니다. 기여도 수학은 시드 데이터로 유닛 테스트됩니다 (긍정 뉴스 0.8 적중 vs 부정 0.2). 백필 주장 없음.

리뷰 루프
수정 (전원, High) 전체 교체 마이그레이션 데이터 손실: _migrate_schema_if_needed가 raw_confidence/components를 제외한 하드코딩된 컬럼 목록을 복사했습니다. 이제 구 컬럼과 신 컬럼의 교집합을 복사합니다. 회귀 테스트 추가 (두 컬럼 모두 가진 레거시 DB + analysis_group_id 없음 → 값 보존됨).
수정 (codex, Medium) NaN/Infinity가 json.loads에서 허용됨; 이제 parse_constant로 거부됩니다 (비표준 JSON으로 직렬화되어 수치 분할을 왜곡할 수 있음).
수정 (code-reviewer, Medium) 영(0)과 음수의 혼동; 수치형 기둥이 이제 양수/영/음수로 분리됩니다.
수정 (codex, Low) n_with_components가 유효하지 않은 행을 계산했습니다; 이제 성공적으로 파싱된 dict 행만 계산합니다.
수정 cmd_component_contribution의 오류 처리; 잘못된 형식/비객체/ NaN 컴포넌트에 대한 CLI 검증 테스트.
참고 CHECK(json_valid(...)) 제안 거절: SQLite 버전 의존적이며 CLI가 이미 검증합니다; 이득 대비 취약성 증가.

  • mcp-prediction-store/metrics.py — get_component_contribution.
  • stock_cli.py — --components 플래그 + 검증, cmd_component_contribution.

  • tests/test_components.py, tests/test_recalibration_cli.py.
회고

리뷰에서 이 변경이 직접 건드리지는 않았지만 폭발 반경을 확장시킨 마이그레이션 경로의 잠재적 데이터 손실 버그를 발견했습니다 — 컬럼이 추가될 때마다 전체 교체 복사를 감사해야 한다는 교훈입니다. 이 단계는 설계상 적중률 변화를 제공하지 않습니다; 다음 조화 단계(학습된 블렌드)를 가능하고 정직하게 만드는 데이터 기반입니다.

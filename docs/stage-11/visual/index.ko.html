11단계

예측 정확도 이니셔티브: 읽기 전용 A/B 백필 평가 하네스, predict create 경로에 결정론적으로 연결된 아이소토닉 재보정 및 죽은 신호 제거, 그리고 리스크오프·중립 구간에서 BULL 호출을 억제하는 강성 시장 레짐 게이트.

Backfill Harness

왜

예측 적중률이 73%(2026-05-11)에서 24%(2026-06-14)로 폭락했습니다. 승인된 계획은 여섯 가지 정확도 변경 사항(A–F)을 규정합니다. 모든 변경 사항은 라이브 /expect 흐름에 적용되기 전에 과거 데이터로 검증되어야 합니다 — 그렇지 않으면 LIVE-vs-INTERACTIVE 낙관 편향(F4)을 반복할 위험이 있습니다. 이 하네스가 그 게이트입니다.

무엇을

scheduler/backfill_eval.py — 종료된(HIT/MISS) 예측에 대한 읽기 전용 A/B 도구, 그리고 tests/test_backfill_eval.py(9개 테스트, 전부 통과). 세 섹션을 보고합니다:

  • [A] 아이소토닉 재보정 — 누설 방지: 이전 훈련 슬라이스에서 재보정 맵을 적합시키고, 보류된 최근 테스트 슬라이스에서 원시 vs. 재보정 Brier를 채점합니다.
  • [B] 죽은 신호 기여도 — 종료 행을 죽은 신호 (valuation / cycle / mean_reversion) 사용 여부로 분리합니다.
  • [D] 레짐 구간 억제 — 리스크오프 구간 내에서 생성된 BULL 예측의 결과.
첫 실행 결과 (실제 DB, n=420 종료)
변경 지표 이전 이후
A (recal, OOS) ALL Brier 0.340 0.204
A (recal, OOS) LIVE Brier 0.331 0.160
B with-dead-signal 적중률 — 0.0% (n=15, Brier 0.424)
D BULL 6/1–6/7 적중률 — 4.3% (n=140)
어떻게

재구현 대신 프로덕션 보정 수학(build_recalibration_map, apply_recalibration, get_calibration_report, mcp-prediction-store/metrics.py)을 재사용합니다. 훈련 슬라이스는 인메모리 DB에 로드되어 버킷팅이 라이브와 동일합니다. 시간순 분할은 get_signal_decay (outcome_date, created_at, id)를 반영합니다.

코드 위치
  • scheduler/backfill_eval.py — _connect_readonly, load_closed, _metrics, eval_recalibration, eval_dead_signals, eval_regime_window, build_report.
  • tests/test_backfill_eval.py — 유닛 테스트 15개.
리뷰 루프
  • 수정 — DB가 읽기 전용이 아님 (codex, High): 하네스가 models.get_connection을 사용했는데, 이는 마이그레이션/인덱스/WAL/중복 자가 복구(쓰기)를 수행합니다. _connect_readonly(file:...?mode=ro URI)로 교체하여 읽기 전용 계약을 준수합니다.
  • 수정 — avg-return이 ×100 팽창 (codex, Low): outcome_return은 퍼센트 포인트로 저장되는데 :+.2% 형식 지정자가 100을 곱했습니다. 이제 :+.2f%. 이전의 “데이터 손상” 메모는 틀린 것이었습니다—데이터는 정상이었으며 표시 버그였습니다.
  • 수정 — 잘못된 oos_fraction / tiny-n (codex + gemini): 0 < oos_fraction < 1 검증과 “데이터 부족” 가드 추가.
  • 수정 — 수평별 재보정 (gemini + code-reviewer): eval_recalibration / build_report에 선택적 timeframe 및 --timeframe CLI 플래그 노출. 변경 A가 전역 vs. 수평별 맵을 비교할 수 있게 됩니다(1W 전역 Brier 0.331→0.169 vs. 전체 수평 0.331→0.160).
  • 수정 — 테스트 공백: 잘못된 fraction, 빈 신호 목록, 커스텀 dead-set, build_report 스모크 테스트 추가 (9 → 15).
  • 기각 — 인메모리 스키마 “Critical” (code-reviewer): 세 리뷰어 모두 4열 임시 테이블이 정확하게 옳다는 것을 확인했습니다.
  • 기각 — 엄격한 시점 분할 (gemini/codex): 분할이 outcome_date 기준이라 잔여 PIT 효과는 2차적입니다. eval_recalibration에 문서화.
알려진 기존 이슈 (표시됨, 수정 안 함 — 범위 외)

scheduler/weekly_calibration.py:208,236에서 avg_return을 :+.2%로 포맷합니다 (×100 팽창 버그)—프로덕션 주간 리포트에서 평균 수익률이 과장 표시됩니다. 별도의 범위 지정 수정으로 남겨둡니다.

회고

인메모리 DB를 통해 프로덕션 재보정 빌더를 재사용한 것이 하네스를 정직하게 유지시켰습니다(라이브에서 이탈할 수 있는 중복 보정 로직 없음). 세 리뷰어 루프는 충분한 가치를 발휘했습니다: codex가 읽기 전용 계약 위반과 잘못된 데이터를 탓하게 만든 포맷팅 버그를 잡아냈습니다. 교훈: 데이터를 탓하기 전에 표시 경로를 먼저 검증하라.

Recalibration And Dead Signals

왜
  • F1/F7 (과신 + 미사용 재보정 맵): 0.60–0.70 신뢰도 구간이 실제보다 +0.28 높게 나타났고, /expect가 오퍼레이터에게 재보정 맵을 수동으로 적용하라고 안내했음에도 백필에서 기록된 신뢰도는 여전히 ~0.6으로 거의 일정했습니다. 수동 LLM 단계는 신뢰할 수 없습니다; 재보정은 결정론적이어야 합니다.
  • F2/F5 (죽은 신호): valuation, cycle, mean_reversion의 적중률이 0%이며 신호별 보정만 오염시킵니다.
무엇을
  • A — predict create에 --recalibrate 플래그 (stock_cli.py). 저장 전에 원시 --confidence를 소스 범위 아이소토닉 곡선에 통과시킵니다; JSON에 raw_confidence / recalibration_applied를 출력합니다. 해당 소스의 종료 예측이 MIN_CLOSED_FOR_RECAL = 30개 미만이면 안전한 no-op.
  • B — 죽은 신호 제거. /expect와 daily-briefing 스킬 모두의 허용 가능한 --signals 목록에서 제거; 오퍼레이터는 그 읽기를 LLM_CONTEXT_SCORE로 라우팅하도록 안내받습니다.
  • 기존 버그 수정 (승인됨): weekly_calibration.py:208,236에서 avg_return을 :+.2%로 포맷 (×100 팽창). 이제 :+.2f%.
  • 테스트: tests/test_recalibration_cli.py(3개) — 최소 샘플 게이트, 과신 당김, 소스 범위 지정.
어떻게

재보정은 build_recalibration_map / apply_recalibration (mcp-prediction-store/metrics.py)을 재사용합니다. 전역(전체 수평) 맵을 사용합니다—백필에서 수평별 맵만큼 정확하고 (Brier 0.160 vs. 0.169) 현재 표본 규모에서 더 견고합니다. 소스 범위 지정: LIVE 예측은 LIVE 이력에 대해서만 보정되며, 과적합된 INTERACTIVE 행과는 혼합되지 않습니다(F4 격차). 로깅 임계값은 여전히 원시 신뢰도로 게이팅되며, 저장 값만 재보정되므로 “각 수평 ≥ 0.60 저장” 의미론이 그대로 유지됩니다.

검증

백필 OOS Brier: LIVE 0.331 → 0.160, ALL 0.340 → 0.204 (누설 방지 훈련/테스트 분할).

라이브 맵 검사로 드러난 경고: 프로덕션 LIVE 곡선에는 단일 앵커(0.612 → 0.248)만 있는데, raw_confidence가 거의 일정하기 때문입니다. 재보정이 모든 신뢰도를 ~0.25 기본율로 수렴시킵니다. 이것이 Brier 개선의 원천이지만 (순열 테스트가 이미 원시 신뢰도에 신호가 없음을 보여줬습니다), 모델이 정보가 담긴 신뢰도 스프레드를 출력할 때까지 기록된 신뢰도가 종목 순위를 멈추게 됩니다. 판별력 회복은 하위 작업(변경 E / 메타-레이블링)이지 재보정의 역할이 아닙니다.

리뷰 루프
  • CRITICAL (3개 모두, 수정) — 재보정이 자체 훈련 데이터를 오염시킴. 재보정된 값을 confidence에 다시 저장하면 향후 맵을 오염시킵니다: build_recalibration_map / get_calibration_report가 confidence를 원시 예측 변수로 읽으므로, 재보정된 행(≈0.25)이 종료되면 원시인 것처럼 곡선에 다시 진입하여 그 도메인을 붕괴시킵니다(재귀 피드백). 수정: nullable raw_confidence 열 추가(models.py 스키마 + 가산적 _ensure_raw_confidence_column 마이그레이션 + dataclass/insert/reader); predict create는 이제 항상 원시 신뢰도를 거기에 유지하며, 보정은 COALESCE(raw_confidence, confidence)로 훈련하여 재보정된 값을 절대 볼 수 없습니다. 새 테스트 test_map_trains_on_raw_not_recalibrated는 stored-0.30 / raw-0.65 행이 0.65를 맵에 기여함을 증명합니다. 마이그레이션은 프로덕션 복사본에서 검증되었습니다 (1169행 보존, 열 추가, 레거시 맵 변경 없음).
  • 수정 — 테스트 공백 (codex/code-reviewer): 게이트 이후 빈 맵 no-op, 무오염 테스트, 엔드투엔드 cmd_predict_create --recalibrate 테스트 추가.
  • 인지됨 — 리플레이 이중 적용: 호출자가 --recalibrate로 이미 보정된 저장 신뢰도를 수동으로 재제출하면 다시 맵핑됩니다. 정상적인 /expect 경로 밖의 이야기이며, 문서화되었고 게이팅되지 않았습니다.

회고

재보정을 수동 LLM 지시에서 CLI 플래그로 이동한 것이 F7의 실질적인 수정입니다—맵이 수 주 동안 존재했지만 한 번도 안정적으로 적용되지 않았습니다. 백필 델타만이 아닌 실제 라이브 맵을 검사한 것이, 재보정이 현재 기본율로 퇴화하고 있음을 포착했습니다. 신뢰도가 판별을 멈췄음을 나중에 발견하는 것보다 지금 솔직하게 기록하는 것이 낫습니다.

Regime Gate

왜

F3: 2026년 6월 하락장 동안 /expect가 조정을 통해 계속 BULL을 발행했습니다(6/1–6/7의 140개 종료 BULL 중 적중률 4.3%). 결정론적 리스크오프 게이트가 없었습니다—매크로 스킬들은 LLM이 무시할 수 있는 권고성 콜아웃에 불과했습니다.

무엇을
  • stock-cli regime --market US|KR → 결정론적 RISK_ON / NEUTRAL / RISK_OFF 판정: 인덱스 프록시 가격 구조 기반(MA50/MA200 대비 추세, 52주 고점 대비 하락, 1개월 수익률, 연율화 20일 실현 변동성). US는 SPY + QQQ 중 더 나쁜 것을 집계; KR은 KODEX 200(069500) 사용.
  • /expect(RULE R1) 및 daily-briefing(RULE R1)에 강성 게이트 연결: RISK_OFF → 신규 BULL 억제(WATCH로 제한, 수평 → NEUTRAL); NEUTRAL → BUY 바 8.0→9.0 상향 및 신뢰도 제한(cap 0.60); RISK_ON → 변경 없음.
  • tests/test_regime.py(16개 테스트).
어떻게

mcp-market-data/regime.py의 순수하고 네트워크 없는 로직 (compute_realized_vol, compute_regime, aggregate_regime); CLI가 기존 프로바이더 + compute_horizon_metrics를 통해 인덱스 봉을 공급합니다. aggregate_regime은 dataclasses.replace(입력 변경 없음)를 통해 최악의 프록시를 반환하고 모든 프록시 점수를 proxy_scores에 기록합니다.

검증

각 예측의 발행일 기준 레짐을 재구성하고 140개 종료 BULL을 버킷팅했습니다 (6월 구간에 대한 네트워크 재구성 — 솔직한 결과):

  • 발행 시 NEUTRAL: n=65, 적중률 3.1% — 게이트가 억제/강화합니다.
  • 발행 시 RISK_ON: n=75, 적중률 5.3% — 발행 시점에 지수가 침착했습니다; 게이트가 포착할 수 없습니다.
  • 6/2 클러스터(72건)는 인덱스만으로는 게이팅 불가였습니다— QQQ조차 RISK_ON이었고 하락은 그 이후에 왔습니다. SPY는 전체 구간 동안 RISK_ON을 벗어나지 않았습니다; QQQ는 6/7에 NEUTRAL로 전환했습니다; KR은 급등 변동성(1개월 +40%, 변동성 56%)을 통해 일찍 NEUTRAL을 표시했습니다.

결론 (과장 없이): 레짐 게이트는 부분적인 완화책입니다— 창구의 패자 중 ~46%(NEUTRAL 건들)를 제거하고 진행 중인/급등 조정으로의 매수를 중단시키지만, 6/2 고점에서 광범위한 지수는 침착했습니다. 보완적 레버—개별 종목 과확장—는 계획된 후속 단계입니다; 재보정(A)이 이미 6/2 클러스터를 그토록 피해를 주게 만든 과신을 붕괴시킵니다.

리뷰 루프
  • 수정 (3개 모두) — aggregate_regime이 입력 판정을 변경. 이제 dataclasses.replace가 복사본을 반환합니다; 테스트가 입력 불변을 단언합니다.
  • 수정 (codex High) — cmd_regime이 실패한 프록시를 조용히 누락. (QQQ 손실 시 US 게이트가 성장 주도 하락에 맹목적이 됩니다.) 이제 누락된 프록시가 판정 노트에 표시됩니다.
  • 수정 (codex+gemini) — 이력 부족 시 RISK_ON 기본값. MA200이 없으면 추세를 알 수 없으므로 강성 게이트가 RISK_ON을 인증해서는 안 됩니다; 이제 노트와 함께 NEUTRAL로 내려갑니다.
  • 수정 — argparser 도움말이 US의 기본값으로 SPY라고 했습니다; 이제 “worst-of SPY+QQQ”.
  • 수정 — 테스트 공백: 정확한 실현 변동성 값, MA 우선순위, 이력 부족, 변경 없음, tie→first, 단일 프록시.
  • 기각 — 임계값 플래핑/히스테리시스 (gemini): 임계값 근처의 일별 플래핑에는 영속 상태가 필요합니다; 게이트는 장중이 아닌 브리핑당 한 번 조회됩니다. 알려진 제한 사항으로 문서화하고 구현하지 않았습니다.

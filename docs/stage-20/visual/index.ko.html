20단계

한국 주식 뉴스 수집 방식을 불안정한 HTML 스크래핑에서 공식 Naver Search API로 교체하고, 기존 NewsItem 인터페이스와 스크래핑 폴백을 그대로 유지합니다.

Kr News Naver Api

왜

한국 종목별 뉴스는 finance.naver.com HTML을 스크래핑하는 방식 (KoreanMarketProvider.get_news)으로 수집되었는데, 레이아웃 변경이나 차단이 발생할 때마다 빈 목록을 반환하며 조용히 실패하는 문제가 반복되었습니다. 심층 리서치(22/25개 주장 검증)를 통해 공식 Naver Search API for News가 무료이면서 안정적인 최선의 대안으로 권고되었으며, Naver 크롤링에 따른 데이터베이스 권리/UCPA 법적 위험도 함께 제거됩니다.

무엇을
  • get_news는 이제 NAVER_CLIENT_ID + NAVER_CLIENT_SECRET가 설정된 경우 Naver Search API (https://openapi.naver.com/v1/search/news.json)를 우선 사용합니다. pykrx get_market_ticker_name으로 종목의 한글 회사명을 조회한 뒤 키워드 검색하며, 결과를 기존의 변경되지 않은 NewsItem 형태 (headline, source=발행사 도메인, ISO 날짜, url)로 매핑합니다.
  • 강건한 폴백: 키가 없거나, 회사명을 확인할 수 없거나, API 오류가 발생하면 기존 HTML 스크래핑으로 전환합니다(회귀 없음). 스크래핑은 이제 주경로가 아닌 안전망입니다.
  • 헬퍼 함수: _company_name, _fetch_naver_search_news, _clean_html (<b> 태그 제거 + html.unescape), _domain, _parse_rfc822 (타임존 인식).
  • sentiment_score=None (Naver는 감성 점수를 제공하지 않으며, 하위 /expect에서 계산됩니다).
  • 문서: NAVER_CLIENT_ID/NAVER_CLIENT_SECRET를 CLAUDE.md API Keys 및 README .env에 추가했습니다.
어떻게

키워드 검색은 노이즈가 많아 과잉 수집 방식을 사용합니다 (display=min(100, max(limit*3,30)), sort=date). 이후 제목 또는 요약에 회사명이 포함된 최근 항목만 남기며, RFC-822 pubDate를 타임존 인식 datetime으로 파싱해 호스트 타임존에 무관한 since_days 기준을 적용합니다. TDD 방식으로 작성(총 8개 KR 뉴스 테스트: API 파싱/관련성/since_days + 폴백 경로 3가지 + 정제 처리).

코드 위치
  • mcp-market-data/providers/kr.py — get_news 재작성 + _company_name, _fetch_naver_search_news, _clean_html, _domain, _parse_rfc822; NAVER_SEARCH_NEWS_URL 상수.
  • mcp-market-data/tests/test_news.py — Naver Search API 테스트 + 폴백 테스트.
  • CLAUDE.md (API Keys), README.md (.env).
리뷰 루프

회고

리서치-통합 인계 방식이 효과적으로 작동했습니다. 검증된 권고안이 기존 NewsItem 인터페이스에 깔끔하게 맞아 떨어져 변경 범위가 단일 프로바이더로 한정되었고, 스크래핑은 폴백으로 보존되었습니다. 키워드 검색을 사용하므로 관련성 필터링과 종목→회사명 조회가 처리 경로에 포함됩니다. 정밀도가 낮아지는 경우(예: 삼성 vs 삼성전자 모호성)에는 관련성 검사를 강화하거나 DeepSearch(유료, 종목별)를 도입하는 방향을 고려할 수 있습니다.

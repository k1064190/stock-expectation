22단계

차단된 FMP 레거시 엔드포인트를 이관하고, 키 없이 동작하는 yfinance earnings 폴백을 추가하며, 부분 장애를 조용히 fail-open 처리하는 대신 눈에 보이게 만들어, 조용히 죽어 있던 R3 catalyst-event 게이트를 복원합니다.

R3 Event Gate Restore

왜

R3 이벤트 게이트는 조용히 죽어 있었습니다. FMP의 레거시 엔드포인트인 /api/v3/earning_calendar와 /api/v3/economic_calendar가 이 계정 키에 대해 403 Forbidden을 반환했기 때문입니다(FMP의 플랜 마이그레이션 이후 레거시 엔드포인트가 차단됨). 게이트는 설계상 fail-open이므로, 모든 실패가 gate_unavailable: true로 수렴되어 캡/트림이 전혀 적용되지 않았고, 모든 LIVE 예측은 그저 R3 unavailable=0이라고만 로그를 남길 뿐이었습니다 — earnings-imminent WATCH 캡과 FOMC/CPI 매크로 트림이 전혀 적용되지 않았으며, 출력에는 "피드가 죽었다"와 "이벤트가 없다"를 구분할 수 있는 정보가 전혀 없었습니다.

무엇을

  • 엔드포인트 마이그레이션. 실제 키로 프로빙한 결과: /stable/earnings-calendar → 200 (동작함; 동일한 symbol/date 키, time/companyName은 없음), /stable/economic-calendar → 402 (유료 플랜 필요), 두 v3 엔드포인트 모두 → 403. events.py의 FMP_BASE_URL과 pre_surge_discovery.py의 earnings URL을 /stable로 마이그레이션했습니다.
  • 키 없이 동작하는 yfinance earnings 폴백. 새로 추가된 _fetch_earnings_fallback_yf는 FMP earnings 조회가 실패하거나(또는 키가 없을 때) yf.Ticker(t).calendar를 통해 후보 티커별 다음 실적 발표일을 가져와 동일한 티커별 캡/트림 로직에 공급합니다. 전체 장애 시에만 예외를 발생시켜, 빈 결과가 "임박한 실적 없음"과 혼동되지 않도록 합니다.
  • 부분 가용성의 가시화. EventGate에 earnings_source("fmp" / "yfinance" / null)와 macro_available(불리언)가 추가되었으며, 성능 저하가 발생할 때마다 설명 노트가 추가됩니다. gate_unavailable: true는 이제 "어떤 소스도 데이터를 만들어내지 못함"을 의미하며, 부분적 장애(예: 매크로 402)에서는 게이트가 계속 살아 있습니다. daily-briefing 프롬프트 블록이 이 노트를 렌더링합니다.
  • 키 마스킹(redaction). httpx 에러 문자열에는 apikey=…를 포함한 요청 URL이 그대로 들어 있습니다; 새로 추가된 _redact_key가 이 메시지를 notes(JSON 출력 / LLM 프롬프트)나 로그에 도달하기 전에 제거합니다.
  • 타임라인 분리. catalyst timeline이 두 캘린더를 독립적으로 조회하도록 변경되어, --include-macro와 함께 매크로 402가 발생해도 정상 동작하는 earnings 타임라인을 더 이상 가리지 않습니다.
  • 문서 업데이트: catalyst-event-gate/SKILL.md(가용성 필드 표, stable 엔드포인트, 폴백), expect/SKILL.md(4단계 + R3 fail-open 항목), daily-briefing/SKILL.md(R3 문단).

어떻게

evaluate_gate는 하나의 all-or-nothing try/except 구조에서 두 개의 독립적인 축으로 재구성되었습니다: earnings(FMP → yfinance 폴백, US 전용)와 macro(FMP 전용, 키 없이 사용 가능한 소스가 없음). 각 축은 게이트에 자신의 결과를 기록하며, 중립 판정으로의 단락(short-circuit)은 두 축이 모두 다운되었을 때만 발생합니다. 폴백 fetcher는 기존 테스트 스텁 관례를 따라 주입 가능하도록 (fetch_earnings_fallback) 설계되었습니다. 메인 체크아웃에서 읽기 전용으로 라이브 검증한 결과: 실제 키로는 earnings_source: "fmp", 매크로 402는 노트에 표시됨(키는 마스킹됨), yfinance 경로는 CAT의 실제 다음 실적 발표일을 반환했습니다.

코드 위치

  • mcp-market-data/events.py — FMP_BASE_URL(stable), EventGate.earnings_source / macro_available, _redact_key, 재구성된 evaluate_gate(~L436-530), _fetch_earnings_fallback_yf, stable 엔드포인트 fetch 래퍼(wrapper).
  • stock_cli.py — cmd_catalyst_timeline 분리된 fetch (~L875-900), cmd_catalyst_gate docstring, _redact_key import.
  • scheduler/daily_briefing.py — _format_event_gate_for_prompt가 노트를 렌더링.
  • scheduler/pre_surge_discovery.py — earnings URL을 stable로 마이그레이션.
  • mcp-market-data/tests/test_events.py — 9개의 신규 테스트 (403→폴백 캡, 키 누락 시 폴백, 매크로 다운 시 가시화, 양쪽 다운 시 부분 가용, 키 마스킹, yfinance 폴백 단위 테스트), 폴백을 주입하도록 업데이트된 기존 fail-open 테스트 2개.
  • scheduler/tests/test_daily_briefing.py — 부분 가용성 노트 렌더링.

회고

소스별 가시성 없는 fail-open은 "무위험"과 구별할 수 없습니다 — 앞으로 만들 게이트는 처음부터 source/availability 필드를 포함해야 합니다. 이번 라이브 프로브는 또한 원래 구현 시점부터 존재했던 httpx 에러 메시지의 API 키 유출을 게이트 노트에서 발견해 냈습니다.

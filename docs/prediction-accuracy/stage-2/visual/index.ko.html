2단계

통계적으로 죽은 시그널에 대한 자본 노출을 줄이기 위해 ALGO 테이블 가중치를 재조정하고, low-edge-band 예측을 완전히 차단하는 대신 태깅한 뒤 필터링합니다.

Signal Downweight Edge Band

왜

30일 주간 캘리브레이션(2026-07-05)에서 모멘텀(24.6%), 거래량 (23.3%), 기술적(26.5%), 뉴스(21.1%) 시그널이 통계적으로 죽은 시그널로 판정되었고, 섹터(52.6%)와 펀더멘털(67.5%)만 동전 던지기보다 나은 성과를 보였습니다. 별도로, 두 페이퍼 계좌 모두에서 0.60~0.70 raw-confidence 구간이 음(-)의 실현 엣지(US +1.0%, KR -0.1% 평균 왕복 수익률)를 보이는데도 예측 대부분이 이 구간에 몰려 로그되고 있었습니다.

무엇을

/expect ALGO 테이블에서 모멘텀 가중치를 +1.5 → +1.0으로, 거래량을 +1.0 → +0.5로 낮춰 ALGO 상한을 8.0 → 7.0으로 낮췄습니다. 이에 따라 BUY(≥8.0) 판정은 항상 뉴스/ LLM-context의 결합 확신도가 +1.0 이상이어야 합니다. 긍정적 LLM_CONTEXT는 반드시 섹터 상대강도(sector-RS)나 펀더멘털 촉매를 근거로 들어야 하며, 기술적/모멘텀 근거만으로는 인정되지 않습니다. 파생되는 모든 수치(합성 점수 범위, 임계값 근거, 예시 계산, 샘플 JSON)를 함께 갱신했습니다. predict create는 이제 raw confidence가 [0.60, 0.70]인 LIVE BULL 예측에 components.low_edge_band = true를 태깅합니다 — 차단이 아니라 태그입니다. 재보정 확신도(recal-confidence) 하한은 isotonic 보정이 모든 값을 ~0.25 근처로 수렴시켜 버려 실효성이 없고, 차단할 경우 4단계 학습형 블렌드에 필요한 학습 데이터 행이 고갈되기 때문입니다. paper_trading_run의 새 filter_low_edge_band는 페이퍼 자본을 투입하기 전에 태그된 예측을 건너뜁니다.

어떻게

개발은 TDD 방식으로 진행되어, 태깅 테스트 7개와 필터 테스트 1개를 먼저 작성했습니다. 태그는 1단계 게이트 리프레시 직후 cmd_predict_create 안에 위치하며, 필터는 run_range 최상단에서 호출되는 순수 헬퍼로, 건너뛴 예측 개수를 info 로그로 남깁니다.

코드 위치

  • stock_cli.py — LOW_EDGE_BAND 상수 + cmd_predict_create 내 태그 블록
  • scheduler/paper_trading_run.py — filter_low_edge_band, SELECT + run_range 연결
  • .claude/skills/expect/SKILL.md — 점수 테이블, 근거 설명, Step 5b 가이드, 예시 계산
  • tests/test_low_edge_band.py, scheduler/tests/test_paper_trading_run.py

검증

  • uv run pytest -m "not network" — 895개 통과 (신규 8개)
  • SKILL.md에서 예전 8.0 상한 값에 대한 잔존 참조를 훑어본 결과, 의도적으로 유지된 BUY 임계값(8.0)만 남아 있음을 확인함.

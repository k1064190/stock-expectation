Stage 4a

Builds and validates a learned confidence blend offline against raw and isotonic baselines, wiring it live only if it beats them on real data — which, honestly, it currently does not.

Learned Blend Offline

Why

Raw confidence carries zero discrimination under a permutation test, and the isotonic recalibrator collapses everything to the ~0.25 base rate — confidence has stopped ranking picks. The standing capstone (docs/stage-11) prescribed a learned blend over the persisted components pillars, gated on at least 100 components-tagged closed rows. That threshold is now crossed, with 150 usable rows.

What

mcp-prediction-store/blend.py implements a hand-rolled L2 logistic regression — no new dependencies, matching the hand-rolled isotonic PAV — over a fixed 11-feature vector (algo / news / llm_context / return_1m scores, overextension and regime one-hots, market, timeframe), with column standardization and deterministic full-batch gradient descent. Validation uses leak-free walk-forward cross-validation: folds are built by created_at, and each fold trains only on rows whose outcome_date precedes the fold's first test created_at — i.e. outcomes actually known at prediction time, so overlapping horizons cannot leak. Baselines are raw confidence and a train-fold isotonic map; metrics are Brier score and rank AUC, both pooled and fold-mean. blend_wins requires beating isotonic on Brier and an AUC above 0.55. stock-cli blend-eval [--write] produces the CV report; --write trains on all rows and saves state/blend_model.json with CV metrics embedded — inert until stage 4b wires it in. The weekly calibration report gains a fail-open "Learned blend (offline walk-forward CV)" section.

Live-data result

On the real 150-row sample (2026-07-12, leak-free CV) the blend honestly loses: blend Brier 0.233 / AUC 0.406 versus isotonic Brier 0.123 (raw 0.348). Only one fold currently has enough already-known outcomes to train on, since the components-tagged history is young and horizons overlap, and on it the blend under-ranks while isotonic's flat base-rate output wins on Brier. blend_wins: false, so nothing is wired live; the weekly report keeps re-evaluating as rows accumulate. This is exactly the outcome the offline stage exists to catch.

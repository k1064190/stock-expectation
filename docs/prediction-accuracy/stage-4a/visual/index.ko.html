4a단계

학습형 신뢰도 블렌드를 오프라인에서 만들고 raw/등장형(isotonic) 기준과 비교 검증하며, 실데이터에서 이겼을 때만 라이브에 연결합니다 — 현재는 이기지 못합니다.

Learned Blend Offline

왜

raw confidence는 순열 검정(permutation test)에서 판별력이 전혀 없고, 등장형(isotonic) 재보정기는 모든 값을 기저율 ~0.25로 수렴시켜 — confidence가 더 이상 후보 순위를 매기지 못합니다. 상시 capstone(docs/stage-11)은 저장된 components 필러들에 대한 학습형 블렌드를 처방했으며, 조건은 components 태그가 붙은 종료된 예측 100건 이상이었습니다. 이제 사용 가능한 150건으로 그 임계값을 넘었습니다.

무엇을

mcp-prediction-store/blend.py는 손수 구현한(hand-rolled) L2 로지스틱 회귀를 구현합니다 — 손수 구현한 등장형 PAV와 마찬가지로 새로운 의존성 없이 — 고정된 11개 피처 벡터(algo/news/llm_context/return_1m 점수, overextension·regime 원-핫, market, timeframe)에 대해 열 표준화와 결정론적 풀배치 경사하강을 사용합니다. 검증은 누수 없는(leak-free) walk-forward 교차검증을 사용합니다: 폴드는 created_at 기준으로 나뉘고, 각 폴드는 해당 폴드의 첫 테스트 created_at 이전에 outcome_date가 있는 행에서만 학습합니다 — 즉 예측 시점에 실제로 알려져 있던 결과만 사용하므로 겹치는 호라이즌이 누수를 일으킬 수 없습니다. 기준선은 raw confidence와 학습 폴드의 등장형 매핑이며, 지표는 Brier 점수와 순위 AUC를 pooled와 fold-mean 두 방식으로 봅니다. blend_wins는 Brier에서 등장형을 이기고 AUC가 0.55를 넘어야 참이 됩니다. stock-cli blend-eval [--write]는 CV 리포트를 생성하고, --write는 전체 행으로 학습하여 CV 지표가 담긴 state/blend_model.json을 저장합니다 — 4b 단계에서 연결하기 전까지는 비활성 상태입니다. 주간 캘리브레이션 리포트에는 fail-open 방식의 "Learned blend (offline walk-forward CV)" 섹션이 추가되었습니다.

실데이터 결과

실제 150건 표본(2026-07-12, 누수 없는 CV)에서 블렌드는 정직하게 집니다: 블렌드 Brier 0.233 / AUC 0.406 대 등장형 Brier 0.123 (raw 0.348). components 태그 이력이 아직 짧고 호라이즌이 겹치기 때문에 현재는 학습할 만큼 이미 결과가 알려진 폴드가 단 하나뿐이며, 그 폴드에서 블렌드는 순위를 잘못 매기는 반면 등장형의 평평한 기저율 출력이 Brier에서 이깁니다. blend_wins: false이므로 라이브에는 아무것도 연결되지 않았고, 주간 리포트는 데이터가 쌓이는 대로 계속 재평가합니다. 이는 오프라인 단계가 정확히 잡아내기 위해 존재하는 결과입니다.

리뷰 루프

  • Antigravity (Gemini 3.1 Pro High): CRITICAL 1건 — outcome_date 기준으로 나눈 walk-forward 폴드가 테스트 예측의 created_at 시점에는 아직 알려지지 않은 결과를 누수시킴. 수정: 폴드가 이제 created_at을 기준으로 하고, 폴드별 학습 풀은 outcome_date < 첫 테스트 created_at인 행이며, 최소 학습 크기 미만인 폴드는 건너뛰고 회귀 테스트를 추가함. MEDIUM 1건 — n으로 나눈 L2 페널티가 데이터가 늘어남에 따라 감쇠함; 스텝당 상수 페널티로 수정(L2_DEFAULT를 1.0에서 0.05로 재조정). LOW 1건 — pooled AUC가 폴드 간 레짐 변화로 왜곡됨; 이제 fold-mean AUC를 함께 보고함.

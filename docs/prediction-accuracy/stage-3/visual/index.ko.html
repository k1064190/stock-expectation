3단계

예측 시점에 계산한 뒤 버려지던 기사 단위 뉴스 시그널을 저장하기 시작하여, 어떤 촉매가 실제로 예측력을 갖는지 나중에 측정할 수 있도록 합니다.

News Signal Persistence

왜

스칼라 뉴스 점수는 거의 죽은 시그널(승률 21~33%)로 평가되지만, 여기서 축약되어 사라지는 더 풍부한 NewsSignal 필드들 — 실적 발표, M&A, 애널리스트 등급 같은 이벤트 태그, 최근성 가중 감성, 확실한 긍정/부정 촉매 — 은 예측 시점에 계산된 뒤 그대로 버려지고 있었습니다. 이를 저장하지 않으면 어떤 뉴스 촉매가 실제로 예측력이 있는지 영원히 학습할 수 없고, 하루하루 미룰수록 4단계 학습형 블렌드 등을 위한 라벨링된 훈련 데이터를 잃게 됩니다.

무엇을

NewsSignal.to_components_dict()는 이제 모든 예측의 components.news_signal에 저장되는 압축 JSON 페이로드를 생성합니다. API 모드에서는 log_predictions 내부의 _augment_news_signal이 티커별 뉴스를 가져와 LIVE 예측에 한해서만 시그널을 저장하며, fail-open으로 동작하고 모델이 제공한 값은 절대 덮어쓰지 않습니다. claude-code/codex 같은 CLI 기반 모드에서는 /expect 스킬과 두 브리핑 프롬프트 모두 --components에 news_signal을 필수로 요구합니다. 새로운 get_news_tag_performance 함수와 stock-cli news-tag-performance 명령은 종료된 예측들에 대해 이벤트 태그별·촉매별 적중률을 보고하며, 최소 표본 수(기본값 8)로 가드됩니다. get_component_contribution은 이제 중첩된 dict/list 값을 건너뛰어 새 페이로드가 필러 버킷을 오염시키지 않도록 합니다.

어떻게

개발은 TDD 방식으로 진행되어, 구현 전에 새 테스트 6개를 먼저 작성했습니다. augment 헬퍼는 기존 _augment_gate_components 패턴을 그대로 따르며, _news_item_obj는 dict 형태의 픽스처를 summarize_news가 기대하는 속성 접근 형태로 연결해 줍니다.

리뷰 루프

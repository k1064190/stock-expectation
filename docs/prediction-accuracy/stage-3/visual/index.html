Stage 3

Stops discarding the rich per-article news signal at prediction time and starts persisting it, so which catalysts actually predict can eventually be measured.

News Signal Persistence

Why

The scalar news score is graded near-dead (21-33% win), but the richer NewsSignal fields it collapses from — event tags such as earnings, M&A, and analyst actions, recency-weighted sentiment, and hard positive or negative catalysts — were computed at prediction time and then discarded. Without persisting them, nothing can ever learn which news catalysts actually predict, and every day of delay loses labeled training rows for the stage-4 learned blend and beyond.

What

NewsSignal.to_components_dict() produces a compact JSON payload now persisted under components.news_signal on every prediction. In API mode, _augment_news_signal inside log_predictions fetches per-ticker news and stores the signal for LIVE predictions only, failing open and never overwriting a model-supplied value. For CLI-driven modes (claude-code/codex), the /expect skill and both briefing prompts now mandate news_signal in --components. A new get_news_tag_performance function and stock-cli news-tag-performance command report per-event-tag and per-catalyst hit rates over closed predictions, guarded by a minimum sample size (default 8). get_component_contribution now skips nested dict or list values so the new payload cannot pollute pillar buckets.

How

Development followed TDD: 6 new tests were written before the implementation. The augment helper mirrors the existing _augment_gate_components pattern, and _news_item_obj bridges dict fixtures to the attribute-access shape that summarize_news expects.

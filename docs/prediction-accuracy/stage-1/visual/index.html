Stage 1

Closes a fail-open gap in the store-level overextension gate so LIVE BULL entries always have real overextension data to be judged against.

Overextension Gate Refresh

Why

The store-level overextension gate (RULE R2, _check_overextension_gate) hard-rejects LIVE BULL entries on parabolic blow-offs, but it reads overextension and return_1m from the caller-supplied --components JSON and fails open when they are absent. A briefing or expect run that omitted components silently bypassed the one enforcement that survives cron. Entry-time evidence showed EXTREME-overextended BULL entries winning only 29.1% versus 53.5% at NONE.

What

stock-cli predict create for LIVE BULL now backfills missing overextension and return_1m into components from fresh price bars before insertion, so the R2 gate always has real data to act on. Caller-supplied values are never overwritten. The system fails open on any fetch or compute error, logging a stderr warning. A new --no-gate-refresh escape hatch supports offline use. INTERACTIVE and BEAR creates are untouched.

How

A new _refresh_overextension_components() fetches roughly 120 calendar days of bars via the existing provider (_get_provider().get_price_history) and reuses compute_horizon_metrics (which already computes overextension_level and return_1m); only missing keys are injected. It is wired into cmd_predict_create between components parsing and the DB insert. Development followed TDD: 10 tests were written first, then the implementation.

Code locations

  • stock_cli.py — _refresh_overextension_components (+ GATE_REFRESH_DAYS), call site in cmd_predict_create, --no-gate-refresh argparse flag
  • tests/test_gate_refresh.py — helper unit tests + cmd_predict_create integration tests (parabolic reject, healthy insert with injected components, escape hatch, INTERACTIVE skip, fail-open insert)

1단계

스토어 단계의 과열도(overextension) 게이트에 있던 fail-open 허점을 메워, LIVE BULL 진입이 항상 실제 과열도 데이터를 근거로 판정되도록 합니다.

Overextension Gate Refresh

왜

스토어 단계 과열도 게이트(RULE R2, _check_overextension_gate)는 포물선형 급등 (parabolic blow-off) 국면에서 LIVE BULL 진입을 강제로 거부하지만, 호출자가 전달한 --components JSON에서 overextension과 return_1m을 읽어오기 때문에 이 값들이 없으면 fail-open(통과)되어 버립니다. 브리핑이나 expect 실행에서 components를 생략하면 cron에서도 살아남는 유일한 강제 규칙이 조용히 우회되던 셈입니다. 진입 시점 데이터로는 EXTREME 수준으로 과열된 BULL 진입의 승률이 29.1%에 불과했던 반면, NONE 수준에서는 53.5%였습니다.

무엇을

LIVE BULL에 대한 stock-cli predict create는 이제 DB에 삽입하기 전에 최신 가격 바(bar) 데이터로부터 overextension과 return_1m의 누락 값을 components에 채워 넣어, R2 게이트가 항상 실제 데이터를 근거로 동작하도록 합니다. 호출자가 값을 전달한 경우에는 절대 덮어쓰지 않습니다. 데이터 조회나 계산 과정에서 오류가 나면 stderr 경고를 남기고 fail-open으로 동작합니다. 오프라인 사용을 위한 새로운 --no-gate-refresh 탈출구도 추가되었습니다. INTERACTIVE와 BEAR 생성 경로는 변경되지 않았습니다.

어떻게

새로 추가된 _refresh_overextension_components()는 기존 provider(_get_provider().get_price_history)를 통해 약 120 캘린더 일치의 바 데이터를 가져오고, overextension_level과 return_1m을 이미 계산하는 compute_horizon_metrics를 재사용합니다. 누락된 키만 주입됩니다. 이 로직은 components 파싱과 DB 삽입 사이, cmd_predict_create 안에 연결되었습니다. 개발은 TDD 방식으로 진행되어, 구현 전에 테스트 10개를 먼저 작성했습니다.

코드 위치

  • stock_cli.py — _refresh_overextension_components (+ GATE_REFRESH_DAYS), cmd_predict_create 내 호출 지점, --no-gate-refresh argparse 플래그
  • tests/test_gate_refresh.py — 헬퍼 단위 테스트 + cmd_predict_create 통합 테스트(포물선형 거부, 주입된 components를 사용한 정상 삽입, 탈출구, INTERACTIVE 스킵, fail-open 삽입)

검증

  • uv run pytest -m "not network" — 883개 통과 (신규 10개)
  • 실제 E2E: components 없이 predict create NVDA LIVE BULL을 스크래치 DB에 대해 실행 — 실제 바 데이터를 가져와 {"overextension": "NONE", "return_1m": 0.0133}이 주입되어 저장됨

회고

이 게이트의 허점은 기존 유틸리티(provider + 지표 계산)만으로도 완전히 메울 수 있었다. 새로 추가된 로직은 병합 정책(누락된 키만 주입)과 fail-open 동작뿐이다.

Stage 6

Turns keyword-bucket curation from reactive firefighting into a monthly LLM-reviewed audit against real headlines, with humans applying any accepted edits via PR.

News Bucket Audit

Why

The catalyst/risk matchers are hand-maintained keyword lists with a documented live false positive: in 2026-06 a ballot-counting-site "blockade" headline tripped the war_conflict macro bucket and wrongly trimmed every pick. The stage-24 retrospective said the keyword lists would need occasional curation — this job makes that curation systematic instead of reactive.

What

scheduler/news_bucket_audit.py is a monthly, report-only job: it samples recent live headlines (from recently-predicted tickers via each market's provider, plus the macro wire), annotates them with the current matcher verdicts (EVENT_KEYWORDS, hard catalysts, MACRO_RISK_BUCKETS), and has a single claude -p call judge false positives, likely misses, per-family precision, and suggested keyword edits. Output goes to reports/news-bucket-audit-YYYY-MM-DD.md. It never edits the tables itself — a human applies accepted suggestions via a PR. A monthly crontab entry runs it on the 1st at 20:00 KST.

How

TDD with 5 tests. The job reuses deep_dive._call_claude, sampling is fail-open per source, and headlines are fenced as untrusted data in the auditor prompt.

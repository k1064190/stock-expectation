Stage 5

Gives each scanner pick its own independent Bull/Bear/Judge deep dive with full headline context, behind a default-off flag, without ever logging a prediction itself.

Deep Dive Fanout

Why

The daily briefing analyzes five or six candidates in one LLM call, so every stock gets shallow, shared context, and /expect's LLM_CONTEXT effort collapses to 0 for most names. An independent per-stock deep dive — Bull/Bear/Judge with the full headline set and its own bin/stock-cli access — raises context rigor exactly where the one-shot prompt is thinnest.

What

scheduler/deep_dive.py runs a single-ticker dive prompt under a strict-JSON contract (ticker / context_score(-5..+3) / conviction / risks / catalysts / summary, with prediction logging explicitly forbidden), with bounded fan-out (a ThreadPoolExecutor at parallelism 2, 420 seconds per dive, capped at 6), hardened parsing (last ```json block, required ticker match, score clamp, conviction whitelist, list sanitization), and per-ticker fail-open. daily_briefing.py gains --deep-dive (default off) and --deep-dive-cap; results are injected into the briefing prompt with the instruction to adopt each dive's context_score as that stock's LLM_CONTEXT pillar and store the dive verbatim in components.deep_dive. API mode ignores the flag. Dives never log predictions themselves — the single logging path keeps rules R1/R2/R3 and the store gates authoritative.

How

TDD: 11 module tests and 2 wiring tests were written first. The subprocess wrapper mirrors call_claude_code but is self-contained in deep_dive.py to avoid a circular import. Worst-case wall clock at defaults is about 6 dives times up to 7 minutes over 2 workers, roughly 21 minutes per market — hence default-off until a week of manual runs looks sane.

Code locations

  • scheduler/deep_dive.py — full module
  • scheduler/daily_briefing.py — _deep_dive_block, build_claude_code_prompt params, run_briefing + argparse plumbing
  • scheduler/tests/test_deep_dive.py, scheduler/tests/test_daily_briefing.py

  • --help smoke shows both flags

Review loop

  • Antigravity (Gemini 3.1 Pro High): 1 HIGH — headlines were interpolated raw into the dive prompt, an injection surface; fixed with <headlines> fencing plus an untrusted-data instruction and a regression test. 1 MEDIUM — bare JSON with conversational preamble failed the fallback parser; fixed with an outermost-brace span. 3 LOW — a null summary rendered as the string "None" (fixed), plus ARG_MAX and orphaned-child concerns documented as comments, matching the existing call_claude_code pattern.
  • code-reviewer subagent: verified all fixes; 1 warning (multi-block parsing untested — 3 tests added) plus 2 suggestions (a brace-in-string test added, a debug log at parse-accept added). "Merge."

Retrospective

The dive's own data access is what makes it valuable: the live NVDA run pulled sector-RS, volume, and the earnings calendar unprompted. Keep it default-off until a week of manual runs establishes the cost/quality trade.

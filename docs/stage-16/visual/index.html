Watchlist Monitor — price-level alert system that fires Korean Telegram nudges when a tracked ticker's latest close touches a watched entry, stop, target, or re-entry level.

Watchlist Monitor

Why

Predictions and positions already existed, but there was no mechanism to notify when a ticker actually reached a level of interest — an entry zone, a stop, a target, or a re-entry trigger. The outcome tracker resolves predictions nightly but is silent about "price is at your level now". This stage adds an EOD-ish trigger alerter so Doctor Cho receives a Korean Telegram nudge when the latest close touches a watched level, without introducing any new schema in predictions.db.

What

  • A saved-ticker watchlist in a sibling DB data/watchlist.db (CRUD), plus a unified-watchlist builder that merges saved rows + OPEN predictions + portfolio positions, deduped by (ticker, market) with precedence saved > prediction > position.
  • A pure-Python monitor that fetches the latest price per ticker (never-raise), evaluates ENTRY / STOP / TARGET / RE-ENTRY triggers (BULL default, BEAR mirrored), and fires Korean Telegram alerts on rising-edge transitions with a 6h cooldown backstop and re-arm semantics. Market-hours gated, alert-only (never mutates predictions).
  • CLI subcommands watch add/remove/list/check, send_watch_alert, an EOD-cadence crontab entry, the SKILL.md, and .gitignore entries.

How

  • Delayed reframing made explicit. get_current_price() returns the last close; KR PyKRX is EOD. Documented in SKILL.md, module docstrings, the crontab comment, and the alert body.
  • Mirrored existing patterns. Connection pattern (WAL + busy_timeout + CREATE TABLE IF NOT EXISTS) copied from portfolio/db.py. Never-raise loop, timezone-aware gate, and Telegram alerting mirror outcome_tracker.py.
  • Rising-edge dedup. state/watchlist_alerts.json keyed {source}:{ticker}:{market}:{trigger} stores {last_state, last_alert_iso}. Fire only on a transition into the satisfied state; re-arm on transition out; 6h cooldown as a flip-flop guard. Atomic write via temp + os.replace; stale keys pruned each run.
  • Single-point entry band. Predictions/positions carry one entry price, so ENTRY uses a ±1% band; saved rows use the explicit [entry_low, entry_high].
  • Delivery. One focused Korean message per trigger; a single batched digest when more than 3 fire.
  • TDD. Store tests then monitor tests written before/with implementation; 36 new tests, all green.

Retrospective

The single-pass collect-then-deliver design removed an ugly mid-loop digest decision. The scheduler package is not installed — the CLI needed PROJECT_ROOT on sys.path. Carry forward: the US market-hours gate is now DST-aware (America/New_York) after the review loop.

Review loop

Four P1 correctness defects found in a second-pass review, all fixed under TDD. Reviewers: code-reviewer-pro (Claude) and Codex (gpt-5.5, high effort). EOD/delayed framing, never-mutate-predictions, and never-raise conventions preserved throughout.

  • State persisted before send (Codex P1). last_alert_iso was committed before the alert was sent, so a send failure silently consumed the rising edge. Fix: deliver first; _deliver returns the delivered _state_keys; run_monitor rolls back each unfired key to its prior snapshot so the next run retries. Dry-run still commits edges; digest is all-or-nothing.
  • Shared temp state path (Codex P1). save_state now uses tempfile.mkstemp (unique same-dir temp) + os.replace, with temp cleanup on failure.
  • OPEN-prediction dedup ordering (Codex P1). Added ORDER BY created_at DESC, rowid DESC so the newest prediction's levels win the dedup (predictions.id is a UUID, so rowid is the insertion-order tiebreaker).
  • US market-hours DST gate (Codex P1). is_market_open now computes the US session in America/New_York (DST-aware), RTH 09:30–16:00 ET inclusive plus a 30-min post-close grace compared as full datetimes; US cron window widened to cover the EST close.
  • Stable state keys (code-reviewer-pro). id()-based matching replaced with stable _state_key strings.
  • Digest import/build in never-raise try (code-reviewer-pro). Import and construction of the digest moved inside the never-raise try block.
  • Full-datetime grace boundary (code-reviewer-pro). Grace period boundary now compared as full datetimes rather than time-only values.
  • Pushed back — Telegram failures not in errors (Codex MEDIUM). errors is a price-fetch-failure counter by existing contract; the edge-rollback mechanism (retry next run) is the correct remedy and failures are logged. Out of scope deliberately.
Verification: 44 passed (36 baseline + 8 new) for the two watchlist suites; 130 passed for the full scheduler suite (no-network).

Watchlist Monitor — 관심 종목의 최신 종가가 설정한 진입·손절·목표·재진입 수준에 도달했을 때 한국어 Telegram 알림을 발송하는 가격 레벨 알림 시스템.

Watchlist Monitor

왜

예측과 포지션은 이미 존재했지만, 종목이 관심 레벨 — 진입 구간, 손절선, 목표가, 재진입 트리거 — 에 실제로 도달했을 때 알려주는 수단이 없었다. 결과 추적기는 매일 밤 예측을 정산하지만 "지금 가격이 레벨에 있다"는 사실은 침묵한다. 이 단계에서는 최신 종가가 관심 레벨에 닿을 때 Doctor Cho에게 한국어 Telegram 알림을 보내는 EOD 트리거 알림 시스템을 추가한다. predictions.db에는 새 스키마를 일절 추가하지 않는다.

무엇을

  • 별도 DB data/watchlist.db에 저장되는 종목 관심 목록(CRUD)과, 저장 행 + OPEN 예측 + 포트폴리오 포지션을 (ticker, market) 기준으로 통합·중복 제거하는 unified-watchlist 빌더 — 우선순위: saved > prediction > position.
  • 순수 Python 모니터: 종목별 최신 가격을 never-raise 방식으로 조회하고, ENTRY / STOP / TARGET / RE-ENTRY 트리거를 평가(BULL 기본, BEAR 반전)하며, 상승 엣지 전환 시 6h 쿨다운 및 재활성화 시맨틱을 적용해 한국어 Telegram 알림을 발송. 마켓 시간 게이팅 적용, 알림 전용(예측 절대 수정 없음).
  • CLI 서브커맨드 watch add/remove/list/check, send_watch_alert, EOD 케이던스 crontab 항목, SKILL.md, .gitignore 항목 추가.

어떻게

  • 지연 데이터 재정의를 명시적으로 문서화. get_current_price()는 마지막 종가를 반환하며, KR PyKRX는 EOD 전용. SKILL.md, 모듈 docstring, crontab 주석, 알림 본문 모두에 명시.
  • 기존 패턴 그대로 적용. 커넥션 패턴(WAL + busy_timeout + CREATE TABLE IF NOT EXISTS)은 portfolio/db.py에서 복사. Never-raise 루프, 타임존 인식 게이팅, Telegram 알림 방식은 outcome_tracker.py를 그대로 따름.
  • 상승 엣지 중복 제거. state/watchlist_alerts.json을 {source}:{ticker}:{market}:{trigger} 키로 관리하고 {last_state, last_alert_iso}를 저장. 만족 상태로 전환 시에만 발송; 상태 이탈 시 재활성화; 6h 쿨다운을 플립플롭 가드로 사용. tempfile.mkstemp + os.replace로 원자적 쓰기; 매 실행마다 stale 키 정리.
  • 단일 진입 구간. 예측·포지션은 진입가가 하나이므로 ENTRY에 ±1% 밴드를 사용하고, 저장 행은 명시적 [entry_low, entry_high]를 사용.
  • 전송. 트리거당 한국어 메시지 1건; 3건 초과 시 단일 일괄 다이제스트 발송.
  • TDD. 스토어 테스트와 모니터 테스트를 구현 전/중에 작성; 신규 테스트 36개, 모두 통과.

리뷰 루프

두 번째 패스 리뷰에서 P1 정확성 결함 4건이 발견되어 TDD 방식으로 모두 수정. 리뷰어: code-reviewer-pro (Claude), Codex (gpt-5.5, high effort). EOD/지연 데이터 프레임, never-mutate-predictions, never-raise 규약은 전 과정에서 유지.

  • 전송 전 상태 영속화 (Codex P1). last_alert_iso가 알림 발송 전에 커밋되어 발송 실패 시 상승 엣지가 소실되었다. 수정: 먼저 전송하고 이후 영속화; _deliver가 전달된 _state_key 목록을 반환하며, run_monitor는 미전달 키를 이전 스냅샷으로 롤백해 다음 실행에서 재시도. dry-run은 여전히 엣지를 커밋하며, 다이제스트는 전부-또는-전무 처리.
  • 공유 임시 상태 경로 (Codex P1). save_state가 tempfile.mkstemp(동일 디렉터리 내 고유 임시 파일) + os.replace를 사용하며, 실패 시 임시 파일을 정리하도록 수정.
  • OPEN 예측 중복 제거 정렬 (Codex P1). ORDER BY created_at DESC, rowid DESC를 추가하여 가장 최신 예측의 레벨이 중복 제거에서 우선하도록 수정 (predictions.id는 UUID이므로 rowid가 삽입 순서 기준).
  • US 마켓 시간 DST 게이팅 (Codex P1). is_market_open이 America/New_York 기준으로 US 세션을 계산(DST 인식), RTH 09:30–16:00 ET 포함 + 30분 장후 유예를 전체 datetime으로 비교; US cron 윈도우를 EST 마감 커버에 맞게 확장.
  • 안정적 상태 키 (code-reviewer-pro). id() 기반 매칭을 안정적인 _state_key 문자열로 교체.
  • 다이제스트 임포트/빌드를 never-raise try 내부로 이동 (code-reviewer-pro). 다이제스트의 임포트 및 생성을 never-raise try 블록 안으로 이동.
  • 전체 datetime 유예 경계 비교 (code-reviewer-pro). 유예 기간 경계를 시간 값만으로 비교하던 방식을 전체 datetime 비교로 수정.
  • 반려 — Telegram 실패를 errors에 미집계 (Codex MEDIUM). errors는 기존 계약상 가격 조회 실패 카운터이며, 엣지 롤백(다음 실행에서 재시도)이 올바른 대응책이고 실패는 로그에 기록된다. 의도적으로 범위 밖으로 제외.

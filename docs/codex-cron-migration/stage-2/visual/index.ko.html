2단계

실제 할인 Cron 작업은 구조화되고 격리된 수집 계약을 유지하면서 이제 네이티브 Codex 수집기를 사용합니다.

Discount Collector

왜

실제 할인 Cron 작업은 여전히 Claude CLI 수집기를 기본값으로 사용했으므로, 주식 스케줄러만 변경하면 설치된 Claude 실행 경로 하나가 활성 상태로 남게 됩니다.

무엇을

  • ClaudeCollector와 claude 레지스트리 키를 CodexCollector와 codex로 교체했습니다.
  • codex를 기본 DEALS_COLLECTORS 값으로 지정하고 생성되는 README 템플릿을 업데이트했습니다.
  • 명시적 비대화형 승인, 읽기 전용 sandbox, 임시 세션, 닫힌 stdin, 기존 제공자의 제한 시간 및 동시성 범위를 적용해 네이티브 Codex 실시간 웹 검색을 활성화했습니다.
  • 제공자당 1회 호출 범위, 공식 event page 기준점, 제공자별 실패 격리 및 grounding document 출력을 유지했습니다.
  • Claude 전용 JSON envelope 구문 분석과 WebFetch 프롬프트 문구를 제거했습니다.
  • 정확한 Codex 명령, 모델 재정의, 레지스트리/설정 기본값, 실패, 동시성 동작 및 Claude 소스 경로 부재에 대한 회귀 테스트를 추가했습니다.

어떻게

Codex 수집기가 존재하지 않아 테스트가 먼저 실패했습니다. 구현에서는 기존 수집기 구조를 유지하고 CLI 경계와 Claude 전용 출력 처리만 변경했습니다. 공유 micromamba 환경의 editable install이 원본 checkout을 가리키므로 worktree 테스트에서는 PYTHONPATH=src를 명시적으로 사용했습니다. 검증에서는 테스트 260개가 통과하고 기존 실시간 테스트 1개가 건너뛰어졌으며, 컴파일/정적 검사와 실제 읽기 전용 Codex 웹 검색 스모크 테스트를 완료했습니다. 이 스모크 테스트는 프로젝트 상태를 작성하지 않고 51개 할인 정보를 포함한 구문 분석 가능한 문서 하나를 반환했습니다.

회고

실제 스모크 테스트에서 네이티브 Codex 검색이 구조화된 수집기 계약을 유지함을 확인했습니다. Antigravity가 지적한 유효한 설정 흐름 문제를 수정했습니다. 승인, TOML, 프롬프트, legacy-env 및 PATH 관련 지적은 CLI 스모크/도움말과 실제 배포 증거를 근거로 기각했습니다. 최종 재검토에서는 지적 사항이 없었습니다. Doctor Cho는 이 마이그레이션의 Claude 검토를 면제했습니다.

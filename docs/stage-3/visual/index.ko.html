Tier2 Oos Staged Debate

왜

Stage 1에서 연기한 Tier 2 구현. 측정 결함의 다음 층위를 공략했습니다: 정적 전체-기간 승률은 최근 쇠퇴를 숨김 → OOS 분할 필요(S5); 단일패스 프롬프트 + 한쪽 관점 편향 → 단계형 + 적대적 디베이트(S4/S6). 출처: Vibe-Trading(MIT) strict 팩터 게이트 (train/test 분할), AutoHedge(Director→Quant→Risk), FinceptTerminal(Bull/Bear/Judge — 아이디어만).

무엇을
  • S5 (코드): get_signal_decay — closed 예측을 outcome_date로 train/test 분할, 각 구간을 50% 귀무가설로 채점 후 confirmed_alive / train_only / reversed / insufficient_oos / noise 라벨. 실데이터에서 news가 train_only(쇠퇴)로 식별. CLI calibration에 signal_decay, weekly_calibration에 decaying_signals 노출.
  • S4 (프롬프트): /expect Step 5b에 단계 역할 명시 — Quant(결정론적 ALGO/NEWS) → Director/Judge(LLM_CONTEXT 디베이트) → Risk(Step 9 C2/C3 게이트).
  • S6 (프롬프트): LLM_CONTEXT_SCORE를 Director thesis(선커밋) → Bull → Bear → Judge 산출물로 재정의. 새 override 채널 없음, −5..+3 범위·composite 불변. stock-research에도 경량 Bull/Bear/Judge 단계(3b) 추가.
어떻게

SignalDecay 데이터클래스 + get_signal_decay(min_count, oos_fraction=0.3) + _decay_label. S1의 _signal_verdict 재사용. 인덱스 기반 시간순 분할(i >= split_idx) — 동일 날짜 군집 시 train이 비는 경계 문제를 방지. find_decaying_signals(weekly_calibration)가 train_only·reversed만 surface. S4/S6은 결정론적 점수 표를 건드리지 않고 narrative 채널(Step 5b)의 추론 품질만 강화. TDD: S5 신규 테스트 6개, 전체 not-network 303 통과.

Kr Universe Fallback

왜

Stage A(PR #12)에서 동적 candidate discovery를 도입했지만, 2026-05-13 production cron 실행 결과 PyKRX의 bulk-by-ticker 엔드포인트가 KRX upstream 응답 포맷 변경으로 모두 장애 상태임을 확인했습니다. get_market_cap_by_ticker, get_market_fundamental_by_ticker, get_market_ohlcv_by_ticker, get_market_ticker_list 모두 동일 KeyError (PyKRX 1.2.4·1.2.8 공통). Universe 열거가 불가능해 anchors-only fallback이 발동, 5/13 catalyst 종목(307950 +55%, 066570 +34%, 005380 +30%)이 프롬프트에 올라오지 못했습니다. 추가로 PR #12 머지 후 Copilot 자동 리뷰·codex @codex review에서 즉시 적용 가능한 surgical fix 7건이 도착했습니다.

무엇을
  • 신규 파일 data/kr_universe.csv — 166개 curated ticker (KOSPI 110 + KOSDAQ 36 + ETF 20). 5/13 catalyst 5종목 전원 포함.
  • scheduler/candidate_discovery.py: _load_static_universe()(CSV → ticker 리스트), _load_static_universe_names()(ticker → name 매핑, _fill_names의 first-tier fallback), enumerate_kr_universe() 재작성(PyKRX 시도 → 실패 시 CSV fallback → 둘 다 실패 시 [] 반환으로 anchors-only 안전망 유지).
  • Codex/Copilot 리뷰 fix 7건 적용: subsequence 기반 테마 dedup (C1), PyKRX import를 try 블록 내부로 이동(C2), 헤드라인별 n-gram dedup(C3), confidence floor 0.60으로 상향 (C4), dead 변수 제거, docstring 수정, fixture 명세 보강.
  • 회귀 테스트 4건 신규 추가: CSV fallback, 양쪽 실패 시 안전망, 별개 테마 동시 생존, 반복 n-gram 카운트 정확성.
어떻게

CSV 컬럼 3개(ticker, name, market_segment). market_segment는 Stage 3 코드에서 미사용이지만 향후 KOSPI/KOSDAQ/ETF 필터를 CSV 재발행 없이 활용 가능하도록 의도적 보존(YAGNI vs 확장성 trade-off). CSV 모드에서 cap/value는 None — stale 값보다 정직. 순위는 score_and_filter(get_price_history_batch + |return_5d|/vol_ratio 임계값)가 담당하므로 CSV ticker 순서 무관. stale ticker(상장폐지·합병 등)는 score 필터가 자동 skip하고 INFO 레벨로 로그 — 운영자가 cron 로그에서 바로 식별 가능. 테스트는 monkeypatch.setattr으로 STATIC_UNIVERSE_PATH를 교체해 양쪽 실패 시나리오를 정확히 검증.

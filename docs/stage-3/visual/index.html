Tier2 Oos Staged Debate

Why

Tier 2 work deferred from Stage 1. Three measurement weaknesses remained: a static all-period win rate hides recent decay (OOS split needed — S5); a single-pass prompt with one-sided bias (staged roles + adversarial debate — S4/S6). Inspired by Vibe-Trading (MIT) strict factor gates (train/test split), AutoHedge (Director→Quant→Risk), and FinceptTerminal (Bull/Bear/Judge — concept only).

What
  • S5 (code): get_signal_decay — splits closed predictions by outcome_date into train/test, scores each half against the 50% null hypothesis, then labels each signal as confirmed_alive, train_only, reversed, insufficient_oos, or noise. On real data, the news signal was identified as train_only (decaying). signal_decay surfaced in CLI calibration; decaying_signals surfaced in weekly_calibration.
  • S4 (prompt): /expect Step 5b assigns explicit roles — Quant (deterministic ALGO/NEWS) → Director/Judge (LLM_CONTEXT debate) → Risk (Step 9 C2/C3 gates).
  • S6 (prompt): LLM_CONTEXT_SCORE redefined as Director thesis (pre-commit) → Bull → Bear → Judge output. No new override channel; the −5..+3 range and composite formula are unchanged. Lightweight Bull/Bear/Judge step (3b) also added to stock-research.
How

SignalDecay dataclass + get_signal_decay(min_count, oos_fraction=0.3) + _decay_label. Reuses _signal_verdict from S1. Index-based chronological split (i >= split_idx) avoids empty-train edge cases caused by same-date clusters. find_decaying_signals in weekly_calibration surfaces only train_only and reversed labels. S4/S6 touch only the narrative channel (Step 5b), leaving the deterministic score table intact. TDD: 6 new S5 tests; full not-network suite at 303 passing.

Kr Universe Fallback

Why

Stage A (PR #12) introduced dynamic candidate discovery, but a 2026-05-13 production cron run revealed that PyKRX's bulk-by-ticker endpoints had all broken due to a KRX upstream response format change. get_market_cap_by_ticker, get_market_fundamental_by_ticker, get_market_ohlcv_by_ticker, and get_market_ticker_list all failed with the same KeyError on PyKRX 1.2.4 and 1.2.8. Universe enumeration was impossible, causing the anchors-only fallback to activate and missing the 5/13 catalyst stocks (307950 +55%, 066570 +34%, 005380 +30%). Additionally, 7 surgical fixes from Copilot and Codex reviews of PR #12 were ready to apply.

What
  • New file data/kr_universe.csv — 166 curated tickers (110 KOSPI + 36 KOSDAQ + 20 ETF), including all five 5/13 catalyst tickers.
  • scheduler/candidate_discovery.py: _load_static_universe() reads CSV to a ticker list; _load_static_universe_names() provides a ticker-to-name map as first-tier fallback in _fill_names; enumerate_kr_universe() rewritten to try PyKRX first, then fall back to CSV, then return [] (anchors-only safety net).
  • 7 Codex/Copilot review fixes applied: subsequence-based theme dedup (C1), PyKRX import moved inside try block (C2), per-headline n-gram dedup (C3), confidence floor raised to 0.60 (C4), dead variable removal, docstring corrections, and fixture clarification.
  • 4 new regression tests covering CSV fallback, both-fail safety net, distinct-theme survival, and repeated n-gram counting.
How

CSV has three columns (ticker, name, market_segment); market_segment is unused in Stage 3 but kept intentionally for future KOSPI/KOSDAQ/ETF filtering without reissuing the file. cap/value fields are None in CSV mode — honest rather than stale. Ranking relies on score_and_filter (get_price_history_batch + |return_5d| / vol_ratio thresholds), so CSV ticker order is irrelevant. Stale CSV entries are automatically skipped by the score filter and logged at INFO level for operator visibility. Tests use monkeypatch.setattr on STATIC_UNIVERSE_PATH to cover the both-fail scenario precisely.

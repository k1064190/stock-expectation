승률이 73%에서 51%로 악화된 후, 이식 가능한 개선 패턴을 발굴하기 위해 외부 오픈소스 트레이딩 레포 3종을 벤치마킹했습니다.

External Repo Benchmark

왜

예측 품질이 한 달 반 만에 승률 73%→51%로 악화됐습니다. 외부 오픈소스 트레이딩 시스템 3종을 clone·심층 분석해 이식 가능한 개선 패턴을 찾기 위해 수행했습니다.

무엇을
  • research/external/(gitignore)에 3개 레포 clone: Vibe-Trading(HKUDS), AutoHedge(Swarm Corp), FinceptTerminal(Fincept).
  • 서브에이전트 3개 병렬 분석 → reports/external-analysis/{vibe-trading,autohedge,finceptterminal}.md 레포별 보고서 작성.
  • 통합 합성 reports/external-analysis/SYNTHESIS.md — 측정된 결함과 매핑한 개선안 S1~S13 정리.
  • 리뷰 게이트 결과: Tier 1(S1+S2+S3)만 1단계에서 구현, 나머지는 이후 단계로 연기.
어떻게

라이선스 먼저 확인: Vibe-Trading = MIT (코드 차용 가능), AutoHedge = MIT (아이디어 위주), FinceptTerminal = AGPL/상용 (아이디어만, 코드 복사 금지). 적용성 기준은 Python CLI + Claude 스킬 + SQLite 트랙레코드 스택에 실제로 들어맞는 것으로 한정. 웹 UI·선물/크립토 엔진·C++/Qt·ML 플랫폼은 제외했습니다.

코드 위치

research/external/* (gitignored)   reports/external-analysis/*.md   .gitignore (research/external 추가)

회고

WebFetch 정찰 → clone → 병렬 서브에이전트 보고서 → 합성 흐름이 효율적이었습니다. 측정된 결함(BEAR 6%, 0% 신호, confidence 상수)이 후보 우선순위를 명확히 정렬해줬습니다. 연기 항목은 SYNTHESIS.md에 보존되어 다음 단계 재진입이 쉽습니다.

Stage 1

Five parallel workstreams: trustworthy calibration reporting, dynamic KR candidate discovery, external reference skill analysis, tier-1 signal gating with isotonic recalibration, and Toss official Open API portfolio sync.

Calibration Report Trustworthiness

Why

The weekly calibration report drove operator decisions but had two structural flaws that made its advice misleading. First, calibration buckets and signal-performance tables were always computed over the full prediction history regardless of the selected time window, so the "7-day window" section still showed all-time data (e.g. technical n=445), hiding that recent post-momentum-overhaul signals had recovered (7-day technical ~52% vs. all-history ~38%). Second, buckets were always computed on raw confidence, so the report could not show whether the live isotonic recalibrator was closing the overconfidence gap — and its headline "trim confidence" recommendation would have double-corrected the recalibrator, which already maps raw 0.61 to approximately 0.31 on recalibrated rows.

What
  • get_calibration_report and get_signal_performance gained an optional days window filter on outcome_date, matching the existing get_track_record semantics.
  • get_calibration_report gained use_raw (default True preserves the recalibration-training path; False uses as-logged/post-recalibration confidence).
  • The report now renders two calibration tables per window (raw vs. as-logged) when they diverge, collapsing to one table plus an explanatory note while they still coincide.
  • The headline overconfidence warning is now based on the as-logged curve; raw flags retained in overconfident_buckets_raw for trend-file plotting.
  • Live result: 7-day window shows raw drift +0.09 vs. as-logged +0.02 — the recalibrator is visibly closing the gap on recent data.
How

Test-first (TDD): 7 new failing tests (4 in test_metrics.py, 3 in test_weekly_calibration.py) drove minimal additions. The windowing reuses the exact outcome_date >= datetime('now', ?) predicate already used by get_track_record, so all windowed sections align with the headline number. A _render_bucket_table helper was extracted to remove duplication that two-table rendering would have introduced. A Codex review identified that ISO string lexicographic comparison wrongly included same-cutoff-date rows with an earlier time; fixed by wrapping with datetime(outcome_date) in all new queries and the shared _closed_filter helper.

Code locations
  • mcp-prediction-store/metrics.py — get_calibration_report (≈467–540), get_signal_performance (≈540–585)
  • scheduler/weekly_calibration.py — compute_window, _render_bucket_table, two-table render, headline warning wording, overconfident_buckets_raw
  • mcp-prediction-store/tests/test_metrics.py
  • scheduler/tests/test_weekly_calibration.py
Retrospective
Verifying the report's premise before acting paid off: the data showed the "trim confidence" advice would have double-corrected an existing recalibrator. Carry forward: treat advisory reports as hypotheses and confirm against the DB before acting on them. The dual-table view is exactly how to confirm the recalibrator is converging as the 722 open LIVE predictions close — no further code changes needed.

Candidate Discovery

Why

The 2026-05-13 cron daily briefing completely missed the "Physical AI" theme surge (Hyundai AutoEver +55%, LG Electronics +34%, Hyundai Motor +30% over 10 days), re-recommending only Samsung / SK Hynix / Hyundai Motor. Root cause: scheduler/daily_briefing.py hard-coded 6 KR blue-chips, placing mid-cap momentum stocks entirely outside the LLM's view. A secondary cause (the briefing skill's framing anchoring the LLM to those names) is addressed in Stage 2. Stage 1 removes the hard-coded universe.

What
  • New module scheduler/candidate_discovery.py (340 lines): Candidate dataclass, ANCHORS_KR (3 reference anchors), enumerate_kr_universe (market-cap top-N ∪ trading-value top-N via single PyKRX call), score_and_filter (|return_5d| ≥ 15% OR vol_ratio_5d ≥ 2×), discover_kr_candidates, format_candidates_for_prompt.
  • Hard-coded 6 tickers reduced to 3 reference anchors: Samsung Electronics (005930), SK Hynix (000660), KODEX 200 (069500).
  • scheduler/daily_briefing.py: fetch_kr_market_data() rewritten for API mode; KR Claude Code cron prompt rewritten to inject {candidate_block} and {ticker_csv}.
  • .claude/skills/daily-briefing/SKILL.md static ticker list replaced with guidance that tickers are dynamically determined with 3 reference anchors.
  • 21 new unit tests (all mocked): enumerate ×4, score_filter ×7, discover ×5, format ×2, defaults ×1.
How
  • Universe = market-cap top-N ∪ trading-value top-N. Market-cap only misses mid-cap surges (Hyundai AutoEver may be outside top-200 by cap); trading-value only brings too much mega-cap noise. The union captures both.
  • Anchors trimmed to 3; the other 3 legacy tickers must pass the dynamic filter to appear, ensuring only today's meaningful names are shown.
  • News count deferred to Stage 2: fetching news for 200 candidates risks timeout. The theme clusterer will backfill news counts for top-30 candidates only.
  • PyKRX failure falls back gracefully to anchors-only; cron never crashes.
  • Name lookups applied only to filter survivors (~20–30 tickers) not the full ~250 universe, reducing PyKRX sequential calls.
  • Provider injectable via discover_kr_candidates(provider=...) for unit-test isolation.
Code locations
  • scheduler/candidate_discovery.py — new, 340 lines
  • scheduler/tests/test_candidate_discovery.py — new, 21 tests
  • scheduler/daily_briefing.py:44-56 — import additions
  • scheduler/daily_briefing.py:107-149 — fetch_kr_market_data() rewrite
  • scheduler/daily_briefing.py:386-410 — KR Claude Code prompt rewrite
  • .claude/skills/daily-briefing/SKILL.md:46-56 — KR ticker guidance replacement
Retrospective
21 unit tests anchored to the 2026-05-13 missed-scenario fixture give strong regression protection. The score_and_filter fixture is intuitive and easy to reuse when threshold tuning is needed. Watch for PyKRX bulk endpoint KeyErrors in cron — the anchors-only fallback is safe but silently disables dynamic discovery; a static fallback universe CSV is worth considering in a later stage.

Tier1 Signal Gate Recal

Why

Three measured defects targeted directly: (S1) valuation/cycle/mean_reversion signal types showing 0% win rate with no pruning mechanism; (S2) 39% of LIVE predictions low-quality and BEAR direction issued at 6% without sufficient gate; (S3) confidence values stuck near 0.60 as a near-constant, carrying no information. Design informed by the Vibe-Trading (MIT) signal IC/classification and recalibration philosophy and the AutoHedge risk-first gate concept.

What
  • S1: Added binomial two-sided p-value and verdict (alive / weak / dead) per signal type to get_signal_performance. On live data, valuation/cycle/mean_reversion correctly identified as dead (p=0.001); the rest are weak.
  • S2: Added risk/edge gate (reward:risk < 1.5 blocks registration) and raised the BEAR bar (≥3 signals + macro confirmation + RR ≥ 2.0; LIVE demoted to NEUTRAL) in /expect and daily-briefing prompts.
  • S3: Fitted a monotone recalibration map (isotonic regression / PAVA) and applied it. Live data: raw 0.626 corrected to 0.50. Recalibration map exposed via CLI calibration subcommand output.
How
  • _binomial_two_sided_p uses math.comb with no external dependencies; later rewritten in log-gamma space to handle n ≳ 1100 without overflow (caught by Codex PR review #27).
  • _signal_verdict added to get_signal_performance as backward-compatible new fields — 4 existing consumers required no changes.
  • _isotonic_nondecreasing (PAVA) → build_recalibration_map / apply_recalibration (linear interpolation; empty map is identity function).
  • TDD: 9 new tests (verdict ×3, recalibration ×3, weekly ×1, existing augmentation ×2). Full not network suite: 287 passing.
Code locations

  • mcp-prediction-store/tests/test_metrics.py — S1/S3 tests

  • scheduler/tests/test_weekly_calibration.py — verdict tests + _FakeSignal fields

Retrospective
S1 extended cleanly via additive fields with zero changes to 4 existing consumers. Implementing exact binomial without scipy kept core dependencies minimal. S2 is prompt-only and cannot be automatically tested; the Stage 2 store-layer BEAR hard gate is the real enforcement line — S2 and the gate are complementary.

Toss Open Api

Why

portfolio sync depended on the unofficial tossctl CLI, which required browser/QR login, had roughly weekly session expiry, and needed a separate session-expiry monitor with Telegram alerts. Toss Securities now offers an official Open API (OAuth2, REST/JSON), enabling server-side credentials with automatic token refresh and eliminating browser session management entirely.

What
  • New portfolio/toss_api.py: OAuth2 client-credentials client — issues/caches a token, lists accounts, reads holdings, normalizes each holding into the dict shape reconcile() already consumes.
  • portfolio sync prefers the official API and falls back to tossctl when credentials are absent. New --source {auto,toss-api,tossctl} flag; output JSON reports the source actually used.
  • Removed now-unnecessary session-expiry monitor: scheduler/toss_auth_check.py, its test, the 07:30 cron line, and all documentation references.
  • Credentials via .env: TOSS_CLIENT_ID, TOSS_CLIENT_SECRET (optional TOSS_OPENAPI_BASE_URL).
  • Live verified: token issued, BROKERAGE account, 18 holdings (6 KR + 12 US) synced correctly via portfolio sync --source toss-api --dry-run.
How

Reconciliation logic, DB schema, and ticker/market normalization are data-source agnostic and were left untouched. The new code sits only at the boundary: toss_api.fetch_toss_positions_api() produces the same normalized positions tossctl used to, so toss_sync.reconcile() is unchanged. A thin dispatcher toss_sync.fetch_positions(source) selects the source. Endpoints were confirmed against the canonical spec at https://openapi.tossinvest.com/openapi-docs/latest/openapi.json — initial guesses about auth method, path prefix, and the accountSeq header were all wrong and corrected before implementation.

Code locations
  • portfolio/toss_api.py — Open API client and adapter
  • portfolio/toss_sync.py — fetch_positions() dispatcher (reconcile unchanged)
  • stock_cli.py — cmd_portfolio_sync + --source flag
  • portfolio/tests/test_toss_api.py — client/adapter/dispatcher unit tests
  • Removed: scheduler/toss_auth_check.py, scheduler/tests/test_toss_auth_check.py
  • Docs: CLAUDE.md, .claude/skills/toss-sync/SKILL.md, scheduler/crontab.example, cron_setting.md, README.md
Retrospective
Boundary-only design kept the change surgical — reconcile, DB, and existing logic tests were untouched. Pulling the real openapi.json early rather than trusting research guesses was the key unblock: auth method, path prefix, and the accountSeq header were all different from the initial assumptions. The credential mix-up (ID/secret swapped) surfaced as a clean invalid_client error, isolating the issue quickly.

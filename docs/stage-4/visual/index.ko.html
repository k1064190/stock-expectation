4단계

/expect 스킬을 결정론적 점수 체계, 설명력 체인, 결과 텔레메트리로 전면 재작성하고, 부트스트랩 신뢰구간, 순열검정, JSON 스키마 검증으로 예측 저장소를 강화했습니다.

/Expect 스킬 재작성

왜

4단계 이전 /expect는 4개 호라이즌 방향 예측을 생성했지만, 결정론적 점수표(LLM이 정성적 "강세" 텍스트를 출력), 정량적 뉴스/감성 입력, 단일 헤드라인 레이블(매수/매도 결정), 전달 체인, 결과 텔레메트리가 모두 없었습니다. 조교수님의 요청: 알고리즘 분석과 뉴스 분석을 결합해 매수/매도 신호를 내보내되, 캘리브레이션 루프(다중 호라이즌 예측을 predictions.db에 기록)를 유지.

무엇을
  • 알고리즘 점수표 (ALGO_SCORE, 최대 +8.0, 하한 -5.0): 추세, 모멘텀, 1개월 수익률, 거래량, 사이클, 실적발표 이벤트 패널티.
  • 뉴스 점수표 (NEWS_SCORE, 최대 +3.0, 하한 -2.0): Alpha Vantage 감성, 헤드라인 수, 부정 키워드 스캔, KR 공시 플래그. 하드캡으로 누적 대신 클램프.
  • 복합 점수 + 결정 레이블: BUY ≥ 8.0 / WATCH 6.0..7.9 / HOLD 3.0..5.9 / AVOID 0..2.9 / SELL < 0. 반열린 연속 구간으로 모든 점수가 정확히 하나의 버킷에 귀속.
  • 전달 체인: 종목당 3개 사실 (TECH / NEWS / RISK), 각각 구체적 숫자 또는 필드명 인용 — 단순 형용사 금지.
  • 결과 텔레메트리 사이드카 (state/last-outcome-expect.json): 모든 컴포넌트 점수, 전달 체인, 기록된 호라이즌 목록. 6단계 주간 집계기가 파싱.
  • 품질 게이트(Step 11) + 편향 체크리스트(Step 12): 부호 일치, 목표가 간격, 데이터 신선도, 최신성/확증/앵커링/과신 점검.
  • 다중 호라이즌 예측 유지: 4호라이즌 (1W/1M/6M/1Y) predictions.db 기록, 공유 analysis_group_id. RULE C1 그대로 보존.
  • 출력 상세도 스케일링: /expect ALL은 종목당 3줄 요약, 단일/배치 모드 또는 RULE-C1/하드캡 종목에는 전체 블록 출력.
  • 스킬 합성 게이트: market-top-detector / ftd-detector / theme-detector는 COMPOSITE ≥ 8.0일 때만 호출, 재귀 가드 주석 추가.
어떻게

외부 스킬 컬렉션에서 세 가지 패턴 차용: 점수표 스코어링(staskh), 전달 체인(roman-rr), 결과 사이드카(ScientiaCapital). 수학 검증: gemini 리뷰에서 초안의 최대 점수 오기재를 포착 (알고 "최대 10"이나 컴포넌트 합산은 8; 뉴스 "최대 5"이나 합산은 3; 복합 최대 "15"이나 실제 11). 임계값을 실제 합산치에 맞게 수정하고 if/elif 방식으로 재작성해 모든 입력이 하나의 행에 귀속되도록.

회고

gemini 리뷰가 계획과 SKILL.md 초안 양쪽에 내재된 수학 오류를 잡아냈습니다. 이 과정 없이 넘어갔다면 "BUY composite 11.5/15" 같은 맞지 않는 출력을 조교수님이 직접 보셨을 것입니다. 앞으로 유지할 교훈: 스코어링 루브릭 설계 시, 임계값을 공표하기 전에 최대 양수 합산과 절대 하한을 별도 검증 줄로 명시적으로 작성할 것.

Tier 3 — 부트스트랩 CI / 순열검정 / JSON 스키마 검증

왜

Tier 1/2에 이어 세 가지 통계적·견고성 공백이 남아 있었습니다. 점추정 승률만으로는 "동전과 구분되는가"를 알 수 없음 → 부트스트랩 CI (S7). confidence가 실제 정보를 담는가는 이항검정으로 볼 수 없음 → 순열검정 (S8). LLM/JSON 예측을 요청만 하고 검증하지 않음 → 스키마 검증 (S9). 출처: Vibe-Trading (MIT) validation.py, AutoHedge (validate, don't just request JSON).

무엇을
  • S7 — get_track_record_ci: 승률·Brier 점수 부트스트랩 95% CI + prob_better_than_coin. 시드 고정으로 재현 가능. 실데이터: 승률 0.498, CI95 [0.44, 0.56] → 동전과 구분 불가.
  • S8 — permutation_test_confidence: 라벨 셔플 양측검정으로 confidence가 결과와 연관되는지 검증. 실데이터: p = 0.004 → confidence는 약하지만 유의미하게 정보 보유.
  • S9 — validate_prediction_dict: 필수 필드, enum 값, 범위, 유한 양수 검증. API 모드 log_predictions가 Prediction 생성 전에 호출해 malformed 행을 조용히 넘기지 않고 명확히 skip.
  • stock-cli calibration robustness 섹션 및 weekly_calibration robustness 키로 노출.
어떻게

공유 _closed_filter (WHERE 절)와 _percentile_ci (nearest-rank) 사용. 부트스트랩·순열 모두 random.Random(seed)로 결정론적 실행. 순열 통계 = mean(confidence | HIT) − mean(confidence | MISS), 양측 p값. validate_prediction_dict는 오류 문자열 리스트 반환. TDD: 신규 11개 테스트 추가, 전체 315개 통과.

회고

S7/S8가 실데이터에서 "전체 트랙레코드는 동전 수준이나 confidence는 약한 신호 보유"를 정량화했습니다. S9는 SQLite CHECK 제약에 의존하는 암묵적 검증을 명시적·메시지화된 검증으로 대체해 API 모드에서의 조용한 실패를 제거했습니다.

/Expect Skill Rewrite

Why

The pre-Stage-4 /expect produced four-horizon directional predictions but lacked: deterministic point-table scoring (LLM emitted qualitative "bullishness"), quantitative news/sentiment input, a single headline label (Buy/Sell decision), a transmission chain, and outcome telemetry. Doctor Cho's requirement: combine algorithmic and news analysis to emit a buy/sell signal while preserving the calibration loop.

What
  • Algorithmic point table (ALGO_SCORE, max +8.0, floor -5.0): trend, momentum, 1-month return, volume, cycle, earnings-event penalty.
  • News point table (NEWS_SCORE, max +3.0, floor -2.0): Alpha Vantage sentiment, headline volume, negative-keyword scan, KR disclosure flag. Hard caps clamp rather than stack.
  • Composite + decision label: BUY ≥ 8.0 / WATCH 6.0..7.9 / HOLD 3.0..5.9 / AVOID 0..2.9 / SELL < 0. Contiguous half-open ranges — every score lands in exactly one bucket.
  • Transmission chain: 3 facts per pick (TECH / NEWS / RISK), each quoting a specific number or named field — no bare adjectives.
  • Outcome telemetry sidecar at state/last-outcome-expect.json: every component score, transmission chain, and logged horizons. Parsed by Stage 6's weekly aggregator.
  • Quality gate (Step 11) + bias checklist (Step 12): sign agreement, target separation, fresh-data, recency/confirmation/anchoring/overconfidence checks.
  • Multi-horizon predictions preserved: 4-horizon (1W/1M/6M/1Y) logging to predictions.db with shared analysis_group_id. RULE C1 preserved.
  • Output verbosity scaling: /expect ALL emits 3-line per-stock summaries; full blocks for single/batch modes or RULE-C1/hard-cap picks.
  • Skill composition as gates: market-top-detector / ftd-detector / theme-detector called only when COMPOSITE ≥ 8.0, with recursion-guard note.
How

Borrowed three patterns from external skill collections: point-table scoring (staskh), transmission chain (roman-rr), outcome sidecar (ScientiaCapital). Math reconciliation: the gemini review caught that the initial draft misstated max scores (algo "max 10" but components summed to 8; news "max 5" but summed to 3; composite max stated as 15 but actually 11). Thresholds were fixed to match real component sums and rewritten in if/elif style so every input lands in exactly one row.

Tier 3 — Bootstrap CI / Permutation Test / JSON Schema Validation

Why

Following Tier 1 and 2, three statistical and robustness gaps remained. A point-estimate win rate cannot answer "is this distinguishable from a coin flip?" — addressed by bootstrap CI (S7). Whether confidence scores carry real information cannot be seen from a binomial test — addressed by permutation testing (S8). LLM/JSON predictions were requested but never validated — addressed by schema validation (S9). Draws from Vibe-Trading (MIT) validation.py and AutoHedge (validate, don't just request JSON).

What
  • S7 — get_track_record_ci: win-rate and Brier-score bootstrap 95% CI with prob_better_than_coin. Fixed seed for reproducibility. Live result: win rate 0.498, CI95 [0.44, 0.56] — indistinguishable from a coin flip.
  • S8 — permutation_test_confidence: label-shuffle two-sided test for whether confidence scores correlate with outcomes. Live result: p = 0.004 — confidence weakly but significantly carries information.
  • S9 — validate_prediction_dict: required fields, enum values, range checks, and finite-positive guards. API-mode log_predictions calls this before constructing a Prediction, making malformed rows fail explicitly rather than silently.
  • Exposed via stock-cli calibration robustness section and weekly_calibration robustness key.
How

Shared _closed_filter (WHERE clause) and _percentile_ci (nearest-rank). Bootstrap and permutation both use random.Random(seed) for determinism. Permutation statistic: mean(confidence | HIT) − mean(confidence | MISS), two-sided p-value. validate_prediction_dict returns a list of error strings. TDD: 11 new tests added, 315 total passing.

Retrospective

S7 and S8 quantified what the full track record shows in live data: aggregate win rate is coin-level, but confidence is a weak informative signal. S9 replaced an implicit reliance on SQLite CHECK constraints with explicit, message-bearing validation that eliminates silent failures in API mode.
